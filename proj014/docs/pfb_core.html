pfb_core：粗い PFB の 1 ch を取り出す

ADC の実数サンプル（4096 MSPS、1 クロックに 16 個）から、ch 間隔 128 MHz・4 倍オーバーサンプリングの粗い PFB のうち 1 本の ch k だけを、複素 512 MSPS で取り出す。1 クロック（256 MHz）に 2 フレームを出す。後ろの ddc_core が、この ch の中から窓を切り出す。

仕様の式と、実装での分け方

仕様は model/win_model.py の式そのもの。実装は、この式を「分岐の和」「32 点の実 DFT の 1 ch」「m で回る位相」の 3 つに分けて計算する。 どの段も model/win_fixed.py の pfb_fixed と bit 単位で同じ。

y_k[m] = Σn=0..95 h[n] · x[p − n] · exp(−j2πk(p − n)/32) p = 8m + 95（ホップ 8 サンプル） ① 分岐の和（n = r + 32t） u_r[m] = Σt=0..2 h[r + 32t] · x[p − r − 32t] r = 0..31 ② 32 点の実 DFT の 1 ch（u は実数なので、+j の和は順変換の共役） Σr u_r · exp(+j2πkr/32) = conj(U[k]) U = u の 32 点 DFT z[n] = u[2n] + j·u[2n+1]、Z = z の 16 点 DFT（dft16f） A = Z[k] + conj(Z[16−k])、B = Z[k] − conj(Z[16−k]) 2·U[k] = A + (−j·W32k)·B W32 = exp(−2πi/32) ③ m で変わる位相 exp(−j2πkp/32) = (−j)k·m · exp(−j2πk·95/32) 後ろの定数は落とす（電力に効かない） y_k[m] = (−j)k·m · conj(U[k]) → 丸めて 24 bit（Q8）

ブロック図

窓とフレームの位置

ビート q のクロックで、直近 7 ビート（112 サンプル）を xw[0..111] に並べる。xw[j] はサンプル番号 16(q − 6) + j で、j が大きいほど新しい。 96 タップのフレームを、末尾（p）が j = 103 と j = 111 の 2 か所に置く。ホップは 8 サンプルなので、1 ビート（16 サンプル）でちょうど 2 フレーム進む。

タイミング

入力に 2 クロックの途切れ（s_tvalid = 0）がある例。窓（hist）と q_cnt は valid なビートでしか進まないので、出力は途切れを含めて 18 クロック後に同じ形で出る。 途切れのクロックでも xw は毎クロック取り込むが、va = 0 のタグがついて運ばれ、y_valid が 0 になる。

小数部の流れ

  • 係数は Q20（和 = 1）。積は x の LSB に対して小数 20 bit
  • R で 10 bit 落として u は Q10
  • 最後の >>> 3 は、2·X の 1/2 と Q10 → Q8 の 2 bit

(−j)e の指数

  • m0 = 2q − 11 ≡ 2q + 1、m1 ≡ 2q + 2（mod 4）
  • q の最下位 bit だけで m mod 4 が決まる
  • e = k[1:0] · (m mod 4) の下位 2 bit。掛け算器は使わない

原型フィルタの応答

ch k の応答は、原型の応答を 128k MHz だけずらしたもの。出力は 512 MSPS なので、f と f ± 512 が同じ所に折り返す。 窓（最大 256 MHz）は ch の中心から ±64 MHz ずれた所にも置くので、使う範囲は ±(64 + 0.45 × 256) = ±179.2 MHz。 そこへ折り返してくる周波数は 512 − 179.2 = 332.8 MHz より外なので、そこから阻止域にしてある。

振る舞いの約束

入力の途切れ

  • s_tvalid = 0 のビートは窓も q_cnt も進めない。値は入力のサンプル列だけで決まる
  • 途切れた所は、18 クロック後の y_valid = 0 として出る
  • 後ろの ddc_core は y_valid の組ごとに進む（途切れに強い）

rst と k

  • rst は hist を 0 に、q_cnt を 0 にする。m = 0 は模型の y[0]（x の最初の 96 個で作るフレーム）
  • k は静的。変えたら rst を打ち直す（win_core の WRST がこれをする）
  • 定数の位相 exp(−j2πk·95/32) は落としてある。ddc_core・電力には効かない

飽和の数え

  • sat_cnt は u（f = 0 の 32 本の OR）と y の出口の飽和を数え、0xFFFF で止まる
  • Z（26 bit）と A / B（27 bit）は語幅の上限から飽和しない（模型で確かめる）
  • win_core の 0x6C PFB_SAT で読む。W-0 はこれが 0 であること

X の段を YW（24 bit）で宣言すると、28 bit の値が切り詰められて巻き戻る。初版の誤りで、sim の満杯の区間で 2 フレームだけ合わなかった。今は ZW + 2 = 28 bit で持ち、最後の段で丸めてから飽和させる。

確かめ方

sim（make sim-pfb）

  • iverilog で RTL と pfb_fixed を bit 単位で照合
  • k = 0 1 4 5 8 13 15 16（0・8・16 は実数化が自明な端、4・12 は 45°）× 入力の途切れ あり / なし
  • 陽性対照 SIM_PFB_POSCTL=1：分岐の和の丸めを切り捨てにすると、1 LSB の違いで落ちる
  • 模型の陽性対照 pfb-short（1 タップ / 分岐）・ppfb（位相 exp(−j2πkp/32) を落とす）も落ちる

実機（rev2）

  • W-0：PFB_SAT = 0（6 通りの幅・帯域の端とも）
  • W-2：窓の中の平らさが模型と 0.015 dB 以内（pfb・半帯域・FFT をまとめた値）
  • W-4：窓を粗い ch の境目（d = ±64）に置き、k と k + 1 で 0.014 dB
  • 通過特性の掃引（winresp）も模型の曲線と一致
