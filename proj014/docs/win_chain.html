RFSoC4x2 分光計 · proj014 rev2 · win_core_0 の中身

窓の 3 段: pfb_core → ddc_core → wspec_core

ADC_B の 4096 MSPS の実数列から、幅 W（256〜8 MHz）の窓を切り出して 4096 ch の電力スペクトルにする。3 段とも DSP ドメイン 256 MHz で動き、固定小数点の模型（model/win_fixed.py）と bit 単位で一致することを sim で確かめてある。

窓の置き方（PS が決める 3 つの値）

ゾーン 2 なので、IF と ADC の見かけの周波数 f は f = 4096 − IF（MHz）。窓の中心 c（f の側）を粗い ch と端数に分ける。

WK = round(c / 128) 粗い ch（0..16）。pfb_core の k d = c − 128·WK 端数（|d| ≦ 64 MHz） WDPHI = round(d / 512 · 2^32) mod 2^32 NCO の 1 サンプルの位相の増分（512 MSPS で） WNS = 1..6 半帯域の段数 → W = 512 / 2^WNS MHz

3 つとも書いただけでは効かず、CTRL[12] = WRST で取り込んで 3 段を最初からやり直す（フレーム番号・積分も 0 から）。観測中は変えない前提。PS の既定は中心を ch の格子に丸め、k·fs/8 の線（IF 2560・3072・3584 MHz）が窓の中央 90 % に入ると警告する。

pfb_core粗い PFB の 1 ch

4096 MSPS の実数列を 32 本の多相フィルタバンクに通し、そのうち ch k（中心 f = 128k MHz）の 1 本だけを 512 MSPS の複素数列 y として出す。ch 間隔 128 MHz に対して出力が 512 MSPS なので 4 倍オーバーサンプリングになり、±64 MHz の端数 d と窓の幅の半分を足しても ch の通過域に収まる。

y_k[m] = Σ_n h[n] · x[p − n] · exp(−j2πk(p − n)/32) p = 8m + 95、N = 96 タップ

段の中身

  1. 分岐の和: u_r[m] = Σ_t h[r+32t]·x[p−r−32t]（r = 0..31、t = 0..2）→ Q10 に丸め・22 bit で飽和
  2. 32 点の実 DFT の 1 ch: 偶奇を複素に詰めて 16 点 DFT（dft16f）→ 実数化の後処理（−j·W32k）
  3. (−j)k·m を掛ける（位相の m で変わる部分。定数の位相は電力に効かないので落とす）
  4. Q8 に丸め・24 bit で飽和 → y

振る舞いの約束

  • 1 ビート（16 サンプル）で 2 フレーム出す（ホップ 8 サンプル）。窓は直近 7 ビート = 112 サンプル
  • tvalid が落ちたビートでは窓を進めない。途切れても値は入力の列だけで決まる
  • m < 0 のフレーム（rst 後の最初の 11 個）は y_ok = 0 で出す
  • k は動作中に変えない（変えたら WRST）
  • 分岐の和は対称の相手が別の分岐にあるので前置加算が使えない（192 DSP の理由）

ddc_coreNCO と半帯域の縦続

y に NCO を掛けて窓の中心を 0 Hz に寄せ、半帯域フィルタで 2 分の 1 ずつ落として幅 W の複素数列 z にする。段数 WNS で 6 通りの幅を 1 本の bit で切り替える。

v[m] = round( y[m] · (cos φ − j sin φ) / 2^17 ) φ = 2π(a + 1/2) / 2^14, a = (m·WDPHI mod 2^32) の上位 14 bit z = sat18( round( v / 2^4 ) ) （Q8 → Q4）

NCO

  • 位相の累算 32 bit。1/4 波の表 4096 語 × 18 bit（振幅 217 − 1）を 2 口 ROM × 2 で引く
  • 番地に半 LSB のずらし（a + ½）を入れて、表の端の重複と偏りを消す
  • m = 0 は pfb_core の最初の ok なフレームで、そこで位相 0
  • pfb の出力の並び（y0 = 奇 m、y1 = 偶 m）を組（偶, 奇）に詰め直して 2 サンプル / 組で進む

半帯域（hb2）

  • 0 でない係数は偶数番目と中心だけ。対称なので前置加算で乗算は L + 1 個 / 成分
  • 組の間隔は自由（入力が来たときだけ進む）。遅延 5 クロック
  • 軽い段（15 タップ）を WNS − 1 段 → 最後に鋭い段（67 タップ）を 1 段
  • 各段 Q8 で丸め・24 bit で飽和。飽和は数えて DDC_SAT に出す

wspec_core溜め・FFT・電力・積分

z を 4096 語ずつ溜めて、溜まった面を途切れなく FFT IP に流し、電力を 64 bit で積む。realtime の FFT IP は入力の途切れを待たないので、W MSPS で必ず途切れる z を直接はつなげない。溜めがそのための緩衝になる。

Y = FFT4096(z) 順変換・unscaled（31 bit）・自然順 q = sat18( Y >>> SHIFT ) p = q_re² + q_im² 37 bit S = Σ p （N_ACC フレーム） 64 bit・二面

溜めと FFT への流し込み

  • 2 面 × 4096 語。書きながら、溜まった面を 4096 クロックで読み出す
  • rev2: 出口のレジスタは「空いている か IP が受けた」ときだけ進む（AXI の握手）。待たされても 1 語も落とさず、IP の枠 = 溜めの枠が保たれる
  • 読み出しが遅れたら次の面は予約して遅れて始める。書き込みが未読の番地に追いついたときだけ FLAGS[1]

積分と読み出し

  • RUN の時点で F0 = fin + 2（確実に未来）。ダンプ k はフレーム F0 + k·N … + N − 1
  • ダンプが閉じるたびに SEQ が 1 増え、読み出しの面が切り替わる（PS は SEQ → 中身 → SEQ で読む）
  • ダンプ k の最初のフレームの z を 4096 語スナップショットに残す。N_ACC = 1 なら FFT(スナップショット) とダンプが 1 対 1（--golden）
  • 既定 N_ACC = 6250（W = 256 MHz で 100 ms）
FLAGS意味（粘着・CTRL[8] で消す）
[0]FFT の出力の XK_INDEX が 1 ずつ進まなかった
[1]溜めの読み出しが間に合わなかった（未読の番地を書いた）
[2]IP の TLAST 事象（IP の枠と溜めの枠が合っていない）
[3]IP の data_in_channel_halt（フレームの途中で入力が途切れた）
[4]IP に待たされた（tready = 0）。rev2 ではデータを保って待つだけ
0x80 WS_STALL
WRST 以来、IP に待たされたクロック数
0x84 WS_RDY0
WRST の解除から IP の tready が最初に 1 になるまでのクロック数
ch b ↔ ν
ν = b·W/4096（b ≧ 2048 は b − 4096）。IF = 4096 − c − ν。並べ替えとゾーン 2 の反転は PS 側
rev1 は tready を見ずに流していた。WRST 直後に IP が受けなかった語のぶん枠がずれたまま回り、実機で FLAGS 0x14 → 0x4 と W-G の NG になった。sim の FFT のモデルに tready を足して同じ形を再現し、rev2 で直した（ビルド待ち）。

確かめ方

  • make sim-pfb・sim-ddc・sim-win: 各段を固定小数点の模型と bit 単位で照合（陽性対照つき）
  • make sim-wspec: 4 層（積分・FFT のモデル・帳簿・FLAGS）。tready を下げる変種 2 つと、rev1 の作りで落ちることを見る陽性対照 sim-wspec-r
