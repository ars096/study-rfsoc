wspec_core：窓のスペクトルを積む

ddc_core が出す z（複素 18 bit、W MSPS で途切れながら届く）を 4096 語ずつ溜め、溜まった 1 フレームを途切れなく FFT IP に流す。 出てきた 4096 ch を電力にして N_ACC フレーム積み、二面のメモリに交互にダンプとして残す。PS は AXI4-Lite で、閉じたほうの面を読む。

溜めを置く理由と、流れ方

realtime の FFT IP は、1 フレームの途中で入力が途切れても待たずに進む（proj011）。窓の出力 z は W MSPS なので、W < 256 では必ず途切れる。 そこで 4096 語を 2 面の溜めに書き、1 面溜まったら（fdone）その面を 4096 クロック続けて IP に流す。 次の面が溜まるには 4096 クロック以上かかる（z は 1 クロックに 1 個以下）ので、読み出しは間に合う。

  • 読み出し中にもう 1 面溜まったら（待たされて遅れた場合）、pend で予約して、今の面を読み終えた次のクロックから読み始める
  • 書き込みが、読み中の面の未読の番地か予約中の面に追いついたら ovr → FLAGS[1]（読み出しが間に合わなかった）
  • 溜めは z の到着順に書くだけで、IP の都合で書き込みを止めることはない。止まるのは読み出し側だけ

tready の握手（rev2）

出口のレジスタ（fd・f_v・f_last）は、「空いている（f_v = 0）」か「IP が今の語を受けた（tready = 1）」のときだけ次の語に進む（adv）。 溜めの番地 ra も同じ条件（issue = rd_go && adv）でしか進まない。これで IP に待たされても 1 語も落とさず、IP のフレームの枠 = 溜めのフレームの枠が保たれる。

電力と積分の段

段中身語幅
S0IP の出力を受ける。XK_INDEX = 0 のクロック（fs）でフレームの行き先（act・first・last・bank・k）を決め、タグに載せるY 31 bit
S1成分ごとに Y >>> SHIFT、18 bit に飽和（飽和したら印）q 18 bit
S2二乗の入口。積分の読み出しの番地を出す（そのフレームが first でなく、行き先の面が同じとき）18 bit
S3q_re²・q_im²（積分のメモリの読み 1 段目）36 bit
S4p = q_re² + q_im²（読み 2 段目）p 37 bit
S5書き込み: first なら p、そうでなければ 読み値 + p64 bit
  • 同じ ch は 4096 クロックおきにしか来ないので、読んで足して書く間に同じ番地の読みが追い越すことはない
  • 64 bit の余裕: p は最大 237 未満なので、飽和した値ばかりでも 227 フレーム積める（256 MHz で 2147 s、8 MHz で 68719 s）
  • first のフレームで読み値を捨てるので、面を 0 に消す手間が要らない（陽性対照 WSPEC_POSCTL は、ここで読み値に足して前のダンプを混ぜる）

ダンプの割り当てと読み出し

RUN（CTRL[0]）の時点で N_ACC・N_DUMP を取り込み、F0 = fin + 2（確実に未来のフレーム）を決める。ダンプ k はフレーム F0 + kN から N 個で、面 k mod 2 に積む。 最後のフレームの ch 4095 を書いたクロックで「閉じ」、SEQ が 1 増え、読み出しの面（rd_bank）と DUMP_K・N・F0・SAT がその面に切り替わる。

PS の読み方（seqlock）

  • SEQ と DUMP_* を読む → スペクトル 4096 × 64 bit（と要ればスナップショット）→ もう一度 SEQ
  • SEQ が変わっていたら読み直す（window.py の read_dump は 5 回まで）
  • FIN・FOUT などの 48 bit の値は、LO を読むと HI が固定される

読み終えるまでの期限

  • スペクトル: 次のダンプが閉じるまで（N フレーム）。閉じると読み出しの面が切り替わる
  • スナップショット: 閉じてから (N_ACC − 2) フレーム以内。2 つ先のダンプの最初のフレームが同じ面に書かれるため
  • N_ACC が小さいときは N_DUMP = 1 で 1 回だけ取る（--golden・W-8 の型）

FLAGS と見張り

bit意味普段
[0]XK_INDEX が 1 ずつ進まなかった（IP の出力の ch が飛んだ）0
[1]溜めの読み出しが間に合わなかった（ovr）0
[2]IP の TLAST 事象（tlast_unexpected・tlast_missing）。rev1 では枠のずれで立ち続けた0

  • FLAGS は粘着で、CTRL[8] で消す。win_core の FLAGS の [8]・[9] は pfb・ddc の飽和
  • WS_STALL（0x80）: rst 以来、待たされたクロック数。W-8 の実測で、W < 256 は 1 フレームに 1 クロック（数え × フレームの長さ = WRST から読むまでの 17.9 ms）
  • WS_RDY0（0x84）: rst の解除から tready が最初に 1 になるまで。実測は 0 クロック（予言「4096 より大きい」は外れ）

SHIFT の選び方

FFT は unscaled なので、窓の中の雑音の電力は W に比例する（同じ入力なら狭い窓ほど 1 ch あたりが小さい）。SHIFT は、次の 2 つを両方満たすように選ぶ。

床を下げすぎない（SHIFT の上限）

  • >>> は切り捨てなので、量子化の床が ≒ 0.67 LSB² 乗る
  • 雑音の床が数 LSB² 以上ないと、弱い線・小さな折り返し・線形性が切り捨ての偏り（振幅に反比例）で歪む
  • 実機では W-3 の床を 16 LSB² 以上にし、W-7 は 6.02 dB ごとに SHIFT を 1 下げた

飽和させない（SHIFT の下限）

  • q は 18 bit。強い線の ch が 217 を超えると飽和し、DUMP_SAT に数える
  • W-7（W = 256、SHIFT 15、+10 dBm）で q の余裕 33.9 dB・z の余裕 15.8 dB
  • 今は PS がスクリプトごとに選ぶ（自動 SHIFT は持ち越し）

確かめ方

sim（make sim-wspec）

  • FFT は振る舞いのモデル（sim/win_fft_model.v）。4 層で判定: A 電力と積分が整数模型と bit 単位で一致／B FFT のモデル = numpy の FFT／C 帳簿（f0・n・SEQ・面・スナップショット）／D FLAGS と fin − fout
  • 変種 5 つ: 途切れなし・3 クロックおき・32 クロックおき・tready が 6000 クロック遅れて 1・周期的に 40 クロック 0
  • 陽性対照: WSPEC_POSCTL（first でも足す）で A が落ちる／WSPEC_NOREADY（rev1 の形）で待たせる変種の B が落ちる
