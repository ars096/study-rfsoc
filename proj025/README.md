## 2G-2 の仕様（BITS.md・proj024 から）

| | 2G-2 | 2G-1（参考） |
|---|---|---|
| ADC | 2 本（4 本から SRC で選ぶ、proj024 D-8） | 1 本 |
| 1 本の FFT | 131072 点 = 16 レーン × **8192 点** | 262144 点 = 16 × 16384 |
| ch / ADC・df | 65536・31.25 kHz | 131072・15.625 kHz |
| フレーム L | 8192 ビート = 32 µs（10.24 ms に 320、格子 2.048 ms に 64） | 16384 ビート = 64 µs |
| PFB | T 4、L = 524,288 タップ、履歴 3 フレーム × 131072 × 14 bit = 5.5 Mbit / ADC | 1,048,576 タップ・11.0 Mbit |
| 語長（proj024 M-7） | Y 28 bit → 下 **1** bit を丸めて 27 → cmul SH 18 → V 25・Z 29（劣化 0.0017 dB） | 2 bit |
| 積分器 | コアごとに 8 銀行 × 8192 × 48 bit × 2 面 = 6.3 Mbit（2 コアで 12.6） | 12.6 Mbit |
| 流れ | KIND 1 FULL × 2、NCH 65536・FRAME_BEATS 8192、レコード 512 KiB × 2 / 10.24 ms | 1 MiB × 1 |
| PFB の重心のずれ 1.5·L | 48 µs | 96 µs |
| 資源の見積もり（proj024 E-1 を S-1 で引き直し） | DSP 39.1 %・BRAM 67.6 %・URAM 70 %・LUT 41.4 %（OOC のまま） | 19.6・59.3・70・23.9 % |
| レーン FFT の IP 1 個（S-1・S-2） | DSP 33・BRAM 13・LUT 3,957（OOC）、`-1`・256 MHz で WNS +1.67 ns | DSP 33・BRAM 21.5、+1.885 ns |

**2G-1 から変わる大きなこと: コアが 2 個になる。** 2G-1 はコア 1 個で避けられていた問題（LESSONS「IP の出口の k1 の位相はコアの間で揃う保証が無い」、proj023 4b）が戻ってくる。

## M. 2G-2 の部品を bit 単位で決める（`model/g22_fixed.py`、`make model`）— 予言（走らせる前に書く、2026-10-18）

proj024 の M-8（2G-1）と同じ 4 項目を、2G-2 の長さで。部品の作りは 2G-1 と同じで、変わるのは長さ・表の行数・丸めの bit だけ。

- **a 係数の補間**（D 64、左右の折り返し、片側 4096 区間）: N が半分なので傾き S は 1 タップあたり 2 倍 → **S は 2G-1 より 1 bit 多い 13 bit（G 5）**、V は 23 bit のまま。
  **G 5 で V ＋ S = 36 bit に入る**（RAMB36 の幅の上限ちょうど）。h に対する rms は全部の表の 1.01 倍以内（2G-1 は 1.0003 倍。補間の誤差は h'' ∝ 1/N² で 4 倍になるが、まだ量子化より十分小さい）。
  表は 4096 × 36 bit = 147 kbit。前半・後半を 2048 行ずつの 2 ポートの ROM（2K × 18 の RAMB36 を 2 個ずつ）にして **RAMB36 4 個**（2G-1 は 8）。
  ビートの式は全部の i で折り返しの式と一致、陽性対照（i' = L − i）は一致しない。応答の差 ≦ 0.05 dB
- **b ひねり係数の積**（k1 = hi·128 + lo、hi 64 行・lo 128 行）: 直の表との差 最大 2 LSB、rms の比 ≒ 1.7、成分は 18 bit に入る。陽性対照（hi·127 + lo）は差が 100 LSB を大きく越える
- **c 鎖の全体**（CW 1000 LSB ＋ 雑音 σ 100、Y の 1 bit の丸め・cmul SH 18）: 雑音の ch の ε は 2G-1（8.7e-6）の半分ほど（**4e-6〜9e-6、線は ≦ 2e-5**。proj024 M-7 で 2G-2 の丸めの雑音の比は 2G-1 の半分）、CW の ch の差 < 0.01 dB、y の飽和 0。
  陽性対照（k1 を 1 ずらす）は 1 ずれの位相 2π·p / N が 2 倍なので ε は 2G-1（1.2e-4）の 4 倍ほど（≒ 5e-4）で、線 2e-5 を越える。各段の最大は Y < 2^27
- **d 積分器の番地**: bit 反転順（13 bit）の k1 は 1 フレームで 8192 の番地を 1 回ずつ通り、同じ番地に戻るまで 8192 ビート

**結果（`make model`、2026-10-18）: 全部通過**（1 回目で。線は走らせる前のまま）

| | 結果 | 予言 |
|---|---|---|
| a 補間 | **G 5**: 差 ≦ 1 LSB・h に対する rms 0.2900 LSB（全部の表 0.2898、比 1.0005）・**V 23・S 13 = 36 bit**。ビートの式は全部の i で一致、陽性対照は 94,393 個違う。応答の差 0.000 dB。表 4096 × 36 bit = 147 kbit → **RAMB36 4 個** | 当たり（S 13・36 bit・RAMB36 4・比 ≦ 1.01） |
| b 積 | 直の表との差 最大 2 LSB・rms 0.668 LSB（直の表 0.396、比 1.69）・成分の最大 65,537。陽性対照は差 2,758 LSB | 当たり |
| c 鎖 | 雑音の ch の ε **8.5e-6**・CW の ch 0.0000 dB・y の飽和 0。各段の最大 Y 4.1M（< 2^27）・Yd 2.0M・V 0.51M・U 2.0M・Z 8.2M | 範囲（4e-6〜9e-6）と線は当たり、**「2G-1 の半分」は外れ**（同じ 8.5e-6 と 8.7e-6） |
| c 陽性対照（k1 を 1 ずらす） | ε **1.6e-4**（線 2e-5 は越えて落ちる） | 「2G-1 の 4 倍（≒ 5e-4）」は**外れ**（1.3 倍） |
| d 番地 | 13 bit の bit 反転順は 1 フレームで 8192 の番地を 1 回ずつ、戻るまで 8192 ビート | 当たり |

外れた 2 つの理由（結果の後に調べた。部品は直していない）:
- **ε は y の整数への丸めで決まっていて、N にも Y の丸めにも依らない**: 雑音 σ_x 100 の PFB の出口の y は σ ≒ 100、整数への丸めの雑音 1/12 → ε ≒ (1/12) / 100² = 8.3e-6（実測 8.5e-6）。
  proj024 M-7 の「2G-2 は 2G-1 の半分」は**Y の丸めの雑音どうしの比**で、それは y の丸めより 2 桁小さい。予言は効かない項の比で書いていた
- **陽性対照の ε は、ほぼ全部が k1 = M − 1 の 1 列から来る**: np.roll で k1 = M − 1 に W_N^(p·M) = W_16^p（大きく違う値）が入る。その列を除くと ε は 1.1e-5 で、**線 2e-5 の内側**（1 ずれの位相 2π·p / N そのものの寄与は 2.6e-6）。
  proj024 M-8 の「番地の 1 ずれが B 層でほとんど見えない」は、端の 1 列を除けば**まったく見えない**の意味だった。番地の誤りは bit 単位の照合（sim）と tw_k1 の見張りで捕まえる、の申し送りは変わらない（LESSONS「sim と模型」）。
  RTL では k1 が bit 反転順で来るので、ビートの 1 ずれは k1 の大きく違う値になり、こちらは振幅でも見える

生成の道具 `tools/gen_g22_tables.py`（`make gen`）: `build-gen/` に `g22_coef_lo.hex`・`g22_coef_hi.hex`（各 2048 行 × 36 bit）・`g22_tw_a.hex`（64 行）・`g22_tw_b.hex`（128 行、各 576 bit）を書き、読み返して模型と照らす（係数 524,288 タップ・ひねり係数 16 × 8192 とも一致）。`src/g22/` に写してコミットする（proj024 と同じ）

## 1a〜1d. 部品の単体の sim（`make sim-all`）— 予言（走らせる前に書く、2026-10-18）

proj024 の 1a〜1d の部品・tb・判定を写し、長さ（m・k1 を 13 bit、フレーム 8192 ビート）・表の行数（係数 2048 行 × 36 bit、A 64 行）・Y の幅（28 bit）と丸め（1 bit）だけを変えた。段の数は変えていない。
sim は作業用のクラウドの環境の Icarus Verilog（oss-cad-suite 2024-10-18 の 13.0 devel。proj024 は 14.0 devel）で回す。

- **1a g22_coef**: 1 フレーム ＋ 512 ビート（切れ目 2 か所）の全部の (m, t, p) が模型の coef_beat と一致、LAT 5（2G-1 と同じ）。陽性対照（-DCOEF_FRAC_ERR）は落ちる
- **1b g22_tw**: 8192 ＋ 256 ビートの全部が tw_prod と一致、k1_out の並びは入れたとおり、LAT 6。陽性対照（-DTW_HI_ERR）は落ちる
- **1c g22_pfb**: 5 フレーム（40,960 ビート）が pfb_int と一致、sat_cnt 0・coef_mis 0、フレームの途中から入れた 384 ビートは捨てる。陽性対照 2 本（係数が 1 ビートずれる・起動の直後のマスクなし）は落ちる
- **1d g22_tw ＋ g22_chain**: 3 フレームが chain_Y ＋ power と一致（SHIFT 7・4）、tw_mis 0。陽性対照 2 本（TW_LAT 5・丸めなし）は落ちる
- 外れるとしたら: 幅を 1 bit 縮めたところの取り残し（`[13:0]` を機械的に置き換えたので、14 を数として書いた所 — ループの上限・定数 — が残っていれば、sim で番地の上半分が出ない形で出る）

**結果（`make sim-all`、2026-10-18、1 分）: 全部通過・陽性対照 6 本は全部落ちた**（1 回目で。予言どおり）

| | ふつう | 陽性対照（落ちた理由） |
|---|---|---|
| 1a g22_coef | 8,704 行・m の種類 8192 / 8192・**模型と違う行 0**・レイテンシはどのビートも同じ（tb の数えで 4 = RTL の LAT 5。2G-1 と同じ数え方） | COEF_FRAC_ERR: 8,704 行が違う |
| 1b g22_tw | 8,460 行・**違う行 0**・k1_out の並びは入れたとおり（1 フレームの k1 の種類 8192）・LAT 6 | TW_HI_ERR: 全部の行が違う |
| 1c g22_pfb | 40,960 ビート（途中から入れた 384 は捨てた）・並び OK・**違うビート 0**・sat_cnt 0・coef_mis 0 | DLY_ERR: 17,043 ビート違い coef_mis 1 / NOMASK: 起動の直後に初期化していない履歴（x）を拾う |
| 1d g22_tw ＋ g22_chain | SHIFT 7・4 とも 24,576 ビート・k1 の並び OK・**違うビート 0**・tw_mis 0（飽和を含むビートは模型と同じ 1・2） | TW_LAT_ERR: 16,384 ビート違い tw_mis 1 / NORND: 2,211 ビート違い |

- 予言の「外れるとしたら」（14 を数として書いた所の取り残し）は無かった。置き換えの後に `16383`・`16384`・`14'd`・`b < 14` を grep して、残りを手で直した（tb の brev・PFB の m の上限・待ちの番地）
- 1c の PRE の始まりは 2G-1 の 16000 から 7800 にした（8192 を越えると 13 bit で巻き戻って 0 を通り、「m = 0 まで捨てる」の試験にならない）

## 決めること（2026-10-18 に並べた）

**決定（2026-10-21、西村さん）: E-1〜E-6 は全部、下の表の勧め（太字）のとおり。** E-1 (a) Wide の形の s45_core × 2・E-2 (a) 係数の ROM はコアごと・E-3 ひねり係数の ROM はコアごと・E-4 SRC はコアごとに 4 本から 1 本（2 コアに同じ ADC も可）・E-5 RAW はコア 0 だけ、TP は FULL の流れごと・E-6 段階 B は 2G-1 の実機の最初の確かめの後のタグから写す。

2G-1 から変わるのは**コアが 2 個になる**ことだけ。部品（1a〜1d）は 1 コアぶんで、模型と bit 単位で一致した。段階 B の前に決めておきたいのは組み方。

| | 決めること | 候補（**勧め**） | 理由 |
|---|---|---|---|
| E-1 | コアの組み方 | **(a) Wide（proj023）の形: s45_core のセルを 2 個（s45_core_0・_1、コアごとに AXI の窓・FULL の流れ 1 本、RAW はコア 0 だけ）**。セルの中身は 2G-1 の g21_s45_core を長さで直したもの / (b) 2G-1 の形を広げる: g22_s45_core 1 個の中に g22_core を 2 個（流れ 2 本 ＋ RAW） | (a) は build.tcl のコアごとの結線の表と照合・PS のコアをセルの名前で見つける道（Wide で実機を通った）をそのまま使える。(b) は AXI の窓と rec_arb の作りを変えることになり、新しく試すところが増える |
| E-2 | PFB の係数の ROM | **(a) コアごとに 1 個**（RAMB36 4 個 × 2 = 8、デバイスの 0.7 %） / (b) 2 コアで共有（Wide と同じ。番地はコア 0 が出し、コアごとに 1 段受けて coef_mis で照合） | 共有してよい種類の ROM（T だけで引く。LESSONS）だが、Wide は共有の ROM の配りで `-1` の余裕が 25 ps になり、1 段を足した（proj023 3 回目のビルド）。2G-2 は表が小さく、コアごとに置いても BRAM はほぼ増えない。コアどうしの配線が無くなる |
| E-3 | ひねり係数の ROM | **コアごとに 1 個**（選べない） | IP の出口の k1 で引く ROM（LESSONS、proj023 4b）。BRAM は 1 コア 16 個ほど |
| E-4 | 入力の ADC（SRC） | **コアごとに 4 本から 1 本を選ぶ**（axis_sel4 をコアごとに。proj024 D-8 の「2 本を選ぶ」を、選び方を縛らない形で）。**2 コアに同じ ADC を選んでもよい**ことにする | 同じ ADC を 2 コアに入れると、2 本のスペクトルは bit 単位で同じになるはず → **実機で 2 コアの同等を確かめる陽性対照**に使える（違えば片方のコアの位相・番地の誤り。proj023 4b のタイル 224 の tw_mis のような事象を、配線を変えずに見分けられる） |
| E-5 | RAW の流れ・TP | **RAW はコア 0 だけ（自分の SRC、2G-1 の D-13・D-14 と同じ）。TP は FULL の流れごとに、その SRC の ADC で（D-12 と同じ）** | Wide・2G-1 と同じ形 |
| E-6 | 段階 B の写し元 | **2G-1 の実機の最初の確かめ（FULL のスペクトルが模型と合う・取得が回る）が済んだ commit に注釈つきのタグ（`proj024-m0` の案）を付け、そこから写す** | 写した後に 2G-1 で直ったことを 2 か所に入れずに済む |

資源の見込み（proj024 の S-1・2f の実測から足し引き。段階 B のビルドで確かめる）: DSP ≒ 37 %（コア 1 個 ≒ 800）・LUT ≒ 35〜41 %（レーン FFT 32 個）・
BRAM ≒ 70 %（2G-1 の 62 % ＋ レーン FFT の差 +72 ＋ ひねり係数 ROM の 2 個目）・URAM は 2G-1 と同じ程度（積分器の総量は同じ 12.6 Mbit）。
タイミングは 2G-1 の既定の戦略で −0.110 ns（積分器の URAM と PFB の履歴の BRAM のカスケード）だった。2G-2 は 1 個あたりの記憶の深さが半分なので、カスケードは短くなる見込み

### 2a〜2e・4d-2 の sim — 予言（走らせる前に書く、2026-10-22）
