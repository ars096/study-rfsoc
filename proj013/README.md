# proj013 — 全帯域の total power を 1 ms ごとに取る（4 IF）

日付: 2026-09-28
状態: **準備中**（RTL と sim まで: `make sim-tp`・陽性対照・`make sim` SHIFT 7 / 4 が通過。build.tcl はファイルを足しただけ。PS 側は未）

## 目的

**4 本の IF それぞれで、全帯域（2 GHz）の電力 Σx² を 1 ms ごとに取り、スペクトルと同じフレーム番号の上に並べる。**

- 連続波・total power の観測に要る（SAM45 の代替として、分光と同時に全帯域の電力を持つ）
- 持ち越しの切り分けに使う: 判定 3 の 1 s 以上のちらつき（100 ms のダンプでしか見ていない）と、判定 1 のタイル間の差 0.27 dB が時間で動くか
- **窓の切り出し（proj014 以降）の前に置く。**窓の方式に依らず接続点（ギアボックスの出口）が変わらず、先に入れて資源と `-1` を実測すれば、窓はその残りで設計できる

土台は proj012 rev3（4 本とも判定 0・2・5 通過、`-1` WNS +0.070 ns）。1 本ずつの分光計は proj012 rev3 と同一で、proj012 の判定を回帰試験に使う。

## tp_core の作り（proj012 rev3 の `-1` の最悪経路から）

```
s0  フレームの頭の判定（pre_*: 48 bit の比較は前のクロックにレジスタへ）
s1  入力を 1 回だけ受ける（x = tdata >>> 2、16 レーン）
s2  s3  DSP の入口のレジスタ 2 段（AREG/BREG = 2）
s4  s5  x² → M → P（DSP 16 個 / ch）
s6..s9  加算木 16 → 8 → 4 → 2 → 1（1 段ごとにレジスタ）
s10 区切りの和（64 bit）  s11 リングバッファ（BRAM）へ
```

- **ファブリックの加算から DSP の入口へ直につながない**（群 A・B の形を作らない）
- spec_core の入力（s_axis_tdata）に足すファンアウトは s1 の 256 本だけ
- 区切りの判定は `fcur ≥ TP_N − 1`（等号にしない。F0 を取りこぼしたまま TP_N を小さくすると区切りが止まることを、単体の sim の陽性対照で見つけた）

| 判定 | 内容 | 予言 |
|---|---|---|

## やったこと

- proj012 の追跡ファイルを複製（`git ls-files proj012`）。ID・proj の名前・BITFILE を proj013 に
- `src/tp_core.v` を書き、spec_core につないだ
- 単体の sim（`make sim-tp`）: 模型は RTL の写しではなく仕様（tp_core.v の冒頭）から書いた。試験は自走（TP_N 3）→ TP_N 1 で RUN（530 個でリングバッファが一巡）→ TP_N 4 で RUN。**RUN の F0 の頭の直前には必ず 3 クロックの隙間**を入れた（F0 の判定の急所）
  - 1 回目で通過。陽性対照（隙間を考えない F0 の判定）を入れると、F0 を取りこぼした後 **TP_WP が 7 で止まった**。TP_N を 4 → 1 に下げると `fcur == TP_N−1` が二度と成り立たないため → 判定を `≥` にした
  - `≥` にすると陽性対照が**通ってしまった**。RUN で始まった区切りが最後の 512 個の外に出ていた → 試験の順序を入れ替え、「最後の 512 個の中に F0 で始まった区切りと短い区切りがある」ことも判定に足した。今は本番が通過・陽性対照が落ちる
