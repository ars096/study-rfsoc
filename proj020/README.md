# proj020 — SAM45-Fine rev2: 窓の分光に PFB（T = 4）を入れ、ch の応答のサイドローブを下げる

日付: 2026-10-07
状態: **`-1` で閉じた**（2026-10-08、Performance_Explore で WNS +0.047 ns。実機は未）

## 目的

**SAM45-Fine（proj017）の窓の分光の ch の応答を、矩形（第 1 サイドローブ −13 dB）から PFB（T = 4）に替える。**
ddc の出口（z、複素 18 bit・Q4）と複素 4096 点 FFT の間に、4 タップの多相の重み付き和を入れる。点数・dt・時刻の格子・TP・読み出しは変えない。

- 合否の中心: 窓の ch の応答（SG の掃引、`winresp.py` の型）で、隣の ch の外（|Δ| ≧ 1.5 ch）が設計の値まで下がっていること
- 単位（proj019 の abs）・窓の和 = TP・リニアリティ・時刻の判定（F-4）が、変える前と同じ形で通ること
- `-1` で閉じる（proj017 は WNS +0.038 ns。ここが山）

土台: **RTL・sim・build は proj017 rev1**（`git ls-files proj017`、pynq を除く）、**PS（`pynq/`）は proj019**（specd・s45* を持つ。proj019 は PS だけの proj）。
2026-10-07 に複製した。ID・BITFILE・build.tcl の `proj` はまだ proj017 のまま（着手で直す）。

経緯: 2026-10-07 の業務ログ「決定: 窓の ch の応答のサイドローブ対策として PFB（T = 4）を proj020 で入れる」
（理由: 感度を落とさず、資源は DSP +80・BRAM +160 前後。見送った案: Hann の窓 = 重ねないと感度が落ち、重ねると FFT が 2 倍）。
SAM45-Wide は proj021 に繰り下げ。

## 下調べ（2026-10-07、`model/pfb_proto.py`。最初の原型を決めたときのもの。決め直しは下調べ 2）

原型 h = sinc(bw·n / 4096) × 窓関数、16384 タップ。ch の応答（電力、ch の中心で 0 dB）:

| 原型 | 半 ch の落ち（scallop） | 隣接 ch の和 Σ_k P(f − k) の波打ち | \|Δ\| ≧ 1.5 ch の最大 | ENBW |
|---|---|---|---|---|
| 矩形（現行、T = 1） | −3.92 dB | 0 dB | −13.5 dB（2.5〜10 ch で −17.9、> 10 ch で −30） | 1.000 ch |
| sinc × Hann、bw 1.00 | −6.12 | 3.11 | −63.4 | 0.776 |
| sinc × Hamming、bw 1.00 | −6.08 | 3.07 | −67.9 | 0.799 |
| sinc × Kaiser β 8、bw 1.00 | −5.88 | 2.88 | **−83.6** | 0.776 |
| sinc × Kaiser β 8、bw 1.10 | −4.58 | 1.58 | −81.1 | 0.862 |
| sinc × Hamming、bw 1.10 | −4.38 | 1.37 | −57.8 | 0.900 |

- 係数を 18 bit に丸めても、\|Δ\| ≦ 10 ch の値は変わらない（> 10 ch の床が −124〜−131 dB に上がるだけ）
- **臨界サンプリングの PFB は ch の間に谷を作る**: bw 1.00 では半 ch で −6 dB、隣接 ch の電力の和が 3 dB 波打つ（矩形は 0 dB で平ら）。
  ch の間に来た線は矩形より 2 dB 低く出る。業務ログの「感度を落とさず」は ch の中心と雑音の話で、ch の間の線には成り立たない。bw を広げると谷は浅くなるがサイドローブと分解能（ENBW）と引き換え
- ENBW < 1 ch: 雑音の帯域が狭いぶん、同じ電力の雑音で ch の値が 0.78 倍。**単位（abs）を保つには係数の規格化を決める**（下）

## 下調べ 2（2026-10-07、別の会話。`model/pfb_proto2.py`）

要件を「0.5 ch で −3 dB（隣の ch と −3 dB で交わる）・|Δ| ≧ 1 ch で < −50 dB・0.5 ch 未満はできるだけ平ら」と置き直した
（Klein et al. 2012, A&A 542, L3 の XFFTS の ch の応答を参考に）。sinc × Kaiser の bw を 0.5 ch で −3 dB になるよう β ごとに合わせ、18 bit で評価:

| 原型 | 0.5 ch | ≧ 1 ch | ≧ 1.5 ch | ≧ 3 ch | 0.4 ch | 和の波打ち | ENBW |
|---|---|---|---|---|---|---|---|
| rev1: Kaiser β 8・bw 1.00 | −5.88 | −42.1 | −83.6 | −101.5 | −3.35 | 2.88 dB | 0.776 |
| **F: Kaiser β 5・bw 1.198（採用）** | **−3.00** | **−53.7** | −58.0 | −64.5 | −1.20 | **0.08 dB** | 1.010 |
| H: T = 3、Kaiser β 3.25・bw 1.215 | −2.99 | −41.9 | −48.0 | −54.5 | −1.28 | 0.08 dB | 1.010 |

T = 2 は ≧ 1 ch が −25 dB 止まり、T = 3 は minimax でも −49 dB、−60 dB には T ≧ 6 が要る。
図: `docs/pfb_cand_50_40dB.png`（候補の比較）・`docs/pfb_cand_60dB.png`・`docs/pfb_resp_T4.png`・`docs/pfb_resp_T8.png`・`docs/pfb_T4_vs_T8.png`。

**飽和の余裕（F で変わる）**: 最悪の CW は **ch の間ちょうど（0.5 ch）**に来たもので、フレームごとに位相が反転し、負の係数（端の側のタップ）が足し合わさる。
そのときの PFB の出口の振幅は z の **1.405 倍（+2.95 dB）**（番地ごとの Σ|c| の最大と同じ。β 8 は ch の中心で 1.153 倍 = +1.24 dB）。
ch の中心の CW は 0.998 倍、0.25 ch で 1.19 倍。win_fixed の見積もり（−1 dBFS の CW に FFT の入力で G 4 は 7 dB、G 5 = NS 7・8 は 1 dB の余裕）から、
**NS 1..6 は 4 dB 前後の余裕が残り、NS 7・8（仕様の外の 4・2 MHz）は −1 dBFS 近い CW が ch の間に来ると FLAGS[5] が立つ見込み**。実機の W-6 の型（強い CW）で確かめる。

まだ決めていない: **5. 時刻**。RTL は出力フレームの番号を最新の入力フレームで呼ぶので、DUMP_T・F0・X(NS) の意味は proj017 と同じ。
ただしダンプの重心は矩形より 1.5·L(NS) 前（NS 1 で 24 µs、NS 6 で 768 µs、NS 8 で 3.1 ms）で、幅の違う窓どうしでは区切りの重心がこの差だけずれる。
PS で X(NS) に −1.5·L を足して扱う（RTL は変えない）か、そのまま記録に残すかは、運転の時刻の要求（BITS.md）と照らして決める。

## 判定（実機。測る前に書く、2026-10-08）

ビットは **build-PE/**（`-1`・Performance_Explore、WNS +0.047 ns）。BUILD_TAG は proj017 と同じ値（プリセットあり・`-1`・ch の番号しか持たない）なので、
**proj020 の RTL が載ったことは実機の ID（0x0020_0100・0x0020_A100・0x0020_7101・spec_core 0x0020_01xx）で確かめる**。

| 判定 | 道具 | 合格 | 予言・注意 |
|---|---|---|---|
| P-0 | `timetest.py --t0` | ID が 0x0020 系、4 ADC の PLL ロック、PPS の間隔 ±1 ビート | timebase は「未較正」と出る（CAL 0x0020_7101 は None） |
| P-1 | `window.py --probe`（A0・D1） | W-0: FLAGS 0（[4] は除く。**[5] PFB の飽和 0**）・z が流れる | |
| P-2 | `window.py --golden`（W 256・8） | W-G: N_ACC 1 のダンプ = スナップショット（**PFB の出口**）の numpy FFT | PFB を通した後の FFT IP の枠の直接の証拠。スナップショットの中身は z ではなく PFB の出口 |
| P-3 | `window.py --tone 3010.5 --w6`（W 256・64） | W-1: CW が予言の ch・W-6: 窓 / 全帯域の比が予言 ±0.1 dB | 予言の比は PFB の ch の中心の利得 0.995² で **−0.04 dB** 低い。**window.py の端数の推定・目減りの戻しは矩形（sinc²）の式のまま**なので、CW は ch の格子の上（3010.5 は W 256・64 で格子の上）に置く |
| P-4 | `timetest.py --t1 --seconds 120` | F-1: 13 コアが START_AT + 1 で RUN、ダンプの DUMP_T のずれ 0、健全性なし | proj017 と同じ（PFB は区切りの意味を変えない） |
| P-5 | `s45resp.py`（specd 経由、proj019 の resp1 と同じ配置・同じレベル） | ch の応答が模型（F）と合う | 0.5 ch **−3.0 dB**・0.4 ch −1.2 dB・隣接 ch の和の波打ち 0.1 dB・\|Δ\| ≧ 1 ch **−54 dB**（遠くはアナログ・ADC の線で床）。窓の形（band）は proj017 と同じ（DDC は変えていない）。proj017 の resp1 の半 ch は −3.9 dB（sinc²）のはず |
| P-6 | `fine.py --f4 --dumps 44000` | F-4: 30 分、8 窓・TP 4 本の読み落とし 0、区切りの一致（DUMP_T − D − X）±2 ビート、FLAGS は [4] 以外 0 | 区切りの重心が 1.5·L 前に動くのは DUMP_T に出ない（RTL の区切りの意味は同じ）。読み出しの 1 周は proj017 と同じ |
| P-7 | `timetest.py --t2 --t2-adc 0,1,2,3`（1PPS を 4 分配） | F-2: adc_to_core を 4 本測り、timebase.CAL 0x0020_7101 を埋める | proj017 の 122〜127 ns の近く（ギアボックスは同じ RTL、配置が違う） |
| P-8 | 窓の和 = TP（proj019 の型） | 窓の和 / TP が proj017 と同じ（0.5 %） | Σh² の規格化で雑音の利得 1。PFB で変わらないはず |

TP の dBm（tp_cal.json の bit_id_win 00170100）は proj020.bit では specd が出さない。TP の経路は変えていないので、P-8 の後に照合の範囲を広げるか s45cal で取り直すかを決める。
