# proj020 — SAM45-Fine rev2: 窓の分光に PFB（T = 4）を入れ、ch の応答のサイドローブを下げる

日付: 2026-10-07
状態: **準備中**（原型・置き場所・記憶・規格化は決めた。RTL は未着手）

## 目的

**SAM45-Fine（proj017）の窓の分光の ch の応答を、矩形（第 1 サイドローブ −13 dB）から PFB（T = 4）に替える。**
ddc の出口（z、複素 18 bit・Q4）と複素 4096 点 FFT の間に、4 タップの多相の重み付き和を入れる。点数・dt・時刻の格子・TP・読み出しは変えない。

- 合否の中心: 窓の ch の応答（SG の掃引、`winresp.py` の型）で、隣の ch の外（|Δ| ≧ 1.5 ch）が設計の値まで下がっていること
- 単位（proj019 の abs）・窓の和 = TP・リニアリティ・時刻の判定（F-4）が、変える前と同じ形で通ること
- `-1` で閉じる（proj017 は WNS +0.038 ns。ここが山）

土台: **RTL・sim・build は proj017 rev1**（`git ls-files proj017`、pynq を除く）、**PS（`pynq/`）は proj019**（specd・s45* を持つ。proj019 は PS だけの proj）。
2026-10-07 に複製した。ID・BITFILE・build.tcl の `proj` はまだ proj017 のまま（着手で直す）。

経緯: 2026-10-07 の業務ログ「決定: 窓の ch の応答のサイドローブ対策として PFB（T = 4）を proj020 で入れる」
（理由: 感度を落とさず、資源は DSP +80・BRAM +160 前後。見送った案: Hann の窓 = 重ねないと感度が落ち、重ねると FFT が 2 倍）。
SAM45-Wide は proj021 に繰り下げ。

## 下調べ（2026-10-07、`model/pfb_proto.py`）

原型 h = sinc(bw·n / 4096) × 窓関数、16384 タップ。ch の応答（電力、ch の中心で 0 dB）:

| 原型 | 半 ch の落ち（scallop） | 隣接 ch の和 Σ_k P(f − k) の波打ち | \|Δ\| ≧ 1.5 ch の最大 | ENBW |
|---|---|---|---|---|
| 矩形（現行、T = 1） | −3.92 dB | 0 dB | −13.5 dB（2.5〜10 ch で −17.9、> 10 ch で −30） | 1.000 ch |
| sinc × Hann、bw 1.00 | −6.12 | 3.11 | −63.4 | 0.776 |
| sinc × Hamming、bw 1.00 | −6.08 | 3.07 | −67.9 | 0.799 |
| sinc × Kaiser β 8、bw 1.00 | −5.88 | 2.88 | **−83.6** | 0.776 |
| sinc × Kaiser β 8、bw 1.10 | −4.58 | 1.58 | −81.1 | 0.862 |
| sinc × Hamming、bw 1.10 | −4.38 | 1.37 | −57.8 | 0.900 |

- 係数を 18 bit に丸めても、\|Δ\| ≦ 10 ch の値は変わらない（> 10 ch の床が −124〜−131 dB に上がるだけ）
- **臨界サンプリングの PFB は ch の間に谷を作る**: bw 1.00 では半 ch で −6 dB、隣接 ch の電力の和が 3 dB 波打つ（矩形は 0 dB で平ら）。
  ch の間に来た線は矩形より 2 dB 低く出る。業務ログの「感度を落とさず」は ch の中心と雑音の話で、ch の間の線には成り立たない。bw を広げると谷は浅くなるがサイドローブと分解能（ENBW）と引き換え
- ENBW < 1 ch: 雑音の帯域が狭いぶん、同じ電力の雑音で ch の値が 0.78 倍。**単位（abs）を保つには係数の規格化を決める**（下）

| 1. 原型 | Kaiser β 8・bw 1.00（\|Δ\| ≧ 1.5 で −84 dB）/ bw を広げて谷を浅く / Hamming | 何 dB まで要るか（強い線の隣の弱い線、櫛 n × 163.84 MHz の漏れ）と、ch の間の谷のどちらを取るか |
| 2. 置き場所 | **案 A**: z の入口に 3 フレームの遅延線と積和（1 / クロック以下で流れる）/ **案 B**: 溜めを 2 面 → 5 面のリングにし、読み出しの側（IP へ流す 4096 クロック）で 4 面を同時に読んで積和 | B は溜めと履歴を兼ね、積和が IP の前の途切れない流れに乗る。A は wspec の溜めに触らない |

| 6. 立ち上がり | WRST の後の最初の 3 フレームは履歴が埋まっていない。F0 = (⌊fin / M⌋ + 2)·M が 3 フレームより先かを確かめる / 埋まるまで ok を落とす | M = 1 の窓（NS ≧ 8）は F0 − fin が 2 しかない |

## 決めたこと（2026-10-07、西村さんの確認済み）

| | 決定 | 読み |
|---|---|---|
| 原型 | **sinc × Kaiser β 8、bw 1.00**、16384 タップ、係数 18 bit | \|Δ\| ≧ 1.5 ch で −83.6 dB。ch の間の谷（半 ch −5.9 dB、隣接 ch の和の波打ち 2.9 dB）は受け入れる |
| 置き場所 | **案 B: wspec の溜めを 2 面 → 5 面のリングに**。IP へ流す 4096 クロックの間に 4 面（フレーム k − 3 … k）を同じ番地で読み、積和して IP へ | 溜めと履歴を兼ねる。積和は途切れのない流れに乗り、tready の握手（rev2）の外側の作りはそのまま。書き込みは 5 面目 |
| 記憶 | **URAM**（今の溜めの BRAM 8 / 窓は空く） | 4 面を同時に読み 1 面に書くので、面を別の記憶に。URAM 4K × 72 に 2 面を詰め、書きはバイトの書き込み許可で半語（URAM 3 / 窓 = 24、今 16 → 40 / 80）。詰めないなら 5 / 窓 = 40（→ 56 / 80） |
| 規格化 | **雑音の電力を保つ**（Σh² で規格化） | proj019 の abs の式と「窓の和 = TP」をそのまま使う。CW の山は矩形より +1.1 dB（1 / ENBW）。判定で見込む |
