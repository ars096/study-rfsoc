# proj011 — FFT IP を realtime・資源優先に設定し直し、1ch のまま資源と `-1` の余裕を測り直す

日付: 2026-09-24
状態: **ほぼ完了**（rev6。DSP 480（4ch で 45 %）、`-1` の余裕 +0.277 ns（rev2）。判定 0・1・2・3 と realtime の危険（1 時間）が通過。起動の途切れは原因未解明のまま、見張り・FLAGS・自動のやり直しの三重で守る。残りは rev6 の `-1` の測り直し）

## 目的

**4ch に広げる前と、窓の切り出しの方式を選ぶ前に、「FFT 1 本にどれだけ資源を使うか」を実測で押さえる。**

proj010 は 1ch で動いたが、次の 2 つが 4ch への拡張と窓の切り出しの両方を塞いでいる:

- **DSP**: 944（22.1 %）のうち **FFT IP が 800（1 個 50 × 16）**。そのまま 4ch にすると 3776（88 %）。
  最終仕様（IF 4 本 × 1 IF あたり 2〜8 窓）で窓ごとに FFT を持つなら、さらに足りない
- **`-1` の余裕**: WNS +0.081 ns（周期 3.906 ns の 2 %）。`-2` の最悪経路は **nonrealtime を選んだために
  IP の中に生えるクロックイネーブル（CE）の大ファンアウト**（配線 97 %）だった

どちらも **IP の設定だけで手が打てる**（RTL はほぼ変えない）。この proj ではそれを試し、
FFT 1 本あたりの DSP・LUT・BRAM と、`-1` の WNS を実測で出す。その数字を持って、proj012 以降で
窓の切り出しの方式（ソフト DDC か粗い PFB か）を選ぶ。

**機能は proj010 と同じ**（ADC_B 1 本・8192 点・4096 ch × 0.5 MHz・100 ms 積分）。
proj010 の判定の道具（`make sim`・`--probe`・`--golden`・`--tone`・`--radiometer`・`--tick`）を回帰試験に使う。

## 手順

1. **`make sim`**（Vivado 不要）— spec_core の接続を 1 本外したので、proj010 と同じ 3 層（bit 単位・numpy・帳簿）で通ることを確かめる。
   モデル（`sim/lane_fft_model.v`）も出力側の tready を外した。**途切れたときの realtime の IP の振る舞いはモデルしていない**
2. **`make survey`**（新設）— FFT IP を 1 個ずつ OOC 合成し、8 通り（throttle × 乗算器 × バタフライ）の資源を
   `build-survey/survey.txt` に出す。**nonrealtime / performance / xtremedsp（= proj010）が DSP 50 になることを物差しの検証にする**
3. survey の数字で「本番」の予言（下の表の空欄）を書く — **ビルドの前に**
4. `make` と `make FFT_OPT=perf`（`-2`）、`make timing-check` と `make timing-check FFT_OPT=perf`（`-1`）
5. 実機: res の `.bit` で回帰試験（下の「実機」）

## rev2（2026-09-24）— フレーム頭の判定を前もってレジスタに置く

rev1 の最悪経路（`cur_k → t_last`、フレーム頭の 1 クロックで 32 bit の加算・比較を 2 段直列）を構造から直す。

- **幅のある演算を `pre_*` に追い出した**: `cur_k + 1`・`cur_k + 1 == run_ndump`・`cur_idx + 1`・`cur_idx + 1 == n_eff − 1`・`n_eff == 1`・`cur_idx == 0xFFFF_FFFF`。
  入力（`cur_k`・`cur_idx`・`run_ndump`・`run_n`）はフレーム頭と RUN でしか変わらず、次に読まれるまで 512 クロック（RUN からは 2 フレーム以上）あるので、1 クロック遅れで必ず間に合う
- **`fout == run_f0`（48 bit）も追い出した**: `fout` はフレーム頭の直前（k1 = 511）に進むので、同じ瞬間に `fout + 1 == run_f0` をレジスタへ取る。RUN と同じクロックでは消す（新しい `run_f0 = fin + 2` とはどのみち一致しない）
- フレーム頭に残るのは選択だけ。ID = **0x0011_02CC**。`spectrometer.py` は上位 16 bit で照合し、rev を表示する
- **`make sim`（SHIFT 7）: 全部通過。3 試験のダンプ（各 8215 行）が ID の 1 行を除いて rev1 と完全に同じ**（振る舞いを変えていないことの確認）

## rev3（2026-09-25）— TLAST 事象の診断

rev2 の実機で、realtime の FFT IP の TLAST 事象（FLAGS[5]）が**起動の 7/20 で立ち、立てばその起動の間ずっと立つ**と分かった（proj010 は 0/20）。
立つ起動でも `--golden` の照合は通るので、**「枠は正しく、IP の TLAST の検査だけがずれている」**と読んだ。この見立てを直す前に確かめる。

- **診断のレジスタ（0x58–0x68）を足した。データの経路には触らない**
  - `DIAG_TL`: レーンごと（16 本）の unexpected / missing（粘着）
  - `DIAG_EV`: レーン 0 の最初の TLAST 事象の種類と、そのときの入力側の数え `m_in`
  - `DIAG_FS`: レーン 0 の `event_frame_started`（**IP が枠を始めた瞬間**）の `m_in`。以後違えば印、レーン間で揃わなければ印
  - `DIAG_EVCNT` / `DIAG_FSCNT`: 事象のクロック数 / frame_started の回数
  - CTRL[9] で診断だけを消す（`--flagwatch` は FLAGS を何度も消すので、診断は Overlay からの累積で見る）
- ID = 0x0011_03CC。`--flagwatch` が見張りの前と後に診断を表示する
- **陽性対照を sim に作った**: `make sim SIM_SKEW=5` で、モデルの**TLAST の検査の数えだけ**を 5 サンプルずらす（枠は変えない。見立てと同じ形）。
  FLAGS = 0x20・16 レーンとも両方の事象・1 フレームに 2 回・データは bit 単位で一致、を判定する。**見張りが動くことを、実機の前に確かめる**

### rev3 の予言（測る前に書く）

| | 予言 |
|---|---|
| sim（SKEW 0） | 全部通過、診断は 0（frame_started だけ見える） |
| sim（SKEW 5） | FLAGS 0x20、`DIAG_TL` = ffffffff、事象 ≒ 2 回 / フレーム、A・B は通過 |
| ビルド | DSP 480・BRAM・CDC は rev2 と同じ。WNS は正（配置で ±0.2 動く） |
| 実機・起動 20 回の率 | rev2 と同程度（7/20 前後）。診断を足しても IP は同じ |
| **立つ起動** | **16 レーンとも**、unexpected と missing の両方。事象 ≒ 2 回 / フレーム。事象の `m_in` はその起動の中で一定 |
| **frame_started の `m_in`** | **立つ起動でも立たない起動でも同じ値で、以後も動かず、レーン間で揃う**（← 見立ての核心） |

- 外れ方の読み:
  - frame_started の `m_in` が立つ起動だけ違う → **枠そのものがずれている**。照合が通ったことと矛盾するので、照合の感度を疑う
  - 立つレーンが一部だけ → IP ごとの起動の競争。16 個が同じリセット・同じ入力なのにばらつく理由を探す
  - 事象が 1 回 / フレーム → unexpected か missing の片方だけ。検査の数えが「ずれ」ではなく「周期が違う」

### rev3 の sim（2026-09-25、SHIFT 7）

| | SKEW 0 | SKEW 5（陽性対照） |
|---|---|---|
| FLAGS | 00 | **20** |
| `DIAG_TL` | 0 | **ffffffff**（16 レーンとも両方） |
| `DIAG_EV` | 事象なし | missing が先、`m_in` = **507**（= 512 − 5。ずれの量がそのまま読める） |
| `DIAG_EVCNT` / FIN | 0 | 32 / 15、446 / 223、874 / 437（**2 回 / フレーム**） |
| `DIAG_FS` | 見た・`m_in` = 1 で一定・レーン間で揃う。回数 ≒ FIN | **同じ**（枠は変えていないので） |
| A（bit 単位）・B（numpy）・C（帳簿） | 通過 | **通過**（検査がずれてもデータは同じ） |

**予言どおり。**見張りが動くこと（陽性）と、見張りが勝手に立たないこと（陰性）の両方を、実機の前に確かめた。
実機で「立つ起動」がこの SKEW 5 と同じ形（16 レーン・2 回 / フレーム・frame_started は同じ `m_in`）になれば、見立てが確かめられる。
その場合、`DIAG_EV` の `m_in` から**ずれの量**が読める（missing が先なら 512 − ずれ）。

## rev4（2026-09-25）— 起動の競争を捕まえる

rev2 と rev3 の比較で、TLAST 事象の率は**ビット列（配置）で変わる起動の競争**と分かった。Overlay を読み直す起動は 1 回 15 秒かかり、

- **SRST（CTRL[10]）**: 16 個の IP の aresetn と、入力側・出力側・積分の数えを 32 クロックだけリセットする。FLAGS と診断も消える
- **D（SRST_D、0x70）**: リセットの解除から、入力の口（IP と入力側の数えが見る tvalid）を開けるまでのクロック数

- ハードのリセット（電源投入・Overlay）では口は開いたまま。**起動の振る舞いは rev3 と同じ**

  ビルド時刻は入れない（定数が変わると配置が組み替わり、作り直しが再現しなくなる）
- `--srst-trials N --srst-d … --srst-e …`: (D, E) の組ごとに N 回やり直し、事象の率・立ったレーン・最初の事象の位置・frame_started の位置を表にする
- sim に **t4** を足した: SRST（D 7 / E 3）の後の 1 フレームのダンプが、模型と bit 単位・numpy と一致する（起動のやり直しの後も正しく動く）

## rev5（2026-09-27）— 起動の見張り: 入力が途切れずに続くまで口を開けない

SRST のやり直しで起きないのは、入力の口を一度閉じてから開けるため。**ハードのリセット（Overlay）の後も同じことをする。**

- ハードのリセットの後、入力の口（`gate_d`）を閉じたまま、**`s_axis_tvalid` が STABLE_N = 16384 クロック（64 µs）途切れずに続いたら開ける**。
  途切れたら数え直す。IP の aresetn・設定の口は rev4 のまま（ハードのリセットで開く）
- **ST_GAPS（0x7C）**: 見張りの間に見た途切れの回数（bit 31 = 口が開いた）。**ST_CYC（0x80）**: 口が開くまでのクロック数。
  ハードのリセットでだけ数え直す（CLR・DCLR・SRST では消えない）
- SRST は見張りを打ち切り、rev4 の D / E の規則で開ける（SRST の振る舞いは rev4 と同じ）
- FLAGS[3]〜[6] は口の内側（`vin`）で見ているので、見張りの間の途切れでは立たない。途切れがあったことは ST_GAPS に残る

## rev6（2026-09-27）— 起動の途切れの仕組みを確かめ、元を断つ

rev5 の見張りは途切れを IP に届かせないが、**途切れがなぜ起きるか**は分かっていなかった。rev5 のビット列では途切れが 1 回も起きず、
見張りの効きも実機で確かめられていない。realtime を使い続けるなら、ここを理解して確実に手を打つ。

### 見立て: 3 : 4 のクロックの非同期 FIFO の起動

- gb_fifo の書き込み（clk_out1 = 341.33 MHz、**4 クロックに 1 語**）と読み出し（clk_out2 = 256 MHz、**3 クロックに 1 語**）は、
  同じ MMCM の VCO（1024 MHz）を 3 分周・4 分周したクロック。**語の周期はどちらも 12 VCO 周期（11.72 ns）で厳密に等しい**
- axis_data_fifo は空でなくなった瞬間に読み始める。起動の直後は残量 1 語・**余裕 0 クロック**のまま定常になる
- 書き込みポインタ（gray、6 bit）の各ビットは、配線の違いでそれぞれ別の時刻 A(b) に読み出し側の同期段に着く。
  語 k の到着は、その語で動くビット b(k) の A で決まる（gray なので 1 語に 1 ビットだけ動く）
- 捕まえる縁（256 MHz）に対する到着の位相は、gb_up が語をまとめ始める位相（4 通り、VCO 1 周期 = 0.977 ns 刻み）で起動ごとに変わる
- **bit 0 より遅いビットがその起動で 1 つ後の縁に入ると、そのビットが初めて動く語（語 2^b − 1）だけが 1 クロック遅れて見え、
  余裕 0 の読み出しが 1 回だけ空振りする**。その後は余裕が 1 クロックできるので、二度と起きない
- 起動のうち途切れる割合 P ≒ D / 0.977 ns（D = bit 0 より後に動くビットの A の最大 − A(0)。0〜1 に切る）。**D ≦ 0 なら決して起きない**

この見立ては、これまでの観測を全部説明する: 起動の直後だけ・1 起動に 1 回・ビット列（配線）で率が変わる（rev2 9/40・rev3 0/40・rev4 17/40・
rev5 0/40）・nonrealtime の proj010 でも同じ率で起きる（11/20）・定常では起きない。そして次の予言が出る:
**途切れは 1 起動に高々 1 回・長さ 1 クロック・位置は語 2^b − 1（RAW_FIRST ≒ 3 (2^b − 1) クロック）・K ≧ 2 で消える。**

### 模型（`make sim-gb`、sim/tb_gearbox.v）

VCO を 3 分周・4 分周したクロック、gray の各ビットの遅延、2 段の同期、FWFT の読み出し、gb_dn（1 語 → 3 拍）を写した模型で、
再起動の位相 12 通り（hold の長さ 3 × ADJ 4）を回した（gb_gate / gb_adc の RTL をそのまま使う）。

| 遅延の組 | K = 0 の途切れ | 途切れた語 | K = 4 |
|---|---|---|---|
| 6 ビットとも 300 ps | 0 / 12 | — | 0 / 12 |
| bit 2 だけ +800 ps | 5 / 12（どれも 1 回） | 語 3 | 0 / 12 |
| bit 2 だけ +1800 ps | 7 / 12（どれも 1 回） | 語 3 | 0 / 12 |
| **bit 0 だけ +1800 ps** | **0 / 12** | — | 0 / 12 |
| ばらばら（410〜1230 ps、bit 2 が最大） | 5 / 12（どれも 1 回） | 語 3 | 0 / 12 |

- 見立てどおり: 途切れは 1 起動に高々 1 回、位置は遅いビットが初めて動く語、bit 0 が一番遅ければ起きない、K = 4 で消える。
  どの場合も通し番号に欠け・重複はない（FIFO は語を落とさず、valid が 1 クロック落ちるだけ）
- 模型を作る途中で、gray を 32 bit の文脈で作ると 63 → 0 の折り返しで bit 5 が動かない誤りを踏んだ（6 bit の中間の線で直した）

## 結論・次にやること

**FFT IP を realtime・資源優先（res）にして、機能は proj010 と同じまま、DSP を 944 → 480（4ch で 88 % → 45 %）に、`-1` の余裕を 2 % → 7 % にした。**
最終の rev6 のビット列で判定 0・1・2・3 と realtime の危険（1 時間の `--record` で FLAGS 00）が通過。

- **DSP を減らしたのは乗算器（3 乗算）とバタフライ（LUT）の設定で、realtime ではない**（survey: throttle に依らず 50 → 21）。realtime はタイミングのため（nonrealtime の CE の大ファンアウトが消える）
- **realtime の代償は、起動の直後の入力の途切れを待たないこと。**途切れはデータの始まりの瞬間に、特定のビット列でだけ起きる（proj010・rev2・rev4 で 2〜5 割、rev3・rev5・rev6 では 0）。
  原因は未解明（gray の到着の差は棄却）。**守りを三重にした**: 起動の見張り（64 µs、実機の注入で効きを確認）・FLAGS（口が開いた後の途切れを 20/20 で捕まえる）・`--record` の自動のやり直し
- 4ch の資源: DSP 44.9 %・LUT ≦ 45.5 %・FF ≦ 42.2 %・BRAM 29.3 %。**DSP と LUT がほぼ同じ速さで埋まる**。最大 32 窓なら窓 1 つあたり DSP 73・LUT 7.2k
- 次（proj012）: この予算で窓の切り出しの方式（間引いてから小さい FFT か、粗い PFB の共有か）を選ぶ
- 持ち越し: 起動の途切れの原因 / FLAGS[3]（IP が入力を受けなかった）が起動のたびに立つ理由（データの枠は正しく、1 時間の記録に影響なし）

## 再現手順

```bash
make sim-all                          # Vivado 不要。SHIFT 7 / 4 / SKEW 5 / 起動の途切れ（見張りあり・なし）/ ギアボックスの模型の 6 本を同時に（`make` と並べてよい）
make sim-gb                           # ギアボックスの起動の途切れの模型だけ（数秒）
make gb-cdc [DCP=...]                 # 配置配線後の dcp で gb_fifo の gray の到着をビットごとに測る（ビルド不要）
make sim                              # 1 本だけ。SIM_SHIFT=4 で飽和の数え方、SIM_SKEW=5 で TLAST の診断の陽性対照
make survey                           # FFT IP 単体 × 8 通りの資源 → build-survey/survey.txt
make                                  # res（既定）: build/proj011.bit / .hwh
make FFT_OPT=perf                     # perf: build-perf/
make timing-check                     # res の -1: build-1-e/
make timing-check FFT_OPT=perf        # perf の -1: build-1-e-perf/
make prog                             # JTAG（OUTDIR=build-perf で perf を書く）
```
