## 目的

proj028 で記憶（チップ内の点数の上限）を検討したのに続き、**DSP 資源の節約**を検討する。
2G 系（2G-1・2G-2・2G-4）・Wide のレーン FFT（Xilinx xfft、複素）は、**実数の y を虚部 0 で入れている**（`g24_spec.v` の `{16'h0000, yp[14], yp}`）。
実のレーン 2 本を z = y_a + j·y_b として 1 個の IP に入れ、出口で
**2Y_a[k] = Z[k] + conj Z[−k]・2Y_b[k] = −j(Z[k] − conj Z[−k])**（加減算だけ）で分ければ、IP の数は半分になる。
これが RTL の前に、模型と見積もりで成り立つか（精度・溜めの大きさ・資源の差し引き）を判定し、成り立てば部品を作って OOC で確かめる。

まず 2G-4（proj027）で考える。いちばん混んでいる bit なので効きが大きい:

| 2G-4（proj027 build-PE） | 全体 | うちレーン FFT（4096 点・bit 反転順、1 個の実測 × 64） |
|---|---|---|
| DSP | 3,312（77.5 %、目安 75 % を越える） | 27 × 64 = **1,728** |
| LUT | 64.6 %（律速） | 3,250 × 64 = **208,000（デバイスの 48.9 %）** |
| FF | | 6,554 × 64 = 419,456 |
| BRAM | 842（78 %） | 7 × 64 = **448** |

（1 個の値は `proj027/build-PE/lane_fft_util.rpt`）

## M-1 2-for-1 の模型 — 予言（走らせる前に書く、2026-10-26）

組は p と p + 8（z_q = y_q + j·y_(q+8)、q = 0..7）。鎖（g24_chain）は今のまま、入口に 2Y を入れて cmul の SH を 18 → 19 にする（½ を捨てずに 1 bit 持つ。2G-4 は Y の最大 ≒ 2.0M で、2Y ≒ 4.0M も cmul の A 27 bit に入る）。
IP の値は今の模型と同じ rint（IP の中の段ごとの丸めは模型に無い。下の「自信が低い所」）。

- **a 式**（浮動小数点、16 レーン × 4096 点の乱数）: 分けた Y と 16 本の DFT の相対差 < 1e-12。陽性対照（共役なし）は > 1e-2
- **b 鎖の全体**（proj027 M-c と同じ入力: CW 1000 LSB @ ch 20000 ＋ 雑音 σ 100、フレーム 3・4）:
  - 今（16 レーン）の ε は proj027 M-c の 8.4e-6 を再現する
  - 2-for-1 の ε は**今の 0.85〜1.00 倍**: Y の丸めの誤差は、今は 1 成分あたり分散 1/12、2-for-1 は (e[k] + conj e[−k]) / 2 で 1/24 に減る。ε の大半は y の整数への丸め（proj027 M の外れの理由）なので、減るのはわずか
  - CW の差 < 0.01 dB、Z の最大は今と ±1 % 以内（2Y と SH 19 で目盛りが同じ）、2Y の最大 < 2^26
  - 陽性対照（相手を −k − 1 に取り違える）: ε > 1e-2（隣の行の値が混ざる）
- **c bit 反転順の出口の溜め**: k と −k は同じ「オクターブ」の区間 [2^j, 2^(j+1)) に鏡の位置で並ぶので、相手を待つ値の最大は**最後の区間の半分 = M/4 = 1,024 値 / IP**。
  （**この値は予言を書く前に手で計算して見た**ので、当たりとして数えない。模型の組み方の確かめ）。2G-4 の 1 コアで 8 IP × 1,024 × 56 bit = 459 kbit ≒ RAMB36 16
  - 判定はしないが出す: 組がそろう拍の並び（最長の連続）、「k と −k の 2 行ずつ・1 拍に 1 行」で鎖へ出すときの待ち行列の最大
- 自信が低い所: IP の中の段ごとの丸め（unscaled でも積を丸める、LESSONS）。実の入力と複素の入力で誤差の大きさが変わるかは、この模型では見えない。単体の sim を IP の行動模型ではなく実物の IP（xsim）で回すか、実機で床を比べる必要がある

## E-1 見積もり（2G-4 の 1 コア、M-1 の後に書いた。S-1 の OOC で確かめる予言）

浮く分（IP 8 個、1 個の実測 × 8）: **DSP −216・LUT −26,000・FF −52,400・BRAM −56**。

増える分（仮の値。どれも DSP は 0）:

| | (A) 鎖は今のまま | (B) 鎖を 16 出口に |
|---|---|---|
| 分け（8 IP × 加減算 4 個 × 29 bit ＋ 段のレジスタ） | LUT ≒ 1,000・FF ≒ 2,000 | 同じ |
| 待つ値（8 IP が同じ拍で動くので 1 本の 1,024 × 448 bit） | RAMB36 13 | 同じ |
| (A) 行の待ち行列（1,028 × 16 レーン × 2 × 28 bit） | RAMB36 25・LUT ≒ 500 | — |
| (B) 鎖の出口の均し（q を 1,024 拍 × 8 個 × 36 bit） | — | RAMB36 9・LUT ≒ 500。dft16 の残り 8 出口は J4 の加減算だけ（LUT ≒ 1,500） |
| 帳簿（番地・組の判定・見張り） | LUT ≒ 500 | LUT ≒ 1,000 |
| **差し引き / コア** | **DSP −216・LUT ≒ −24,000・BRAM −18** | **DSP −216・LUT ≒ −22,000・BRAM −34** |
| **2G-4（4 コア）** | DSP 3,312 → **2,448（57 %）**・LUT 64.6 → **≒ 42 %**・BRAM 842 → ≒ 770（71 %） | DSP **2,448（57 %）**・LUT **≒ 44 %**・BRAM ≒ 706（65 %） |

- 効きの大半は LUT: レーン FFT 64 個がデバイスの LUT の 48.9 % を持っていて、その半分が消える。2G-4 の律速（LUT 目安 65 %）と DSP の目安 75 % 越えが両方外れる見込み
- 外れるとしたら: 分けの段と帳簿の LUT（仮の値）・IP の BRAM が複素の入力で増えること（入力は今も複素の形で入れているので、増えない見込み）・(B) の積分器の書き込みの並び
- **IP の出口の位相がコアの間で揃う保証が無い**（LESSONS、proj023 4b）ので、待つ値の溜めの番地は IP の出口の k1（tuser）で引く。T で引かない

## 決めること

  - (B) 鎖を 16 出口にし、そろった拍だけ動かす（行は半分。積分器は 1 拍に 16 個を受ける形か、出口に溜め）

## P-1 分けの部品 `s2_sep`（`src/s2_sep.v`、`make sim-sep`）— 予言（走らせる前に書く、2026-10-26）

形（(B) 用）: 入口は IP 8 個の出口（同じ拍で動く。Z 28 bit × 2 × 8、k1 は IP 0 の tuser）、出口は**組がそろった拍だけ**、行 r ∈ [0, 2048] の 16 レーンの 2Y（29 bit）。
- 位置 n = bitrev(k1)、h = 2^⌊log2 n⌋。**相手は区間 [h, 2h) の鏡の位置 3h − 1 − n**（4096 点の全部で確かめた）。
  前半（n < 1.5h）は待つ値の溜め（1,024 × 448 bit、番地 n − h）に書き、後半は番地 2h − 1 − n を読む。番地は IP の k1 から決める（T では引かない）
- 書きと読みの番地を同じ段で取り込むので、相手との距離が 1 拍でも、読みは書きの 1 拍以上後になる（迂回の道は要らない）
- n = 0・1（k 0・2048）は自己共役で、相手は自分
- 出口の行は r = min(k, 4096 − k)。k > 2048 の拍では、溜めから読んだ値が Z[r]、今の値が Z[−r]
- 見張り（粘着）: k1 が bit 反転順の次でない（pos_mis）
- 遅れ: 入口から 4 拍（入口の受け 1・番地 1・溜めの読み 2（出口のレジスタつき））＋ 加減算 1

sim（入力は M-1b と同じ CW ＋ 雑音の PFB の出口、3 フレームを途切れなく。模型 `model/s2_model.py` の lane_fft_s2 と bit 単位で照らす）:

| 変種 | 中身 | 予言 |
|---|---|---|
| normal | 3 フレーム続けて | 出口 3 × 2,049 行が順番・値とも一致。行 0〜2048 がフレームごとに 1 回ずつ。pos_mis 0 |
| gap | valid にランダムな空き（3 拍に 1 回ほど） | normal と同じ（溜めの番地は拍の数ではなく n で決まる） |
| 陽性対照 addr | 読みの番地を 1 ずらす | 落ちる（自己共役と、区間 1 の組だけが合う） |
| 陽性対照 swap | k > 2048 で入れ替えない | 落ちる（行の数は合い、k > 2048 で組がそろう行の値だけが違う） |
| 陽性対照 pos | tb が 1 フレーム目の途中で k1 を 1 つ飛ばす | pos_mis が立つ |

**結果（`make sim-sep`、2026-10-26、5 本を並べて 1.4 秒）: 全部通過・陽性対照 3 本は落ちた**（iverilog `-Wall` の警告 0）

## S-1 `s2_sep` の OOC（`make ooc-sep`、`-1`・256 MHz）— 予言（走らせる前に書く、2026-10-26）

IP は今の lane_fft_g24 と同じ設定（入力は今も複素の形で入れている）なので、IP 8 個の資源は 1 個の実測（DSP 27・LUT 3,250・FF 6,554・BRAM 7）× 8 と読み、合成するのは分けの部品だけにする。

- **DSP 0**
- **BRAM 13〜14**（1,024 × 448 bit: 1K × 36 で 13、512 × 72 で 14。m_q2 は BRAM の出口のレジスタに吸われる）
- **LUT 1,800〜2,800**（加減算 8 × 4 × 29 bit ≒ 930・入れ替えと自己共役の選択 ≒ 900・位置と番地・見張り ≒ 200）。E-1 の仮の値（分け 1,000 ＋ 帳簿 500）より多い
- **FF 2,000〜3,500**（入口から s3 までの 448 bit × 4 段・出口 928。d2・d3 は SRL に寄るかもしれない）
- 合成の WNS > +0.5 ns。Synth 8-3848 0・CRITICAL WARNING 0

**結果（`make ooc-sep`、2026-10-26 17:2x、59 秒）: DSP 0・LUT 992・FF 2,809・BRAM 12.5・合成の WNS +1.687 ns**（Synth 8-3848 0・CRITICAL WARNING 0）

| DSP | 0 | 0 | 当たり |
| BRAM | **12.5**（RAMB36 12 ＋ RAMB18 1） | 13〜14 | 外れ（少ない側）: 448 bit を 36 × 12 ＋ 18 × 1 = 450 に分けた。1K × 36 を 13 個と数えたのは粗い |

## (B) の残りの形（2026-10-26、P-1・S-1 の後に書いた）

- **鎖 `s2_chain`**: そろった行 r ∈ [0, 2048] だけを流す（1 拍に 1 行まで）。2Y（29 bit）を **27 bit に飽和**（cmul の A 口。AW ≦ 27 で積 1 つが DSP 1 個）→ V = cmul(2Y, w[p][r], SH 19) → **dft16f（16 出口。proj027 の src/common/dft16f.v、自明な係数は cmul を通さないので dft16 より DSP −32）** → q = sat18(Z >>> SHIFT)。
  - k2 0..7 は行 r の銀行 k2、k2 8..15 は共役で**行 4096 − r の銀行 15 − k2**。r = 0・2048 は k2 0..7 だけ
  - 2Y の飽和: 実数の y（15 bit）なら |Y| ≦ 16383 × 4096 < 2^26 で、2Y は 2^27 まで届きうる。届くのは y が全振幅に近い直流のような入力だけ（全振幅の CW でも |Y| ≒ 16383 × 2048 < 2^25）。**今の 2G-4 より余裕が 1 bit 少ない**。飽和の数を見張る
- **均し `s2_q`**: 鎖の出口の q（行 r の 8 銀行 ＋ 行 4096 − r の 8 銀行）を、行の書き込み 1 本か 2 本として待ち行列に積み、1 拍に 1 本出す → 電力（8 個 / 拍、DSP は今と同じ 16）→ 積分器（g24_acc は今のまま、1 拍に 1 行の RMW）。q を積むので電力の DSP は増えない
- 行の順は bit 反転順ではなくなる。積分器は番地 = 行で受けるので並びには依らないが、**g24_spec の出口の k1 の見張り（flags[6]）と、フレームの帳簿（t_act・t_first・t_plane）は待ち行列の遅れの分だけずれる**。帳簿はタグとして待ち行列に一緒に積む（コアに組むときに）

## M-2 (B) の鎖と均しの模型（`make model`）— 予言（走らせる前に書く、2026-10-26）

- **a 鎖の全体**（M-1b と同じ入力・フレーム 3・4）:
  - 32,768 ch がフレームごとに 1 回ずつ書かれる
  - ε は M-1b の 2-for-1（8.39e-6）の 0.9〜1.1 倍。行 4096 − r の ch は、今は w[p][4096 − r] で、(B) では行 r の w[p][r] の共役で作る。表の量子化の誤差は同じ大きさ
  - CW の差 < 0.01 dB、2Y の飽和 0
  - 今の鎖の Z との差は最大 4 LSB 以下（ひねり係数の量子化と丸めの違いだけ）
  - 陽性対照（k2 8..15 を銀行 k2 − 8 に）: ε > 1e-2
- **b 待ち行列**: 深さの最大は 1,026〜1,028 本（(A) の 1,028 は自己共役の行も 2 本と数えていた。(B) は 1 本）。積んでから出るまでの最大も ≒ 1,027 拍。
  同じ行の書き込みの間隔の最小は **≧ 3,000 拍**（1 フレーム 4,096 拍から待ち行列の遅れの揺れ ≒ 1,027 を引いた程度）で、積分器の RMW（4 段）に十分長い

**結果（`make model`、2026-10-26、0.9 秒）: M-1・M-2 とも全部通過**

| | 結果 | 予言 | |
|---|---|---|---|
| a 1 回ずつ | 32,768 ch がフレームごとに 1 回ずつ | 同じ | 当たり |
| a ε | **8.39e-6**（M-1b と同じ）・CW −0.0000 dB・2Y の飽和 0 | 0.9〜1.1 倍 | 当たり |
| a 今の鎖の Z との差 | **最大 63.6 LSB** | ≦ 4 LSB | **外れ**: ひねり係数の量子化の誤差は信号に比例する。CW の ch（Z ≒ 8.15M）で 16 レーンぶん足されて 64 LSB 程度（相対 8e-6）。ε が同じなので精度の差ではない |
| a 陽性対照（銀行 k2 − 8） | ε 50・CW −76.6 dB | > 1e-2 | 落ちた |
| b 待ち行列（行の単位）の最大 | **1,025 本**（取り出した後は 1,024）・遅れの最大 1,024 拍 | 1,026〜1,028・≒ 1,027 | 外れ（わずかに少ない） |
| b 同じ行の間隔の最小 | **4,096 拍**（ちょうど 1 フレーム） | ≧ 3,000 | 当たり（待ち行列は先入れ先出しで、並びはフレームごとに同じなので、ずれない） |

溜めの形（M-2b の後に数えた）:
- 行の単位で 1,024 深さにすると、1 拍に 2 本書く口が要る。**組（行 1 本か 2 本）を 1 項目**にして 1 拍に 1 回書くと、記憶に残る項目の最大は **513**（2 本目の行を出している拍は取り出さないので、取り出しを先にしても 513）
- → **512 深さ × 576 bit（q 16 銀行、RAMB36 8 個）＋ 出口の先読みのレジスタ 3 段**で入る（行 r と組の印は LUTRAM）。余裕はほとんど無いので、**あふれの見張り（粘着）**を置く
- **出口は 1 フレーム 4,096 拍で 4,096 行を出す。余裕は 0**: 積まれているのに 1 拍でも出さない拍があると、遅れが溜まり続ける。先読みは途切れなく出す形にする（sim で見張る: 待ち行列の深さの最大がフレームを重ねても増えない）
- 1 コアの BRAM の増分は 12.5（s2_sep）＋ 8（s2_q）= 20.5。浮く 56 と差し引き **−35.5 / コア**
