# proj033 — 2G-1-Fast にレーン FFT の 2-for-1 を入れる（proj030 の形を 1 ADC × 131072 ch に）

## 目的

2G-1-Fast（proj024、16 レーン × 16384 点の IP 16 個、実数の y を虚部 0 で入れている）に proj030 の 2-for-1（実のレーン 2 本を複素の IP 1 個に、出口で Z[k] ± conj Z[−k]）を入れ、
**精度・機能を変えずに** DSP・LUT・BRAM・VCCINT がどれだけ減るか、タイミングの余裕（今は Performance_Explore で WNS +0.0018 ns）が広がるかを確かめる。
点数は増やさない（壁は積分器の URAM と出口の量。ADR 0022）。2G の 3 本のコアを 2G-4（proj031）と同じ形（s2_sep・s2_chain・s2_q）にそろえることも狙い。

PFB の係数の URAM 共有（proj031）は入れない: コアが 1 つで共有の得が無く、係数は 2G-4 の 4 倍（対称性でも URAM 32）で、URAM が壁の 2G-1 には逆効果。

## 手順（案）

各手順は 予言 → 結果 → 当たり・外れ → INDEX → コミット。

- **M-1 模型**: proj030 の M-1・M-2 を N 16384・コア 1 個に。鎖の全体の ε が proj024 と同じ（M-7 の Y の 2 bit の丸め・SH 18 との兼ね合いを含めて語長を決め直す）
- **E-1 見積もり**: 下の予言を、proj024 build-PE の階層の報告と s2_* の OOC（proj030 S-1・S-2）を N に合わせて置き換える
- **P-1〜P-3 部品**: s2_sep（相手を待つ溜めは N/4 = 4096 / IP）・s2_chain・s2_q を 16384 点に。単体の sim は模型と bit 単位、陽性対照つき
- **P-4 コアに組む**: proj024-m0 から写した g21 のコアに。2b・2c・D_eff の sim を回し直す（2-for-1 の出口の遅れで D_eff が変わる）
- **B-1 全体の .bit（2-for-1 だけ）**: 既定と Performance_Explore を並べる
- **B-2 記憶のカスケードに段を足す（rev 2、効果を分けて読むため B-1 の後に別のビルドで）**: proj024 の負の経路の 2 つの塊（積分器の URAM 6 段のカスケード、合成の警告 Synth 8-6013「UltraRAM が under-pipelined」・PFB の履歴の RAMB36 7 段のカスケード）に 1 段ずつ
- **R 実機**: proj030 の R-1〜R-6 の型（立ち上げ・床を proj024 と比べる・30 分の取りこぼし・ch の並び・F-2・CW、共役の側を含む）。VCCINT は proj024 と交互に並べて測る
