# proj033 — 2G-1-Fast にレーン FFT の 2-for-1 を入れる（proj030 の形を 1 ADC × 131072 ch に）

日付: 2026-10-28（起こし）
土台: タグ **proj024-m0**（2G-1-Fast の .bit、build-PE、sha256 fdb04d80…）。2-for-1 の部品・模型は **proj030**（commit 1a3e733 の時点の `proj030/`）から写す予定。仕様は YATSUGATAKE の 55f38b2 ＋ PR #51（2G-1 → 2G-1-Fast、ADR 0022）
状態: **進行中**（M-1・M-2 模型は全部通過、鎖の入口は (i) 2Y を 3 bit 丸めて SH 18。次は E-1 見積もりと P-1 部品）

着手の前に [`../LESSONS.md`](../LESSONS.md) を全部読む（知見の全部は [`../docs/lessons_all.md`](../docs/lessons_all.md)）。

## 目的

2G-1-Fast（proj024、16 レーン × 16384 点の IP 16 個、実数の y を虚部 0 で入れている）に proj030 の 2-for-1（実のレーン 2 本を複素の IP 1 個に、出口で Z[k] ± conj Z[−k]）を入れ、
**精度・機能を変えずに** DSP・LUT・BRAM・VCCINT がどれだけ減るか、タイミングの余裕（今は Performance_Explore で WNS +0.0018 ns）が広がるかを確かめる。
点数は増やさない（壁は積分器の URAM と出口の量。ADR 0022）。2G の 3 本のコアを 2G-4（proj031）と同じ形（s2_sep・s2_chain・s2_q）にそろえることも狙い。

PFB の係数の URAM 共有（proj031）は入れない: コアが 1 つで共有の得が無く、係数は 2G-4 の 4 倍（対称性でも URAM 32）で、URAM が壁の 2G-1 には逆効果。

## 手順（案）

各手順は 予言 → 結果 → 当たり・外れ → INDEX → コミット。

- **M-1 模型**: proj030 の M-1・M-2 を N 16384・コア 1 個に。鎖の全体の ε が proj024 と同じ（M-7 の Y の 2 bit の丸め・SH 18 との兼ね合いを含めて語長を決め直す）
- **E-1 見積もり**: 下の予言を、proj024 build-PE の階層の報告と s2_* の OOC（proj030 S-1・S-2）を N に合わせて置き換える
- **P-1〜P-3 部品**: s2_sep（相手を待つ溜めは N/4 = 4096 / IP）・s2_chain・s2_q を 16384 点に。単体の sim は模型と bit 単位、陽性対照つき
- **P-4 コアに組む**: proj024-m0 から写した g21 のコアに。2b・2c・D_eff の sim を回し直す（2-for-1 の出口の遅れで D_eff が変わる）
- **B-1 全体の .bit（2-for-1 だけ）**: 既定と Performance_Explore を並べる
- **B-2 記憶のカスケードに段を足す（rev 2、効果を分けて読むため B-1 の後に別のビルドで）**: proj024 の負の経路の 2 つの塊（積分器の URAM 6 段のカスケード、合成の警告 Synth 8-6013「UltraRAM が under-pipelined」・PFB の履歴の RAMB36 7 段のカスケード）に 1 段ずつ
- **R 実機**: proj030 の R-1〜R-6 の型（立ち上げ・床を proj024 と比べる・30 分の取りこぼし・ch の並び・F-2・CW、共役の側を含む）。VCCINT は proj024 と交互に並べて測る

## M-1・M-2 模型（`make model`、`model/s2_model.py`）— 予言（走らせる前に書く、2026-10-28）

写したもの（`git show`、そのまま）: タグ proj024-m0 の `model/g2_model.py`・`model/g21_fixed.py`（2G-1 の鎖の定義）。
`model/s2_model.py` は proj030（1a3e733）のものを N 262144・M 16384 に直した（組は p と p + 8、IP 8 個）。

2G-1 は 2G-4 と語長が違うので、鎖の入口を決め直す。今の g21_chain は Y（29 bit、|Y| ≦ 16383 × 16384 < 2^28）を **2 bit 丸めて 27 bit → cmul SH 18**（proj024 M-7）。2-for-1 の 2Y は 30 bit。候補:

- **(i) 2Y を 3 bit 丸める → 27 bit → SH 18**: 目盛りは今と同じ（Y/4 と同じ刻み）。|2Y| < 2^29 なので **27 bit に必ず入り、飽和は起きない**（今の余裕のまま）
- **(ii) 2Y を 2 bit 丸める → 27 bit に飽和 → SH 19**: proj030（2G-4）と同じ形。刻みが今の半分。全振幅に近い直流のような入力で飽和しうる（余裕が今より 1 bit 少ない）

IP の出口 Z は複素の入力で |Z_re| ≦ √2 × 16383 × 16384 < 2^29 なので **30 bit**（今の `fft_out_w` 30 のまま入る）。2Y は 31 bit。

- **M-1a 式**（浮動小数点、16 レーン × 16384 点の乱数）: 相対差 < 1e-12。陽性対照（共役なし）は > 1e-2
- **M-1b 鎖の全体**（proj024 M-8c と同じ入力: CW 1000 LSB @ ch 40000 ＋ 雑音 σ 100、フレーム 3・4、浮動小数点の鎖と比べる）:
  - 今（16 レーン）の ε は proj024 M-8c の **8.7e-6 を再現**する
  - (i)・(ii) とも ε は**今の 0.95〜1.00 倍**。ε の大半は y の整数への丸めと V の丸め（proj024 M-7 の見積もりで Y の 2 bit の丸めは丸めの雑音の 4 % ほど）なので、IP の rint の誤差が半分になる分も、(ii) の刻みが半分になる分もほとんど効かない。**(i) と (ii) の ε の差は 2 % 未満**
  - CW の差 < 0.01 dB、Z の最大は今と ±1 % 以内、(i) の 2Y の飽和 0・(ii) もこの入力では 0
  - 陽性対照（相手を −k − 1 に取り違える）: ε > 1e-2
  - **決め方（測る前に決める）**: (i) と (ii) の ε の差が 2 % 未満なら、**飽和の起きない (i)** を選ぶ。(ii) が 2 % を越えて良いときだけ (ii) を考える
- **M-1c bit 反転順の出口で相手を待つ値**: 最大 **M/4 = 4,096 値 / IP**（proj030 の式。手で出した値なので当たりに数えない）。溜めは 4,096 × 480 bit（Z 30 bit × 2 × 8）= 1.97 Mbit ≒ **RAMB36 54**
- **M-2a (B) の鎖の全体**（選んだ形で）: 131,072 ch がフレームごとに 1 回ずつ、ε は M-1b と同じ（0.9〜1.1 倍）、CW < 0.01 dB、2Y の飽和 0。陽性対照（k2 8..15 を銀行 k2 − 8 に）は ε > 1e-2
- **M-2b 均しの待ち行列**: 2G-4 の数（行の単位の最大 1,025・組の単位 513 = M/8 + 1）が M に比例するとして、**行 4,097 本・組 2,049 項目**、同じ行の間隔の最小 16,384 拍（1 フレーム）。
  2G-4 の RTL は組の記憶の山が模型 + 2 − 先読み 6 だったので、記憶 2,048 深さで余裕 ≒ 3（2G-4 と同じ）。**s2_q は 2,048 × 576 bit ≒ RAMB36 32**
- これで E-0 の BRAM を見直すと: IP −172、s2_sep ＋54、s2_q ＋32 → 673 → **≒ 587**（E-0 の 560〜585 の上の端を少し越える。E-0 は s2_sep の溜めを 448 bit（Z 28 bit）で数えていた）

**結果（`make model`、2026-10-28、6 秒）: M-1・M-2 とも全部通過。鎖の入口は (i)**（1 回目は M-2a・M-2b が不合格。どちらも照合の道具の誤りで、模型の定義は直していない。下に経緯）

| | 結果 | 予言 | |
|---|---|---|---|
| M-1a 式 | 相対差 3.9e-16・陽性対照 1.32 | < 1e-12・> 1e-2 | 当たり |
| M-1b 今（16 レーン） | **ε 8.67e-6**・CW −0.0000 dB・y の飽和 0 | 8.7e-6 を再現 | 当たり |

- **(i) を選んだ**: 精度は (ii) と 0.22 % しか違わず、飽和が構造的に起きない（今の g21_chain と同じ余裕）。g21_chain の `(Y + 2) >>> 2` が `(2Y + 4) >>> 3` に、cmul の SH は 18 のまま。2Y の飽和の見張りは要らない（(ii) なら要った）
- **s2_q の記憶**: proj030 の RTL は組の記憶の山が模型（取り出しの後）＋ 2 − 先読み 6 = 509 だった。同じ形なら 2,049 + 2 − 6 = **2,045 ≦ 2,048（余裕 3、2G-4 と同じ）**。記憶は 2,048 × 576 bit ≒ RAMB36 32。余裕が同じ 3 なので、あふれの見張り（粘着）と cmax の判定は proj030 のまま持ち込む
- **鏡の側の ch の電力は、今の鎖と切り捨ての向きが違う**: (B) は行 M − r の ch を行 r の k2 8..15 の共役で作り、q = Z >>> SHIFT は共役する前の値で取る。今の鎖は行 M − r を直に作るので、虚部の切り捨てが 1 LSB 違う ch がある（proj030 の 2G-4 でも同じ。精度の差ではなく、sim の正解は `power_s2` の定義で取る）

1 回目の不合格（**結果を見た後に照合を直した**ので、ここに残す）:
- M-2a の「`power_s2` の並び」: 照合が鏡の側の ch を**共役した後の虚部**で `>> 7` していた。`power_s2`（RTL の定義、proj030 で RTL と bit 単位）は共役する前の値で切り捨てる。切り捨ては符号で非対称なので 1 LSB ずれた。照合を直した（`power_s2` は写したまま）
- M-2b の本数: 「出た本数 = 6 × M」で判定していたが、6 フレームの終わりに待ち行列の遅れ（4,096 本）が残る。「出た ＋ 残り = 6 × M」に直した

## P-1 分けの部品 `s2_sep`（`src/s2_sep.v`、`make sim-sep`）— 予言（走らせる前に書く、2026-10-28）

| 変種 | 中身 | 予言 |

| normal | 3 フレーム続けて | 出口 3 × 8,193 = **24,579 行**が順番・値とも一致。行 0〜8192 がフレームごとに 1 回ずつ。pos_mis 0 |
