# proj023 — SAM45-Wide の RTL（PFB T = 4 ＋ 16 レーンの全帯域 FFT 32768 点 ＋ ch の束ね 1 / 2 / 4 ＋ SLICE、インターフェース v2 の上で）

日付: 2026-10-14（起こし）
状態: 進行中（手順 0・1 済み、次は手順 2）

## 目的

**SAM45-Wide（[BITS.md](../BITS.md) の 1 本目の行、BIT_KIND 1）の bit を作る。**
proj022 で模型と資源の見積もりまで設計したものを RTL にし、proj021 で確定したインターフェース v2（流れとコア・レコードのリング・specd）の上に載せる。

- 4 ADC × 1 コア。コアごとに全帯域の FFT（PFB T = 4 → 16 レーン × レーン FFT 2048 点・**固定長** → ひねり係数 → 16 点 DFT）を 1 本。**FFT はどのモードでも 32768 点**（125 kHz）
- **モードは電力の後の ch の束ね（ビニング）B で作る**（D-7）: 全帯域 2048 MHz = B 4（500 kHz）、1 GHz = B 2（250 kHz）、512 MHz = B 1（125 kHz）
- 流れは SLICE × 2（s = 0, 1）＋ RAW（s = 2）。各 SLICE は束ねた ch の連続した 4096 ch。全帯域は s = 0 が全部（流れ 1 は空）、1 GHz・512 MHz は 2 本（INTERFACE.md 2.1・2.5）
- モードは ADC ごとに独立（D-6）。dt = 40.96 ms（PL のダンプは 10.24 ms、specd で束ねる）
- **`-1` で閉じること**（proj022 の見積もりは LUT 70.1 % が律速。D-7 で ≒ 59 % の見込み）

土台: study-rfsoc のタグ **`proj021-m0`**（proj021 の最終形、SAM45-Fine BIT_REV 3）の `proj021/` の追跡ファイル。proj022 の `model/wide_model.py`（sim の golden の元）と `tools/estimate.py` を足した。

経緯: 2026-10-14 の相談（proj022 を閉じ、proj021 と並行して起こした）。設計の出発点は [proj022 の結論](../proj022/README.md#結論次にやること) と「RTL の proj への申し送り」。
同じ日の相談で、**レーン FFT の実行時の長さ切り替え（proj014 の決定）をやめ、32768 点の固定長 ＋ ch の束ねに替えた**（D-7）。

### M-7 束ねたときの ch の応答（`cd model && python3 bin_resp.py`、2026-10-14）

量子化した 18 bit の係数（`wide_model.py` と同じ原型、32768 点・T = 4）で、細かい ch の電力を B 個束ねた ch の応答。物差しは束ねた ch の幅。

| | 中心のずれ | 半 ch | 中心 ±0.25 ch の凹凸 | ≧ 1 ch | ≧ 1.5 ch | ≧ 3 ch | ENBW |
|---|---|---|---|---|---|---|---|
| proj020 の窓（物差し） | 0 | −3.00 dB | — | −53.7 | −58.0 | −64.5 | 1.010 |
| B = 1（512 MHz、125 kHz） | 0 | −3.00 dB | 0.13 dB | −53.7 | −58.0 | −64.6 | 1.010 |
| B = 2（1 GHz、250 kHz） | 0.5 細かい ch（62.5 kHz） | −3.01 dB | 0.08 dB | −57.0 | −61.2 | −67.7 | 1.008 |
| B = 4（全帯域、500 kHz） | 1.5 細かい ch（187.5 kHz） | −3.01 dB | 0.08 dB | −60.0 | −64.3 | −70.6 | 1.008 |

- B = 1 は proj020 の窓の値と小数 1 桁まで同じ（模型の確かめ）。束ねると ch の中が平らになり、隣より外の漏れが 3〜6 dB 下がる。端（±0.5 ch）は −3 dB のまま、ENBW もほぼ 1
- 中心のずれは束ねた ch の単位で (B − 1)/(2B): B 2 で 1/4 ch、B 4 で 3/8 ch

### 見積もり（proj022 の E-1・S-1 から引き直し、2026-10-14）

案 A（係数 URAM・4 ADC で 1 組 / ひねり係数 BRAM・1 組 / 履歴 URAM / 積分器 切り出しだけ・BRAM）。レーン FFT は S-1 の入力 15 bit の行（長さ切り替えあり）から、proj014 の survey の固定長との差（入力 14 bit で LUT −713・FF −1,052、DSP・BRAM 同じ）を引いた**見込み**:

| | D-6（2 組 × 2 ポート、長さ切り替え） | **D-7（固定長 ＋ 束ね、1 組）** |
|---|---|---|
| DSP | 2,656（62 %） | 2,656（62 %） |
| BRAM | 750（69 %） | **720（67 %）** |
| URAM | 72（90 %） | **56（70 %）** |
| LUT | 298k（70.1 %） | **≒ 252k（≒ 59 %）** |
| FF | 556k（65 %） | ≒ 489k（≒ 58 %） |

- PFB の係数は 1 つの長さ（2048 行 × 4 タップ = 72 bit）になったが、URAM は 1 個 / レーンのまま（深さ 4096 の半分）。BRAM に置く案（対称で 2 / レーン、計 32）にすれば URAM 40（50 %）・BRAM 752（70 %）も取れる
- 束ねの加算（銀行 8 本 × 39 bit × 4 ADC）と切り出しの番地は数千 LUT で、上の見込みの粗さの中
- **固定長・入力 15 bit の FFT IP は survey していない**。手順 3 の最初のビルドで資源を実測する（予言: LUT ≒ 3,190 / 個、DSP 27・BRAM 8 は長さ切り替えありと同じ）

手順 2（RTL と単体の sim）の予言（2026-10-14、書く前。D-7 の後に書き直した）:
- **wide_pfb**: `wide_model.py` の PFB の整数模型と bit 単位で一致する（proj020 の pfb_core が win_fixed.py と bit 単位で一致した型）。最初の 3 フレーム（起動の直後、履歴が埋まる前）は模型と同じ「0 の履歴」で一致する
- **束ね**: 細かい ch c = k1 + 2048·k2 の続く B 個は、同じ銀行 k2 の続く B クロックに出る。区切りは k1 ≡ 0（mod B）で、銀行をまたがない（2048 は B で割り切れる）。積分の手前で束ねるので、積分器の深さ・番地は B に依らない
- **フレームの頭**: 起動から最初のフレームの頭までの位相（T mod 2048）は、起動の時刻・ADC・SRST / GRST の回に依らず K_F に一致する。r = DUMP_T − m·BASE は 1 つの定数（PFB の重心のずれ 1.5·L = 12 µs は 5.2 の D_eff に入れる）
- **一番危ないところ**: 4 ADC で 1 組の係数・ひねり係数を、口が開いた ADC から順に使い始めるときの最初のフレーム。共通の番地は T だけで決まり、コアごとの起動に依らないので、**後から起動した ADC も最初のフレームから係数が合う**はず。sim で 4 ADC の起動をずらし（数百ビート）、4 本とも模型と bit 単位で比べる（陽性対照: 1 つのコアの口を格子に寄せずに開ける）

### 手順 2c-2: wide_spec（`make sim-wsp`、2026-10-14。作業用のクラウドの環境で書きながら回し、**同じ日にVivado サーバで回し直して同じ結果**）

**作り**:

- **RUN**: F0 = (⌊fa / 2^GF⌋ + 2)·2^GF（本番 GF = 8 = 2.048 ms。sim は 2 で待ちを縮める）
- **積分器（wide_acc）**: 8 記憶の銀行 × 2 面 × 1024 × 64 bit。流れ s の ch i = a + Cb·q（Cb = 2048 / B）を B 1: 銀行 {s, q, a[10]}・B 2: {s, q}・B 4: q に置く（proj022 M-5 を束ねに広げた）。どの束でも 1 記憶の銀行に 1 書き込み。書き込みの数と窓に入った ch の数を毎クロック比べる見張り（wr_coll → flags[7]）
- **帳簿**: 流れごとに spec_core の型（予約 → F0 で開始 → N_ACC フレームでダンプ → 面はダンプの偶奇）。ダンプの値は最後の束のクロックで押さえ、書き終えた 5 クロック後に commit（B 1 では次のフレームの頭が 1 クロック後に来て cur_* が変わるので）
- **異常フラグ**: 係数・ひねり係数の番地の見張り・口を開けた後の途切れ・IP の 16 レーンの不揃い・TLAST の事象・IP の口・k1 の飛び・書き込みの衝突
