# proj026 — 1PPS・10 MHz の入口に LPF（Mini-Circuits BLP-10.7+）: 800 MHz 帯の混信の効きと時刻の較正

日付: 2026-10-21
状態: 進行中（時刻の較正は済み。混信の効きは SG の方法で後日）

着手の前に [`../LESSONS.md`](../LESSONS.md) を全部読む（知見の全部は [`../docs/lessons_all.md`](../docs/lessons_all.md)）。

## 目的

proj013 で、携帯電話の 800 MHz 帯の上り（ゾーン 1 の 815〜845 MHz、IF では 3251〜3281 MHz に出る）の**主な入口は 1PPS のケーブル**
（ボード単体の ≒ 7 倍）と分かった。対策として 1PPS と 10 MHz の入口の直前に LPF を入れ、**45m の本番でも常設する**（2026-10-21、西村さん）。
この proj で確かめること:

1. LPF で 800 MHz 帯の混信がどれだけ減るか（proj013 の携帯電話の方法で、LPF なし / 1PPS だけ / 両方）。proj013 の宿題 2 つ（10 MHz のケーブル・LPF の効き）を片づける
2. LPF で時刻の較正 M（timebase.CAL の adc_to_core_ns = adc_to_core − pps_det）がどれだけ動くか（F-2 を LPF なし / ありで、同じ日・同じ配線で）
3. LPF ありで基準（10 MHz）がロックし、1PPS の取り込みが正しいこと（F-0）

RTL は変えない。bit は YATSUGATAKE M5b の SAM45-Fine（BIT_KIND 2・BIT_REV 3、ボードの `~/sam45-fine-m5b/`、`.bit` `ed6bcf78…`・usr 8eba3480）と、それに載せる `sw/pynq/`。

## 構成（2026-10-21）

- **LPF**: Mini-Circuits BLP-10.7+（DC〜11 MHz）× 2。**個体（シリアル）を記録する**（CAL に LPF の個体差が入る）: シリアル番号は無い（2026-10-21 に西村さんが確かめた）。個体は区別できないので、45m でも今日の 2 本をそのまま使い、入れ替えたら F-2 を測り直す
  - 公表値（S パラメータ）: 挿入損失 10 MHz 0.65 dB・群遅延 1〜3 MHz ≒ 59 ns・10 MHz 75 ns・14 MHz 126 ns（山）、減衰 20 MHz 31 dB・30〜200 MHz ≒ 70 dB。**800 MHz の値は無い**
  - 位置: ボードの PPS Clk と 10 MHz の入力のコネクタの直前（配線 P では**分配器の後、PPS Clk の枝だけ**。分配器の手前に入れると ADC の枝も同じだけ遅れ、運用と違う M が出る）
- **ADC 側（今の配線、2026-10-21 に分配器を交換）**:
  ノイズソース → 2 分配器 A ← SG／2 分配器 A → PATT → BPF 2.1〜3.9 GHz（総合電子 SC15FV-3000/1800-O/O）→ 2 分配器 B／
  2 分配器 B → ATT 20 dB → パワーメーター／2 分配器 B → ATT 3 dB → 4 分配器 → ADC_A〜D。
  2 分配器: Mini-Circuits ZFRSC-42-S+、4 分配器: ZFRSC-4-842-S+
- **携帯電話の試験の入力**: ノイズソースの電源を切る・SG の出力 OFF（ADC 自身の床に対して混信を見る。proj013 の −47 dBFS より敏感）
- **携帯電話**: 同じ電話を毎回同じ場所に置く（ボードから ≒ 50 cm、毎回同じ場所）。「on」は通話の間ずっと、「off」は通話なし
- 記録: `runs/`（.s45 は大きいので git に入れない）

## 量（`tools/phone_rfi.py`）

4 ADC とも窓 0 を IF 3200 MHz・256 MHz（3072〜3328 MHz）に置き、ダンプ（40.96 ms）ごとに
**excess = 帯（3251〜3281 MHz）の平均 / 両隣 2 帯ずつ（3219〜3251・3281〜3313 MHz）の平均 − 1**（proj013 の「超過」と同じ形）。
対照の帯 ctl（3150〜3180 MHz、両隣 3118〜3150・3180〜3212）は通話で動かないはず。
線は除く: 窓の両端 5 %・窓の中心・k·163.84 MHz（**3276.8 MHz は 800 MHz 帯の中**）・通話なしの平均で検出した線、各 ±3 ch。
「通話で増えた分」= on の中央値 − off の中央値（off・on を 2 本ずつ交互に取り、同じ種類の 2 本の差を揺れの目安にする）。

道具の確かめ（`python3 tools/phone_rfi.py --selftest`、2026-10-21）: 合成の記録で帯だけ +20 % を +19.90〜+20.02 % と当て、ctl は ±0.07 %、
3276.8 MHz の強い線を除いて off ≒ 0（±0.1 %）、名の無い線を検出。**陽性対照（線を除かない）は off が +3.8 % に持ち上がり、落ちた**。

## 手順

ボード: specd を止めている間に `df -h /dev/shm`・`ls /dev/shm`（残った `psm_*` を消す。YATSUGATAKE M6 の既知の件）。
制御 PC: `cd ~/git/rfsoc/proj026`、`export B=<ボード>`。

**A. LPF なし（今の配線、ノイズソース OFF・SG OFF）**
1. ボードで `cd ~/sam45-fine-m5b && sudo python3 specd.py --clkin 0 --ref 10 --bits bits.json`
2. 制御 PC: `python3 ~/git/YATSUGATAKE/sw/pynq/specctl.py --host $B "SET tint=0.04096 all.shift=4 A0.if=3200 B0.if=3200 C0.if=3200 D0.if=3200 A0.bw=256 B0.bw=256 C0.bw=256 D0.bw=256 A1.if=2432 B1.if=2432 C1.if=2432 D1.if=2432 A1.bw=256 B1.bw=256 C1.bw=256 D1.bw=256"`
3. 床の高さ: `N=244 tools/phone_seg.sh runs/lvl4` → `python3 tools/phone_rfi.py --level runs/lvl4.s45`（q ≧ 16 LSB²・飽和 0 になる SHIFT を選ぶ。決めた SHIFT を以後 C1〜C2b で同じに）
4. **C1**: `tools/phone_seg.sh runs/c1_off1` → （通話を始めて）`runs/c1_on1` → （切って）`runs/c1_off2` → （通話）`runs/c1_on2`
5. `python3 tools/phone_rfi.py --label C1 --off runs/c1_off*.s45 --on runs/c1_on*.s45 --json runs/c1.json`
6. specd を止める（Ctrl-C）。`/dev/shm` を見る

**B. 配線 P（1PPS を分配して PPS Clk と ADC_A〜D に）、ボード直（root）**
1. **LPF なしで 1 回**: `python3 timetest.py --clkin 0 --ref 10 --t2 --t2-adc 0,1,2,3 --out f2_nolpf`
2. LPF を入れる（1PPS は分配器の後の PPS Clk の枝、10 MHz は入力の直前）
3. F-0: `python3 timetest.py --clkin 0 --ref 10 --t0 --seconds 30 | tee f0_lpf.txt`
4. F-2: `python3 timetest.py --clkin 0 --ref 10 --t2 --t2-adc 0,1,2,3 --out f2_lpf_a` → ADC のケーブルを A↔C・B↔D に入れ替えて `--out f2_lpf_b`
5. 結果の .json と画面の出力をこの PC の `runs/` へ

**C. LPF あり（A の配線に戻す。ノイズソース OFF・SG OFF・SHIFT は A と同じ）**
1. **C2a（1PPS だけ LPF）**: 10 MHz の LPF を外して specd を起こし、A の 2 の SET（SHIFT は A で決めた値）→ `runs/c2a_off1・on1・off2・on2`
2. specd を止め、10 MHz にも LPF を入れて起こし直し、SET → **C2b（両方）**: `runs/c2b_off1・on1・off2・on2`
3. `python3 tools/phone_rfi.py --label C2a …`・`--label C2b …`

## 予言（測る前に書く、2026-10-21）

1. **C1（LPF なし）**: 4 ADC とも 800 の帯の「増えた分」が揺れの目安の 5 倍以上ではっきり正。ctl の増えた分は揺れの目安の中。
   大きさは proj013 の構成 2（+26.5 %、入力 −47 dBFS・10 MHz は外していた）以上（入力が ADC の床で低いぶん、超過の比は大きく出る）
2. **F-2（LPF なし、B-1）**: 4 ADC とも縁が見え（最大 / σ ≧ 20）、M は今の CAL（A 146.0・B 146.3・C 147.4・D 147.5 ns）から ±2.5 ns 内（YATSUGATAKE M6 の予言 5 と同じ。配線 P のケーブルが 10-14 と違えばその差が乗る）
3. **F-0（LPF あり）**: 4 タイルの PLL がロック、TRIG・COMP とも 1PPS の間隔 − 1 秒が ±1 ビート（= 10 MHz が LPF の後もロックしている。外れれば +90 ppm ≒ 23,000 ビート）、GLITCH・BAD・MISS 0（LPF の段の応答の振れで二度打ちしない）
4. **F-2（LPF あり）**: **M が B-1 より 55〜80 ns 小さくなる**（LPF は pps_det の側を遅らせる。低い周波数の群遅延 ≒ 59 ns ＋ 立ち上がりが鈍って閾値を越えるのが遅れる分）。4 ADC で同じだけ（差 ≦ 1 ns）。1 回の中の σ ≦ 0.4 ビート、2 回の差 ≦ 1 ビート
5. **C2b（両方 LPF）**: 800 の帯の増えた分が C1 の **1/3 以下**（混信が芯線を伝わってくるなら LPF で大きく落ちる。1/1.5 より減らなければ、入口はシールドの外側を伝わる同相の電流で、直列のフィルタでは止まらない → フェライト・ケーブルの見直し）。ctl は動かない
6. **C2a と C2b の差（10 MHz のケーブルの寄与）**: 数の予言は無い（初めて測る）。proj013 で 1PPS のケーブルだけで 7 倍だったので、C2a は C2b より大きく出る見込み

自信が低い所: 携帯電話の送信電力は通話ごと・基地局の状況で揺れる（proj013 の注）。on / off を交互に 2 組取り、同じ種類の差で揺れを見る。
SHIFT の床の高さ（無入力の窓の床が何 LSB² か）は A-3 で決める。

- **予言 5（C2b は C1 の 1/3 以下）: 判定できない**。強さの物差し（電話の送信電力）が揃わない。ただし **800 MHz 帯に出た区間を見る限り、LPF で減った兆しは無い**（C2a +619 %・C2b +151 % ≧ C1 +103・+121 %）。
  LPF が芯線の 800 MHz を十分に止めているなら、入口は芯線ではない（シールドの外側の同相の電流・ほかのケーブル・ボードの直接の結合）見込み。確かめていない
- **予言 6: 判定できない**（同じ理由）
- 対照の帯（ctl）はどの区間も ±0.04 % で動かない。飽和 0・flags 0・miss 0
- 手順の穴: **specrecv は既にある .s45 に足して書く**。C2b の off1・on1 は 2 回ずつ回して 1 つのファイルに 2 区間が入り、phone_rfi が 2 区間を混ぜて「増えた分 +0.03 %」と出した。
  phone_seg.sh は同じ名前を止める・phone_rfi は START が 2 回あれば注意を出すように直した。区間ごとは `tools/segscan.py`
