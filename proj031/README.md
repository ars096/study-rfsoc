## 目的

proj030（レーン FFT の 2-for-1）で 2G-4 は DSP 2,320（54.3 %）まで減った。続けて **PFB の係数の補間（`g24_coef`、DSP 64 / コア）をやめ、係数そのものを URAM に置いて 4 コアで 1 組を共有する**と、
DSP がさらに 256 減るか、代価（URAM・共有の出口を 4 コアへ配るタイミング・起動の手順）が見合うかを確かめる。
2-for-1 と効果を分けて読むため、proj030 には入れずに別の proj にした（2026-10-26、西村さん）。

**係数の値は proj030 と bit 単位で同じにする**（`g24_coef` が作る補間の値を、そのまま URAM に入れる）。PFB の出口も proj030 と bit 単位で同じになり、
「替えたのは係数の出どころだけ」を sim で直接照らせる（精度は変わらない）。

## 形（2026-10-27）

### 置き方: 対称性で 4096 × 576 bit = URAM 8 個

係数は左右対称（c[i] = c[L − 1 − i]）。1 拍 m に要る 16 レーン × 4 タップのうち、
**t 3・t 2 は「番地 4095 − m・レーン 15 − p」の t 0・t 1 と同じ**（`coef_beat` の 4096 × 16 の全部で bit 単位に一致することを確かめた。2026-10-27、起こしの前）:

- c[t 3][m][p] = c[t 0][4095 − m][15 − p]、c[t 2][m][p] = c[t 1][4095 − m][15 − p]
- 値の範囲 −7,682〜78,287（18 bit の符号つきに入る）

→ 行 m に {t 0, t 1} × 16 レーン = 32 × 18 bit = **576 bit**。URAM288（4096 × 72）を 8 個横に並べた 1 段の深さ（4096 = 1 フレームのビート数）。
**2 ポートで読む**: ポート A が番地 m（t 0・t 1）、ポート B が番地 4095 − m（レーンを逆順にして t 3・t 2）。出口は今の `g24_coef` と同じ 1152 bit の並び（レーン p が [72p +: 72]、タップ t が [18t +: 18]）。

### 入れ方: 起動のときに PS が AXI4-Lite で書く（2026-10-27、西村さん）

**URAM は初期値を持てない**（LESSONS、proj023 2b。proj023 の案 A もこのために係数を BRAM に移した）ので、何かが起動のときに書き込む必要がある。
候補は 3 つ並べた: (a) PL の詰め役（今の補間の表 RAMB36 2 を 1 組残し、rst の後に URAM を書く）・(b) 共有の BRAM の ROM（RAMB36 64、URAM は使わない）・**(c) PS が AXI4-Lite で書く**。**(c) に決まった**。

(c) の穴は「**書き忘れると係数 0（か前の中身）のまま、ビルドも START も通って静かに違う値を出す**」型（LESSONS の「動いているように見える失敗」）。PL の側で閉じる:

- 共有のセル `g24_cu`（新規、BD のセル、AXI4-Lite は smc_ctrl の口を 1 つ足す）が URAM を持つ。書きは **行ごと**: 18 語（576 bit）を溜めてから ROW に番地 m を書くと 1 行を書く
- **検証は PL が URAM を読み直して行う**: PS が期待の CRC を EXP に書き、VERIFY を書くと、PL が URAM の 4096 行を読み直して CRC を取り、一致したら **OK を立てる**。書きが 1 回でもあれば OK は落ちる
  （書いた語の流れの CRC ではなく、記憶の中身を照らす。番地の配線の誤りも捕まる）
- **OK が 0 の間に動いたコアは粘着のフラグを立てる**（g24_spec の flags[0] = coef_mis に OR する。flags の 8 bit は全部使っているため。どちらかは `g24_cu` の STAT で分ける）
- PS（G24Backend）は Overlay の後に係数を書き、OK を読んでから START を許す（照合の項目を 1 つ足す）
- 係数の値の出どころ: 今の `src/g24/g24_coef_lo.hex`・`g24_coef_hi.hex`（補間の表）から、`coef_beat` と同じ式で PS が作る（決めるのは P の段。PC で作った 576 bit × 4096 行の表を bit の ID と対にして持つ形もある）

### 配り: Wide（proj023）の形

- 番地は **s45_core_0 の m_now**（T から作る。4 コアで同じ値）。`g24_cu` の出口 1152 bit と m_out を 4 コアへ配る
- 遅れ: `g24_cu` の中で 番地 1・URAM の読み 1・URAM の出口のレジスタ 1・並べ替え 1 = 4、各コアの受けの 1 段（Wide の coef_q）で **計 5 = 今の g24_coef の LAT と同じ**。g24_pfb の遅延線 DLY 3 は今のまま使える見込み
- 各コアの coef_mis（m_out と自分の m の比べ）は今のまま残す（共有の食い違いの見張り。LESSONS「共有の ROM は番地も一緒に返す」）

## 手順

各手順は 予言（走らせる前に README に書く）→ 結果 → 当たり・外れ → INDEX → commit。

- **E 見積もり**（下）。proj030 の E-1 に入れ忘れた「URAM の係数を足した場合」の行もここで出す
- **M 模型**（`model/cu_model.py`、新規）: 行の並べ方（576 bit）・2 ポートの読みからの組み立てが `coef_beat` と bit 単位で一致・CRC の定義・陽性対照
- **P-1 部品 `g24_cu` の sim**（AXI の書き → VERIFY → 2 ポートの読み、模型と bit 単位。陽性対照: 鏡の番地の誤り・書き忘れ・CRC の食い違い・VERIFY の後の書き）
- **P-2 コアの sim**: g24_spec・g24_core・g24_s45_core・4 コアの sim を `g24_cu` 込みに。**PFB の出口が proj030 と bit 単位で同じ**（同じ入力で）
- **S OOC**: `g24_cu` の OOC（URAM 8・DSP 0）
- **B 全体のビルド**（`-1`）: smc_ctrl の口 +1・結線の照合（`g24_cu` → 4 コア、在るべき相手と在ってはいけない相手）・URAM の総数を事前に足す（LESSONS、proj025）
- **R 実機**: 係数の書き込み（時間・OK）・proj030 の R と同じ確かめ（4 コアの bit 単位の同等・床・CW）・電流。**書かずに START したら断るか**の陽性対照

## E 見積もり — 予言（2026-10-27、走らせる前に書く）

### E-0 proj030 の E-1 に入れ忘れた行（「2-for-1 ＋ URAM の係数」を proj030 の起こしの時点の数で）

proj030 E-1 の (B) の見込み（DSP 2,448・LUT ≒ 44 %・BRAM ≒ 706）に、係数の補間 4 個（DSP 64・RAMB36 2・LUT 16 / コア、proj027 F-2 の OOC）を URAM 8 個に替えた場合:
**DSP 2,448 → 2,192（51.3 %）・BRAM ≒ 698・URAM 48 → 56（70 %）・LUT ≒ 44 %**（LUT は 1 % 未満しか動かない）。
（proj030 は実測で DSP 2,320 になったので、今の起点から出すと下の E-1）

### E-1 2G-4 の 4 コア（起点は proj030 の実測、build/ の既定の戦略）

浮く分: `g24_coef` × 4（1 個 DSP 64・RAMB36 2・LUT 16、proj027 F-2 の OOC。FF は数えていない）。
増える分（仮の値）: `g24_cu` 1 個 — URAM 8・DSP 0・LUT 400〜1,000（AXI4-Lite の口 ≒ 200・18 語の溜めと選び ≒ 150・CRC の展開した XOR（576 bit を 1 拍で）≒ 300〜600・並べ替えはつなぎ替えだけ）・FF ≒ 2,500（溜め 576・出口 1152・CRC・帳簿）。
各コアの受けの 1 段（coef_q 1152 FF）は今の g24_coef の出口のレジスタと入れ替わるだけ。

| | proj030（実測） | proj031 の予言 | 根拠 |
|---|---|---|---|
| DSP | 2,320（54.3 %） | **2,064（48.3 %）ちょうど** | −64 × 4。DSP は数で決まる |
| URAM | 48 | **56（70 %）** | ＋8。積分器 12 × 4 = 48 のまま |
| BRAM | 700 | **692（64.1 %）** | −2 × 4（補間の表）。`g24_cu` は BRAM を使わない |
| LUT | 200,932（47.25 %） | **47.0〜47.6 %** | −64 ＋ 400〜1,000。配置の揺れのほうが大きい |
| タイミング（`-1`・既定） | WNS +0.010 ns（最悪経路は ADC 側の gb_up → gb_fifo） | **既定で閉じる見込みは半分**。落ちるなら最悪経路は `g24_cu` の出口 → コア 1〜3 の coef_q（Wide は同じ形で +0.025 ns） | 1152 bit × 4 コアの配り。URAM の列は 1 か所に固まる |
| VCCINT（実機） | 31.6〜32.4 A | **30〜32 A** | DSP −256 のうち補間の積は毎拍トグルしている。report_power で出してから幅を直す（LESSONS: ±15 %） |

- 外れるとしたら: URAM の 2 ポートの推論（真の 2 ポートで、ポート A が書きと読みを兼ねる。推論が BRAM や LUT に落ちたら OOC で分かる）・タイミング（配りの 1 段で足りないなら、受けを 2 段にして g24_pfb の DLY を 4 に）
- **起動の時間**（PS の書き）: 18 語 ＋ ROW 1 語 = 19 回 × 4096 行 = 77,824 回の MMIO。1 回 ≒ 10 µs（LESSONS）で **≒ 0.8 s**（Python）。VERIFY は 4096 拍 = 16 µs
