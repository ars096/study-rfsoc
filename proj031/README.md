## 目的

proj030（レーン FFT の 2-for-1）で 2G-4 は DSP 2,320（54.3 %）まで減った。続けて **PFB の係数の補間（`g24_coef`、DSP 64 / コア）をやめ、係数そのものを URAM に置いて 4 コアで 1 組を共有する**と、
DSP がさらに 256 減るか、代価（URAM・共有の出口を 4 コアへ配るタイミング・起動の手順）が見合うかを確かめる。
2-for-1 と効果を分けて読むため、proj030 には入れずに別の proj にした（2026-10-26、西村さん）。

**係数の値は proj030 と bit 単位で同じにする**（`g24_coef` が作る補間の値を、そのまま URAM に入れる）。PFB の出口も proj030 と bit 単位で同じになり、
「替えたのは係数の出どころだけ」を sim で直接照らせる（精度は変わらない）。

## 形（2026-10-27）

### 置き方: 対称性で 4096 × 576 bit = URAM 8 個

係数は左右対称（c[i] = c[L − 1 − i]）。1 拍 m に要る 16 レーン × 4 タップのうち、
**t 3・t 2 は「番地 4095 − m・レーン 15 − p」の t 0・t 1 と同じ**（`coef_beat` の 4096 × 16 の全部で bit 単位に一致することを確かめた。2026-10-27、起こしの前）:

- c[t 3][m][p] = c[t 0][4095 − m][15 − p]、c[t 2][m][p] = c[t 1][4095 − m][15 − p]
- 値の範囲 −7,682〜78,287（18 bit の符号つきに入る）

→ 行 m に {t 0, t 1} × 16 レーン = 32 × 18 bit = **576 bit**。URAM288（4096 × 72）を 8 個横に並べた 1 段の深さ（4096 = 1 フレームのビート数）。
**2 ポートで読む**: ポート A が番地 m（t 0・t 1）、ポート B が番地 4095 − m（レーンを逆順にして t 3・t 2）。出口は今の `g24_coef` と同じ 1152 bit の並び（レーン p が [72p +: 72]、タップ t が [18t +: 18]）。

### 入れ方: 起動のときに PS が AXI4-Lite で書く（2026-10-27、西村さん）

**URAM は初期値を持てない**（LESSONS、proj023 2b。proj023 の案 A もこのために係数を BRAM に移した）ので、何かが起動のときに書き込む必要がある。
候補は 3 つ並べた: (a) PL の詰め役（今の補間の表 RAMB36 2 を 1 組残し、rst の後に URAM を書く）・(b) 共有の BRAM の ROM（RAMB36 64、URAM は使わない）・**(c) PS が AXI4-Lite で書く**。**(c) に決まった**。

(c) の穴は「**書き忘れると係数 0（か前の中身）のまま、ビルドも START も通って静かに違う値を出す**」型（LESSONS の「動いているように見える失敗」）。PL の側で閉じる:

- 共有のセル `g24_cu`（新規、BD のセル、AXI4-Lite は smc_ctrl の口を 1 つ足す）が URAM を持つ。書きは **行ごと**: 18 語（576 bit）を溜めてから ROW に番地 m を書くと 1 行を書く
- **検証は PL が URAM を読み直して行う**: PS が期待の CRC を EXP に書き、VERIFY を書くと、PL が URAM の 4096 行を読み直して CRC を取り、一致したら **OK を立てる**。書きが 1 回でもあれば OK は落ちる
  （書いた語の流れの CRC ではなく、記憶の中身を照らす。番地の配線の誤りも捕まる）
- **OK が 0 の間に動いたコアは粘着のフラグを立てる**（g24_spec の flags[0] = coef_mis に OR する。flags の 8 bit は全部使っているため。どちらかは `g24_cu` の STAT で分ける）
- PS（G24Backend）は Overlay の後に係数を書き、OK を読んでから START を許す（照合の項目を 1 つ足す）
- 係数の値の出どころ: 今の `src/g24/g24_coef_lo.hex`・`g24_coef_hi.hex`（補間の表）から、`coef_beat` と同じ式で PS が作る（決めるのは P の段。PC で作った 576 bit × 4096 行の表を bit の ID と対にして持つ形もある）

### 配り: Wide（proj023）の形

- 番地は **s45_core_0 の m_now**（T から作る。4 コアで同じ値）。`g24_cu` の出口 1152 bit と m_out を 4 コアへ配る
- 遅れ: `g24_cu` の中で 番地 1・URAM の読み 1・URAM の出口のレジスタ 1・並べ替え 1 = 4、各コアの受けの 1 段（Wide の coef_q）で **計 5 = 今の g24_coef の LAT と同じ**。g24_pfb の遅延線 DLY 3 は今のまま使える見込み
- 各コアの coef_mis（m_out と自分の m の比べ）は今のまま残す（共有の食い違いの見張り。LESSONS「共有の ROM は番地も一緒に返す」）

## E 見積もり — 予言（2026-10-27、走らせる前に書く）

### E-0 proj030 の E-1 に入れ忘れた行（「2-for-1 ＋ URAM の係数」を proj030 の起こしの時点の数で）

proj030 E-1 の (B) の見込み（DSP 2,448・LUT ≒ 44 %・BRAM ≒ 706）に、係数の補間 4 個（DSP 64・RAMB36 2・LUT 16 / コア、proj027 F-2 の OOC）を URAM 8 個に替えた場合:
**DSP 2,448 → 2,192（51.3 %）・BRAM ≒ 698・URAM 48 → 56（70 %）・LUT ≒ 44 %**（LUT は 1 % 未満しか動かない）。
（proj030 は実測で DSP 2,320 になったので、今の起点から出すと下の E-1）

### E-1 2G-4 の 4 コア（起点は proj030 の実測、build/ の既定の戦略）

浮く分: `g24_coef` × 4（1 個 DSP 64・RAMB36 2・LUT 16、proj027 F-2 の OOC。FF は数えていない）。
増える分（仮の値）: `g24_cu` 1 個 — URAM 8・DSP 0・LUT 400〜1,000（AXI4-Lite の口 ≒ 200・18 語の溜めと選び ≒ 150・CRC の展開した XOR（576 bit を 1 拍で）≒ 300〜600・並べ替えはつなぎ替えだけ）・FF ≒ 2,500（溜め 576・出口 1152・CRC・帳簿）。
各コアの受けの 1 段（coef_q 1152 FF）は今の g24_coef の出口のレジスタと入れ替わるだけ。

| | proj030（実測） | proj031 の予言 | 根拠 |
|---|---|---|---|
| DSP | 2,320（54.3 %） | **2,064（48.3 %）ちょうど** | −64 × 4。DSP は数で決まる |
| URAM | 48 | **56（70 %）** | ＋8。積分器 12 × 4 = 48 のまま |
| BRAM | 700 | **692（64.1 %）** | −2 × 4（補間の表）。`g24_cu` は BRAM を使わない |
| LUT | 200,932（47.25 %） | **47.0〜47.6 %** | −64 ＋ 400〜1,000。配置の揺れのほうが大きい |
| タイミング（`-1`・既定） | WNS +0.010 ns（最悪経路は ADC 側の gb_up → gb_fifo） | **既定で閉じる見込みは半分**。落ちるなら最悪経路は `g24_cu` の出口 → コア 1〜3 の coef_q（Wide は同じ形で +0.025 ns） | 1152 bit × 4 コアの配り。URAM の列は 1 か所に固まる |
| VCCINT（実機） | 31.6〜32.4 A | **30〜32 A** | DSP −256 のうち補間の積は毎拍トグルしている。report_power で出してから幅を直す（LESSONS: ±15 %） |

- 外れるとしたら: URAM の 2 ポートの推論（真の 2 ポートで、ポート A が書きと読みを兼ねる。推論が BRAM や LUT に落ちたら OOC で分かる）・タイミング（配りの 1 段で足りないなら、受けを 2 段にして g24_pfb の DLY を 4 に）
- **起動の時間**（PS の書き）: 18 語 ＋ ROW 1 語 = 19 回 × 4096 行 = 77,824 回の MMIO。1 回 ≒ 10 µs（LESSONS）で **≒ 0.8 s**（Python）。VERIFY は 4096 拍 = 16 µs

### 期待の CRC は bit に焼き込む（2026-10-27、M の前に決めた）

PS が期待の CRC を書く形だと、PS が間違った係数を作ったとき、その CRC も一緒に渡して OK が立つ。
**期待の値はビルドのときに模型から出し、`g24_cu` の定数（CONFIG.COEF_CRC）にする**。OK の意味は「URAM の中身 = この bit が想定する係数」になる。build.tcl は定数を読み返して模型の値と照らす。PS は CRC の値を読めるだけ。

CRC の定義: 行 m = 0..4095 の 576 bit を、bit k をバイト k div 8 の bit k mod 8 に置いた 72 バイトとして並べた 294,912 バイトの **zlib.crc32**（反射 CRC-32、初期値・終わりの XOR 0xFFFFFFFF）。
PL は 1 拍に 32 bit（行を 18 拍）ずつ取る。式は展開した XOR（生成器 `tools/gen_crc32.py` → `src/g24/crc32_d32.vh`。LESSONS「CRC は for 文でなく展開した XOR の式で」）。VERIFY は 4096 × 18 拍 ≒ 288 µs

## M 模型（`model/cu_model.py`、`make model-cu`）— 予言（2026-10-27、走らせる前に書く）

PS の側の係数の作り（`pynq/g24cu.py`、新規。numpy だけで補間の表の hex から行を作る。窓の設計（`design()`）は使わない）を模型が import して照らす。

- **a 表**: `src/g24/g24_coef_lo.hex`・`hi.hex` を {S 13 bit, V 22 bit} として読むと、`coef_tables()`（G 4）の V・S と全部一致（前半 = s 0..1023、後半 = s 1024..2047）
- **b 行の組み立て**: g24cu の行（4096 × 32 個 × 18 bit）を 2 ポートで読んだ形（A = 行 m の t 0・t 1、B = 行 4095 − m のレーンを逆順にして t 3 = t 0・t 2 = t 1）が `coef_beat` と **4096 × 16 × 4 の全部で一致**
  - 陽性対照: B を行 4094 − m で読む → ほとんど全部（t 2・t 3 の 2 × 65,536 のうち 99 % 以上）が違う。レーンを逆順にしない → 同じく 99 % 以上が違う（自己の鏡 p = 15 − p は無い）
- **c 18 語の詰め**: 行 → 18 語 × 32 bit → 行 の往復が元に戻る。18 bit の符号つきの範囲（−131,072〜131,071）に全部入る
- **d CRC**: 3 つの書き方（zlib.crc32・1 bit ずつの式・生成器が作る 32 bit の XOR の行列を 1 拍ずつ当てる）が同じ値。値を README に書き、build.tcl の定数にする
  - 陽性対照: 1 bit 反転・2 行の入れ替え・全部 0（書き忘れ）で CRC が変わる
- 自信が低い所: 無い（どれも決まった式の写し）。外れるなら hex の並び（前半 / 後半、{S, V} の順）の読み違い

**結果（`make model-cu`、2026-10-27、6.9 秒）: a・b・c・d とも本体は当たり。b の陽性対照の割合だけ外れ**

| | 結果 | 予言 | |
|---|---|---|---|
| a 表 | 前半・後半の V・S が coef_tables（G 4）と全部一致 | 同じ | 当たり |
| b 組み立て | coef_beat と違う個 **0 / 262,144** | 全部一致 | 当たり |
| b 陽性対照 | 鏡の番地 4094 − m: t 2・3 の **90.0 %** が違う / レーンを逆順にしない: **79.7 %** が違う | 99 % 以上 | **落ちたのは当たり、割合は外れ** |
| c 18 語 | (4096, 18) uint32・往復で元に戻る・値 −7,682〜78,287 | 18 bit に入る | 当たり |
| d CRC | 3 つの書き方とも **0x891BE197**・crc32_d32.vh は生成器の出力と同じ。陽性対照 3 つとも値が変わった | 同じ値・陽性対照で変わる | 当たり |

- b の外れの理由: **隣のレーンの係数の 49.7 % が同じ値**（補間の傾きが 1 サンプルあたり 1 LSB に満たない所が多い。窓の裾と頂上）。番地を 1 ずらしても、レーンを逆にしても、たまたま同じ値になる所が多い。
  |c| ≧ 1,000 の所に限っても、同じになる割合は 2.0 %（番地）・9.2 %（逆順）。予言は「係数は隣と必ず違う」と暗に読んでいた。
  **sim の陽性対照はどの行が違うかを数えるのでなく、違う個が 0 でないことで判定する**（P-1 にも持ち込む）。まとめの行の成否は本体の一致と陽性対照が落ちることで読むように直した（線を後から動かしたので、ここに書いておく）
- **COEF_CRC = 0x891BE197**（build.tcl の `g24_cu` の CONFIG.COEF_CRC。build.tcl は `make model-cu` の最後の行と照らす）

## P-1 部品 `g24_cu`（`src/g24/g24_cu.v`、`make sim-cu`）— 予言（2026-10-27、走らせる前に書く）

形（「形」の節に足したこと）:
- レジスタ: 0x00 ID 0x6375_0001・0x04 PROJ・0x08 CTRL（W: [0] VERIFY・[1] CLR）/ STAT（R: [0] OK・[1] VERIFY 中・[2] 終えた・[3] 不一致・[4] CLR の後に書きがあった）・0x0C ROW・0x10 COEF_CRC・0x14 CRC・0x18 NROW・0x40〜0x84 DATA[0..17]
- VERIFY は行ごとに「ポート A で読む（2 拍）→ 18 拍で CRC」。**4096 × 21 = 86,016 拍（336 µs）**＋ AXI の応答
- **コアは OK が立つまで口を開けない**（起動の見張り go の条件に OK を足す。P-2 で）。Overlay を載せてから PS が書き終えるまで（≒ 1 s）に、起動直後の粘着 FLAGS を立てないため。開いた後に OK が落ちたら coef_mis（flags[0]）

sim: **比べる相手は proj030 の `g24_coef` の RTL そのもの**（tb の中に並べ、同じ番地を入れて、2・3 フレーム目の出口 1152 bit を m ごとに比べる）。書く中身は `pynq/g24cu.py` の words（PS が書くのと同じ値）。

| 変種 | 中身 | 予言 |
|---|---|---|
| normal | 書く → VERIFY → 3 フレーム読む | **全部通過**: リセット中の ready 0・STAT 0x05（OK・終えた）・CRC 0x891BE197・NROW 4096・遅れ 3 で一定・ok_out 1・**g24_coef と違う m 0 / 4096**。VERIFY は 86,016〜86,100 拍 |
| mirror（RTL、ポート B を 4094 − m） | | 落ちる: OK は 1（CRC は中身を見る）・違う m > 0 |

## S `g24_cu` の OOC（`make ooc-cu`、`-1`・256 MHz）— 予言（2026-10-27、走らせる前に書く）

**結果（2026-10-27、OOC は各 1 分）: 3 回目で URAM 8 に入った**

| 回 | 形 | URAM | BRAM | LUT | FF | WNS |
|---|---|---|---|---|---|---|
| 1 | g24_cu の中に URAM を直に書く（両ポートを 1 つの always） | **0** | **64** | 1,094 | 3,640 | +1.496 |
| 2 | ポートごとに別の always にした | 0 | 64 | 1,094 | 3,640 | +1.496 |
| 3 | **URAM を型どおりの小さなモジュール `g24_cu_ram` に切り出した** | **8** | **0** | **757** | **2,487** | **+1.998** |

- 1・2 回目は `Synth 8-5792: The ram_style = "ultra" ... is ignored because invalid write mode`。推論の表ではポート A が **READ_FIRST** と読まれていた（URAM は NO_CHANGE だけ）。RTL は「書く拍は読みのレジスタを更新しない」NO_CHANGE の形
- 切り分け（scratchpad で、各 1 分）: 型どおりの単体（enable あり・なし・番地を書きの印で選ぶ・番地をレジスタで選ぶ）は**どれも URAM 8**。g24_cu の写しから VERIFY の溜め・出口の並べ替え・番地の vbusy の選び・ポート B の番地の出どころを 1 つずつ外しても**どれも BRAM 64**
  → **原因は特定できていない**（g24_cu のまわりの論理と一緒に最適化されると NO_CHANGE が READ_FIRST に読み替えられる、までしか言えない）。モジュールを分けると直る。
  途中で「Vivado は SYNTHESIS を定義しないので initial が合成に入った」と注釈に書いたが、`ifdef __ICARUS__` に替えても直らなかったので**誤り**（注釈は消した。sim だけの initial は `__ICARUS__` で囲んだまま）
- 3 回目と予言の比べ: URAM 8・DSP 0・BRAM 0・WNS（> +0.3）・8-3848 0・CW 0 は当たり。**LUT 757 は予言 800〜1,600 の下に外れた**（sh の選びが FF の CE と組で LUT が少なかった見込み、未確認）。FF 2,487 は当たり（下の端。ra2・rb2 が URAM の出口のレジスタに吸われた見込み）
- 部品を直した後に `make sim-cu` を回し直して、全部通過・陽性対照 5 本は落ちた（1 回目と同じ）
- 知見（LESSONS の候補）: **URAM の推論は、使う側のモジュールに直に書かず、型どおりの小さなモジュールに切り出す。Synth 8-5792 は WARNING 1 行で、黙って BRAM に落ちる**（ビルドの照合で URAM の数を見る）
