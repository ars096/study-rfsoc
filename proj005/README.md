# proj005 — 正弦波源での ADC 評価（ノイズフロア・線形性・フルスケール）

日付: 2026-09-17
状態: **成功（ただし SFDR の確定は持ち越し）**

## 目的

**素性の分かっている正弦波を入れて、これまで「信号源のもの」と「ADC のもの」が
混ざっていた量を分離する。**

proj003 は信号源が方形波で、高調波が **−9.3 dBc** もあった。この状態では ADC の歪みは
完全に埋もれる。proj004 では、外部基準の測定中にノイズフロアが 1.3 dB 上がる現象が
出たが、原因を切り分けられないまま宿題として残った。

どちらも **信号源を替えれば答えが出る**種類の問いで、Agilent E8257D が使えるように
なったので、proj004 のビットストリームのまま音源だけ差し替えて測った。

## なぜ proj004 から分けるか

proj004 の問い（外部 10 MHz 基準が効いているか）は決着している。そこに別の問いを
足すと「proj004 が何を証明したか」が濁る。**PL の設計もビットストリームも proj004 と
同一**で、変えたのは**測定系だけ**である。

## 測定系

```
観測所 10 MHz ─▶ E8257D REF IN（外部基準にロック）
                    ├─▶ 10 MHz OUT ─▶ RFSoC4x2 CLK_IN（= CLKin0、proj004 で確定）
                    └─▶ RF OUT ─▶ **−10 dB ATT** ─▶ ADC_B
```

| | 値 |
|---|---|
| 信号源 | **Agilent E8257D**（250 kHz 〜 20 GHz） |
| 試験トーン | 100.0125 MHz（= 18.75 kHz × 5334、ビン中心） |
| 経路の減衰 | **−10 dB**（ケーブルの反射軽減のため） |
| SG の出力設定 | ADC 入力の目標値 **+10 dBm**（減衰器の分） |
| クロック源 | CLKin0（外部 10 MHz） |
| ビットストリーム | proj004 と同一 |

**SG は前面パネルで設定した。** ドライバは書いていない（下記「決めたこと」）。

## 決めたこと

- **決定**: 試験音源を APSYN420 から **E8257D に替える**。分光計の評価に方形波源は使わない
  **理由**: 2 つ実害があった。(1) 高調波が **−9.3 dBc** で、ADC の歪みが完全に埋もれる。
  (2) **広帯域ノイズがノイズフロアを 1.3〜2.1 dB 持ち上げていた**（下記）。
  どちらも「装置を評価しているつもりで信号源を評価している」状態になる
  **付随**: APSYN420 の仕様範囲は 2.49〜20.5 GHz で、100 MHz は**範囲外**である
  （`--probe` が返す `周波数範囲` で確認できる）。範囲外での波形・レベル・ノイズは
  保証されない。`tools/apsyn.py` は残すが、**分光計の評価には使わない**

- **決定**: **SFDR の確定は持ち越す。** 着手条件はフィルタの入手
  **理由**: E8257D 自身の H2 が **−51.5 dBc** で、14 bit ADC に期待される SFDR
  （−70 dBc 級）より**悪い**。フィルタ無しでは常に悪いほう＝信号源を測ることになる。
  **無い道具で測れるふりをしない**
  **着手条件**: 100 MHz 帯の BPF、もしくは 150 MHz 級の LPF を 1 個
  **付随**: あわせて **ADC をフルスケール近く（−3 dBFS 級）まで振る**こと。
  今回は −15.9 dBFS 止まりで、ADC の歪みが効いてくる領域に入っていない

- **決定**: レベルは **ADC 入力換算**で記録し、**経路の減衰量を必ず残す**
  **理由**: proj003 は減衰器（−40 dB）の値がログにも README にも残っておらず、
  今回の E8257D の結果と突き合わせたところ **54 dB 合わなかった**。
  APSYN420 の最大出力（+20 dBm）では説明がつかず、**proj003 の絶対レベルは
  記録から再構成できない**。相対変化しか信用できない記録になっていた
  **実装**: `adc_capture.py` に `--sg-dbm` / `--atten-db` を足し、ADC 入力換算と
  0 dBFS 換算を出力に残すようにした。**測ったことと、何を測ったかは別**
  **影響範囲**: proj003 の結論（信号源が方形波）は揺らがない。今回の正弦波での
  直接測定が独立に裏付けている。崩れたのは絶対レベルの帳簿だけ

- **決定**: ADC のフルスケールは **実測値**を使う
  **理由**: `tools/apsyn.py` に書いていた「ADC 入力のフルスケールは +1 dBm 級」は
  根拠不明の想定だった。3 レベルの実測から **0 dBFS ≒ +5.8 dBm** と確定した
  （3 点のばらつき 0.35 dB）。保護の閾値はこれに合わせて見直す

- **決定**: E8257D のドライバは書かない（当面）
  **理由**: 前面パネルで足りる測定しかしていない。LAN 越しの SCPI は書けるが、
  **動かせないものをリポジトリに置かない**。フィルタが入って掃引が要るようになったら書く
  **付随**: 代わりに**前面パネルの設定値を README に残す**（下記「再現手順」）

## 結果

### ノイズフロアの 1.3 dB は APSYN420 だった

| 条件 | ノイズフロア（18.75 kHz 分解能・中央値） |
|---|---|
| **無入力**（今回・外部基準） | **−106.68 dBFS** |
| 無入力（proj003・内部基準） | −106.45 dBFS |
| **E8257D 正弦波**（3 レベルとも） | **−106.41 〜 −106.72 dBFS** |
| APSYN420（proj004・REF OUT 断） | −105.85 dBFS |
| APSYN420（proj004・REF OUT 接続） | **−104.57 dBFS** |

**無入力と E8257D が揃っている。** これが ADC の素のノイズフロアで、
外部基準に切り替えても悪化していない。浮いていたのは APSYN420 のときだけで、
しかも REF OUT を入れるとさらに 1.3 dB 悪化した。**APSYN420 自身の広帯域ノイズ**である。

proj004 の「残した疑問」はこれで解決。**外部基準・ボード・ADC のいずれも無関係だった。**

### 無入力のスパー

| 周波数 | 強さ | 素性 |
|---|---|---|
| **491.520002 MHz** | −75.68 dBFS | LMX2594 → RFDC の基準 |
| 245.756250 MHz | −77.61 dBFS | LMK04828 → LMX の基準 |
| 153.600000 MHz | −82.14 dBFS | AXIS クロック（fs/8） |
| 307.200000 MHz | −86.58 dBFS | 同 × 2 |

強さは proj003（−75.66 / −76.21 dBFS）と同等で、**外部基準にしても回り込みは悪化しない**。

**491.52 MHz ちょうどになっている**のが目を引く。proj003 の内部基準では
491.5125 MHz だった。**スパーの周波数そのものが外部基準の効きを示している。**

### 方形波だったことの直接確認と、残った高調波の素性

| | ADC 入力 −10 dBm | −20 dBm | −30 dBm | 判定 |
|---|---|---|---|---|
| ピーク | −15.89 dBFS | −25.87 dBFS | −35.54 dBFS | 10 dB ステップに追従 |
| **H2** | **−51.51 dBc** | **−51.95 dBc** | **−50.27 dBc** | **dBc 不変 → E8257D の H2** |
| H3 | −70.76 dBc | −71.74 dBc | −66.80 dBc | ほぼ不変 → E8257D の H3 |

H3 は proj003 の **−9.3 dBc から −70.8 dBc へ 61 dB** 落ちた。**信号源が方形波だった
ことの直接確認**である（proj003 はレベル不変性からの推論だった）。

**ADC は圧縮していない。** ADC の 2 次歪みなら入力を 10 dB 下げると dBc は 10 dB
改善するが、H2 の dBc は動いていない。絶対値で見ても H2 は −67.40 → −77.82 →
−85.81 dBFS と入力に **1 : 1** で追従しており、ADC の 2 次歪み（1 : 2）ではない。

### H4 以降に実体は無い

−15.89 dBFS のとき H4 は −88.55 dBc = 絶対 **−104.4 dBFS**。ノイズフロア
（−106.4 dBFS 中央値）とほぼ同じで、**ピーク検出がノイズの山を拾っているだけ**である。
H5〜H9 も同様。**実体があるのは H2 と H3 だけ。**

`adc_capture.py` の高調波表は「その周波数の近傍で最大のビン」を出すので、
**ノイズフロアに埋もれていても必ず何か表示される**。dBc の数字を読む前に、
絶対値をノイズフロアと比べること。

### ADC のフルスケール（実測）

| ADC 入力 | ピーク | 0 dBFS 換算 |
|---|---|---|
| −10 dBm | −15.89 dBFS | +5.89 dBm |
| −20 dBm | −25.87 dBFS | +5.87 dBm |
| −30 dBm | −35.54 dBFS | +5.54 dBm |

**0 dBFS ≒ +5.8 dBm**（3 点のばらつき 0.35 dB、100 MHz、MABA-011118 バラン込み）。

### ノイズと ENOB（導出値）

無入力の標準偏差 **20.15 LSB** から、フルスケール正弦波に対する SNR は

```
SNR = 20 log10( (32768/√2) / 20.15 ) = 61.2 dB
ENOB = (61.2 − 1.76) / 6.02 = 9.9 bit
```

**これは導出値であって測定値ではない。** フルスケールを ±32768 としたこと、
53.3 µs の記録であること、基板のクロック回り込みを含んだ値であることに注意する。
分光計のダイナミックレンジを見積もる出発点として使う。

### ppm の推定精度はレベルで決まる

| ピーク | ppm |
|---|---|
| −15.89 dBFS | **+0.001** |
| −25.87 dBFS | −0.013 |
| −35.54 dBFS | −0.200 |

同じ外部基準・同じ 53.3 µs の記録でも、S/N が下がるとサブビン補間の精度が落ちる。
**proj004 の「残差 −0.015 ppm は測定の下限」という読みが、レベルを振ることで
定量的に裏付けられた。** 周波数確度を詰めたいときは、レベルを確保するか記録長を伸ばす。

## 結論・次にやること

- **信号源と装置が分離できた。** これ以降、スペクトルに出るものは「ADC のもの」と
  「信号源のもの」を区別して語れる。Phase 4 の前にここを済ませた意味は大きい
- **試験音源は E8257D に統一する。** APSYN420 は仕様範囲外の 100 MHz で使っており、
  波形・レベル・ノイズのいずれも保証されない
- **経路の減衰量を記録する規約にした**（`--sg-dbm` / `--atten-db`）。proj003 の
  絶対レベルが再構成できなくなった反省
- 次: **proj006 で 4ch 同時取得とタイル間同期（MTS）**
- 保留: **ADC の SFDR**。フィルタ（100 MHz BPF もしくは 150 MHz 級 LPF）を入手したら、
  フルスケール近く（−3 dBFS 級）まで振って測る

## 再現手順

ビルドは proj004 と同一。**ビットストリームを作り直す必要は無い**が、
自己完結のため一式を持っている。

```bash
# Vivado サーバ
cd proj005
make                # proj004 と同じ設計。WNS +1.0 ns 級が出るはず
```

### E8257D の設定（前面パネル）

| 項目 | 値 |
|---|---|
| Frequency | **100.0125 MHz** |
| Amplitude | **ADC 入力の目標値 +10 dBm**（−10 dB ATT の分） |
| RF Output | ON |
| Reference Oscillator | **External / 10 MHz**（観測所の基準を REF IN へ） |
| 10 MHz OUT | ボードの CLK_IN へ |

**REF IN のロック表示を必ず確認する。** ロックしていなければ ppm が 0 に潰れず、
proj004 の判定が崩れる。

### 測定

```bash
# ボード（PYNQ v3.1.1）
scp build/proj005.bit build/proj005.hwh pynq/*.py xilinx@<board>:~/proj005/
ssh xilinx@<board>
cd ~/proj005

# 1. 無入力（ADC_B に 50Ω 終端）。ADC の素のノイズフロア
sudo -E $(which python3) adc_capture.py --clkin 0 --save noinput.npy

# 2. 正弦波。**--sg-dbm と --atten-db を必ず付ける**
sudo -E $(which python3) adc_capture.py --clkin 0 --tone 100.0125 \
     --sg-dbm 0   --atten-db 10 --save sine_m10.npy    # ADC 入力 -10 dBm
sudo -E $(which python3) adc_capture.py --clkin 0 --tone 100.0125 \
     --sg-dbm -10 --atten-db 10 --save sine_m20.npy    # ADC 入力 -20 dBm
sudo -E $(which python3) adc_capture.py --clkin 0 --tone 100.0125 \
     --sg-dbm -20 --atten-db 10 --save sine_m30.npy    # ADC 入力 -30 dBm
```

**`max|x|` が 32768 に張り付いたら即座にレベルを下げる。** 飽和すると高調波が跳ね上がり、
以降の測定が意味を失う。

保存した `.npy` は `--load` で何度でも解析し直せる。**取得と解析を分けておくこと。**

環境の固定値は [`../VERSIONS.md`](../VERSIONS.md)。

## 想定される詰まりどころ

| 症状 | 見るところ |
|---|---|
| 高調波の dBc が入力レベルに追従しない | **信号源の歪み。** ADC ではない。絶対値も 1 : 1 で動いているか確かめる |
| 高調波の dBc が 1 dB あたり 1 dB 改善する | ADC の 2 次歪み（3 次なら 2 dB）。ここまで来て初めて ADC を測っている |
| H4 以降の dBc が妙な値になる | **ノイズフロアに埋もれている。** 絶対値（dBc + ピークの dBFS）をノイズフロアと比べる |
| ノイズフロアが上がる | **まず信号源を疑う。** 無入力で取れば ADC の素のフロアが出る |
| ppm の推定がばらつく | S/N 不足。レベルを上げるか記録長を伸ばす |
| 絶対レベルが合わない | **経路の減衰量を申告したか**（`--sg-dbm` / `--atten-db`）。分配器・ケーブル損も入れる |
| ppm が 0 に潰れない | E8257D の REF IN がロックしているか。SG とボードが共通基準でなければ 0 にはならない |
