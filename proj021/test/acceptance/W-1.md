# W-1 — SG の CW が予言の ch に出る・周波数の差

- **前提**: 共通の前提。ボード直（root、specd を止めてから）。**配線 S**（SG だけ）。SG は外部 10 MHz に同期
- **手順**:

```bash
python3 window.py --clkin 0 --ref 10 --tone 3010.5 --w 256 --shift 11 --sg $SG --sg-dbm -0.9
python3 window.py --clkin 0 --ref 10 --tone 3010.5 --w 64 --shift 11 --sg $SG --sg-dbm -0.9
```

- **合格**（測る前に決めた条件）:
  - 道具の W-1 が OK（山の ch = 予言の ch。W 256 は 3928）
  - 推定した IF と SG の周波数の差 |·| ≦ 0.5 ppm（**新しく決めた値**。2-2a・2-2d では +0.10 ppm で、数を見るだけだった）
  - **窓のスペクトルの飽和（ダンプの「飽和」= DUMP_SAT）0**。CW は 1 ch に集まるので、既定の SHIFT 4 では山の ch が 18 bit で飽和し、端数 δ と ppm の推定が狂う → `--shift 11`（2-2a・2-2d と同じ）。pfb・ddc の飽和も 0
- **陽性対照**: なし（ch がずれれば道具の W-1 が NG）
- **記録**: **最終の bit の 1 回目（2026-10-14）は判定に使わない**: SHIFT 4（手順に `--shift 11` を書き忘れた）で山の ch が飽和（ダンプごとに 6,250 / 1,563 = 全フレーム）。ch は W 256 で 3928・W 64 で 3424 と予言どおり、ppm は +0.33・−0.11 だが飽和の上の推定。条件の「飽和 0」も「ADC の飽和」と書いていて、見るべき窓のスペクトルの飽和を書いていなかった（測った後に直した）。2-2d までは `--w6` と一緒に回していた（W-1 ch 3928・+0.10 ppm、配線は ノイズソース ＋ SG +20 dBm）
