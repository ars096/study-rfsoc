RFSoC4x2 分光計 · proj020（SAM45-Fine rev2）· 窓 1 つの信号処理

窓の分光: 粗い PFB → DDC → 精細 PFB（T = 4）→ FFT 4096 → 電力 → 積分

ADC の 4096 MSPS の実数列から幅 W（256〜2 MHz）の窓を切り出し、4096 ch の電力スペクトルにするまで。proj020 で変わったのは wspec_core の中だけで、溜めと FFT の間に精細 PFB（4 タップ、原型 sinc × Kaiser β 5・bw 1.198）が入った。ch の応答は隣の ch と −3 dB で交わり、|Δ| ≧ 1 ch で −54 dB。窓は 2 / ADC × 4 ADC = 8 本が同時に動き、すべて DSP ドメイン 256 MHz。

PFB はどちらも「多相の重み付き和（多相フィルタ）＋ DFT」の 2 段でできている。粗い PFB（pfb_core、proj013 から）は 4096 MSPS の帯域を 128 MHz 間隔の 32 ch に分けるもので、分岐の和（96 タップ = 3 × 32）の後の 32 点の実 DFT を中に持つ（16 点の複素 DFT dft16f ＋ 実数化。窓ごとに 1 ch だけ取り出す）。精細 PFB（wspec_core、proj020）は 4 タップ × 4096 の重み付き和で、DFT の段は既存の FFT 4096 点の IP がそのまま担う。proj017 は重み付き和が無い（＝矩形の窓）FFT だけの分光だった。この資料で「精細 PFB」と書いた箱は前段の重み付き和を指し、FFT と合わせて 1 つの PFB になる。

1. 溜め: 5 面のリング wspec_core · URAM proj020

FFT の IP は入力の途切れを待たずに進む（proj011）ので、途切れながら来る z をフレーム単位で溜め、溜まったら 4096 クロック途切れずに読み出す。proj017 は 2 面だったが、proj020 では 5 面のリングにして精細 PFB の履歴を兼ねる。フレーム f は面 f mod 5 に書く。フレーム r が溜まったら、面 r − 3 … r の 4 面を同じ番地 a で読み、その間に 5 面目へ次のフレームを書く。

  • 記憶は URAM（4K × 72）。rev1 は詰めずに 1 面 1 個 = 5 / 窓、全体で 16 → 56 / 80。proj017 の溜めの BRAM 8 / 窓は空く
  • 次のフレームが溜まるには 4096 クロック以上かかる（z は 1 / クロック以下）ので、読み出しは必ず間に合う。書き込みが未読の番地に追いついたら FLAGS[1]
  • WRST の後の最初の 3 フレームは履歴が埋まっていない。r − 3 + t < 0 のタップは 0 にする（面に前の走りの値が残っていても混ぜない）。出力は模型に「前に 0 を詰めた z」を与えたものと bit 単位で同じ

2. 精細 PFB の前段: 4 タップの重み付き和 wspec_core 読みの段 P0 … P7 proj020

同じ番地 a の 4 フレームぶんの z に係数を掛けて足し、FFT の入力 y を作る。番地ごとの実係数の積和なので、FFT の前の「4 フレーム長の窓関数」と同じことを、フレームの重なりで実現している。出力フレームの番号は最新の入力フレーム r で呼ぶ。

y_r[a] = sat18( ( Σ_{t=0..3} c[a + 4096t] · z_{r−3+t}[a] + 2^15 ) >> 16 ) re・im を別々に c[n] = round( h[n] · 2^16 )、18 bit 符号付き（最大 78288 ≒ 1.19、最小 −7682） h[n] = sinc( 1.198 · (n − 8191.5) / 4096 ) · kaiser(16384, β = 5)、Σh² = 4096 に規格化

原型の決め方（F）

  • bw 1.198: 0.5 ch で −3 dB になる幅。隣の ch と −3 dB で交わるので、全 ch の電力の和がほぼ一定（波打ち 0.08 dB）
  • β 5: bw を合わせたうえで |Δ| ≧ 1 ch の最大が最も深くなる値（T = 4 で −53.7 dB）
  • Σh² = 4096: 白色の z に対し y の分散 = z の分散。雑音の電力を保つので、proj019 の abs の式と「窓の和 = TP」がそのまま使える
  • 係数の正は model/pfb4.py → model/pfb4_coef.txt（gen で src/sam45fine/pfb4_rom.v）

段の中身

  • P0 番地と有効の印 → P1 面と ROM を読む → P2 出力レジスタ
  • P3 タップ t の面 = rbk + 2 + t（mod 5）を選ぶ。無効なタップは 0
  • P4 積 18 × 18 を 4 タップ × re・im = 8 DSP
  • P5 2 つずつ足す → P6 和と丸めの定数 → P7 右へ 16・18 bit で飽和（FLAGS[5]）
  • 係数 ROM は 2 本（タップ 0・1）× 2 ポート。左右対称なので、ポート B（番地 4095 − a）がタップ 3・2 を出す
  • 段は自走。出口を深さ 16 の FIFO に入れ、IP の tready とは FIFO の後ろで握手する（tready を段全体に配らない。-1 のファンアウト対策）

3. FFT 4096 点（精細 PFB の DFT 段） Xilinx FFT IP（realtime）

Y_r[b] = Σ_{a=0..4095} y_r[a] · exp(−j2π ab / 4096) 順変換・unscaled・自然順、出力 31 bit（18 + 12 + 1）
  • 入力は精細 PFB の FIFO から AXI の握手で入れる。待たされても 1 語も落とさないので、IP のフレームの枠 = 溜めの枠がいつも保たれる（proj014 rev2 の教訓）
  • 見張り: FLAGS[0] XK_INDEX の飛び、[2] IP の TLAST 事象、[3] 入力の途切れ、[4] IP に待たされた
  • スナップショットは精細 PFB の出口 y（= FFT の入力）を残す。PS の --golden（スナップショットを numpy で FFT した電力 = N_ACC 1 のダンプ）は proj017 のまま使え、PFB の bit 単位の照合も sim でスナップショットに対して取れる

4. 電力と積分 wspec_core S1 … S5

q = sat18( Y >>> SHIFT ) SHIFT は RUN で取り込む p = q_re² + q_im² 37 bit P_k[b] = Σ p を N_ACC フレーム 64 bit、2 面（ダンプごとに交互）
  • RUN を受けたら F0 = (⌊fin / M⌋ + 2)·M から積む（時刻の格子 G = 219 ビート = 2.048 ms に切り上げ、M = G / L フレーム。proj017）
  • フレーム F0 + k·N_ACC … F0 + k·N_ACC + N_ACC − 1 をダンプ k に積む。ダンプが閉じるたびに SEQ が 1 増える（PS は SEQ → 中身 → SEQ の seqlock で読む）
  • 同じ ch は 4096 クロックおきにしか来ないので、読み書きの追い越しは起きない

5. PS 側 specd・window.py

  • AXI で 4096 ch × 64 bit を読む。並べ替え（fftshift）とゾーン 2 の反転（IF = 4096 − c − ν）は PS で行う
  • 単位（proj019、変えない）: abs = (ΣP / N_ACC − 2/3) · 4SHIFT · 44−G / 231（14 bit の LSB²）。Σh² = 4096 で雑音の電力を保つので、精細 PFB を入れても式は同じ
  • F は ENBW 1.010 なので、ch の中心の CW の山は矩形とほぼ同じ（−0.04 dB）。rev1 案で見込む必要があった +1.1 dB はなくなった

6. 時刻の扱い

出力フレーム r は入力フレーム r − 3 … r を重みつきで含む。フレームの番号は最新の入力で呼ぶので DUMP_T・F0・X(NS) の意味は proj017 と同じだが、ダンプの区切りの重心は矩形より 1.5·L 前にある。幅の違う窓どうしでは、区切りの重心がこの差だけずれる。
