# proj008 — 1PPS を ADC に常時入れる構成（エポックごとの較正器）

日付: 2026-09-18
状態: **進行中**

## 目的

**較正定数を事前に測って持つのをやめ、その場で測る器を常設する。**

proj007 で `L_adc − D_pps` は装置の定数ではなく**エポックごとの定数**だと決着した。
だとすれば、較正値を記録して持ち回る設計は成立しない。**1PPS を ADC のチャネルに
常時入れておけば、1 回のキャプチャ（53 µs）が N も k も δ もまとめて与える。**

proj008 ① の成果物はビットストリームではない。**「バッファの添字 i のサンプルは何時のものか」
を、エポックが変わっても人手を介さずに答えられる状態**である。

2 台でのボード間同期（10 MHz + 1PPS の分配）は **proj009 以降に回す**。

## proj007 との差

**RTL は proj007 rev2 から変えない。** proj007 のビットストリームは既に 4ch 構成
（`chans = {0 0} {0 2} {2 0} {2 2}`）で、`epoch` と `mmcm_locked` も出ている。
proj008 で足すのは **RF の配り方**と **PS 側のソフト層**の 2 つだけ。

| | proj007 | proj008 |
|---|---|---|
| RTL | — | **同一**（`MAGIC` の番号だけ `0x0008_0001` に進める）|
| PPS の入れ先 | `PPS Clk` ＋ 判定 4 のときだけ ADC_D | **`PPS Clk` ＋ ADC 4ch 全部**（構成 A）|
| 較正 | 人が `pps_delay.py` を叩いて読む | **`epoch` の変化を検出して自動で取り直す** |
| 出口 | 較正定数の数値 | **「添字 i は何時か」を返す層** |

`MAGIC` を進めるのは、RTL が同一でも**実機に載っているのがどちらの proj のビットストリームか**を
1 回の読み出しで言えるようにするため。番号が同じだと、取り違えても症状が出ない。

## 同期の 3 層のどこにいるか

proj006 で分けた 3 層のうち ③ を **運用できる形にする**のが proj008 ①。

| 層 | 揃えるもの | 手段 | 状態 |
|---|---|---|---|
| ① 周波数 | fs の確度とボード間コヒーレンス | 外部 10 MHz → CLK_IN | **proj004 で完了**（−0.015 ppm）|
| ② サンプル位相 | タイル間 / ボード間のサンプル境界 | SYSREF / MTS | **proj006 で決着**（MTS 不要）|
| ③ 絶対時刻 | エポック、積分窓の開始 | 1PPS | proj007 で**成立**／proj008 で**常設化** ← ここ |

## 構成

### 構成 A — 較正器の特性把握（proj008 ① の本題）

**4ch すべてに同じ 1PPS を入れる。** 科学信号は取らない。**特性把握のための構成であり、
運用形ではない。**

```
1PPS ─┬─(2分配 −3 dB)──────────────────────▶ PPS Clk  （コンパレータ／シュミットトリガ）
      └─(2分配 −3 dB)─ 4分配(−6 dB) ─┬─(減衰)─▶ ADC_A   ch3
                                      ├─(減衰)─▶ ADC_B   ch2
                                      ├─(減衰)─▶ ADC_C   ch1
                                      └─(減衰)─▶ ADC_D   ch0
```

**段を分ける理由。** proj007 で受かった実績は「2 分配（−3 dB）で +2.5 V の 1PPS」である。
5 分配にすると `PPS Clk` 側が −7 dB まで落ちる。**コンパレータの閾値は RefMan に記載が無く
未文書なので、受かるかどうかは実測でしか分からない。** 段を分ければ `PPS Clk` 側は
proj007 と同じレベルのままで、変更点が ADC 側だけになる。

**ADC 側の分配損はコストではない。** 0 dBFS ≒ +5.8 dBm に対して TTL レベルの PPS は
どのみち 20 dB 級の減衰が要るので、分配の −9 dB は減衰器の置き換えになるだけである。

**4 本のケーブルは同じ長さ・同じ種類で揃える。** 揃っていれば ch 間の差はケーブルに
由来しない。揃えられない場合は長さを記録する（proj007 の実測で **1 ns ≒ 25 cm**、短縮率 0.85）。

### 構成 B — 運用形（proj008 ① の出口で決める）

科学チャネルを何本残せるかは、構成 A の測定結果で決まる。**先に決めない。**

| 案 | 科学 ch | 成立条件 |
|---|---|---|
| PPS 1 本（ADC_D）| 3 | **タイルをまたいでも 1 本で較正できること** |
| PPS 2 本（ADC_D と ADC_B）| 2 | タイル内は 1 本で足りること |

proj006 の実測（**タイル内は 0.02 サンプル以内で不変、タイル間は 1〜1.5 サンプル RMS で
起動ごとに変わる**）を素直に読めば **2 本案**になる。だが proj006 が測ったのは CW トーンの
位相であって、PPS のエッジではない。**別の量かもしれないので、測ってから決める。**

## 設計

### 1. 4ch を 1 キャプチャで同時に読む

512 bit 語に 4ch すべてが入っている。**追加のキャプチャは要らない。**

| ch（512bit 語。ch0 が最下位）| SMA | Tile / slice | `blocks[]` |
|---|---|---|---|
| 0 | ADC_D | 224 / 0 | `adc_tiles[0].blocks[0]` |
| 1 | ADC_C | 224 / 2 | `adc_tiles[0].blocks[1]` |
| 2 | ADC_B | 226 / 0 | `adc_tiles[2].blocks[0]` |
| 3 | ADC_A | 226 / 2 | `adc_tiles[2].blocks[1]` |

**1 キャプチャが 4 つの独立な測定になる。** これは対照が構成に組み込まれている状態で、
proj006 で「対照を並べていたから偽陽性だと分かった」のと同じ形である。

**Tile 224 と Tile 226 は入力極性が反転している**（proj006 で確定・厳密な 180°・周波数非依存）。
**PPS のエッジのスパイクは ch0/ch1 と ch2/ch3 で符号が逆に出る。**

**エッジ探索は壊れない。** `find_edge` は `np.abs()` を取ってから探すので、
極性が反転しても同じ位置を返す（`sim/test_analysis.py` で検証済み）。
むしろ **ピークの符号が無料の対照になる** — タイルで符号が分かれなければ、
配線か ch の対応表を疑う。`pps_delay.py` は符号を毎回表示する。

### 2. 較正の式

proj007 で確定した形をそのまま使う。

```
L_adc − D_pps = N(epoch) × 6.5104 ns + frac(overlay)
```

| | 動くもの | 測り直しの契機 |
|---|---|---|
| タイル再起動（同じ Overlay 内）| **整数ビート N だけ** | `epoch` の増加 |
| Overlay の焼き直し | **N も k も δ も** | Overlay のロード |

**実務では区別しなくてよい。** 1 キャプチャが N も k も δ もまとめて与えるので、
「エポックが変わったら測り直す」の一手で足りる。`epoch` はその瞬間を教える印である。

### 3. ch 間の差は試行ごとに対にする

**4ch は同じキャプチャの同じ PL スタンプから出ている。** したがって

- ビート量子化の固定バイアス（0〜6.51 ns。proj007 で「回数を増やしても消えない」と書いたもの）
- ±1 ビートのディザ
- PPS そのもののジッタ

は**すべて共通項として引き算で消える**。個々の ch の σ で差の誤差を見積もると、
**実際より 1 桁悪く見える。**

**判定 3 / 4 は絶対値ではなく差で見る。** これは 4ch 同時取得にした副産物だが、
副産物のほうが大きいかもしれない — proj007 が「量子化の下限は 6.51 ns で、
これは回数を増やしても消えない」と正直に書いた壁が、**差については存在しない。**

### 4. ±1 ビートのディザを潰さない

proj007 で 4 回中 2 回、±1 ビートちょうどのディザが出た。**素朴な平均は 2 つの山の間に落ちて、
どちらの山にも対応しない値を返す。** しかも σ が膨らむので「精度が悪い」ように見えるが、
実際の精度は 0.2 ns である。

`pps_delay.py` の `beat_summary()`（中央値からのビート単位のずれで分類し、多数派の山だけを返す）を
**ch ごとに掛ける。** 4ch をまとめて平均しない。

**ディザの有無はそのエポックの位相が良いかの指標になる**ので、抑えずに記録する。

### 5. 時刻を返す層

```
t(i) = t_epoch_base + (beat_start × 8 + i) × T_sample + (L_adc − D_pps)
```

呼ぶ側が意識するのは `t(i)` だけ。`epoch` の監視と再較正は層の内側に隠す。

- `epoch` を読み、**前回の較正時と変わっていたら較正を取り直す**
- 較正を取り直せない状態（`pps_alive` = 0）なら、**古い較正で黙って答えない。**
  時刻に「較正がどのエポックのものか」を添えて返し、不一致なら例外にする
- `mmcm_locked` = 0 は較正の失効と同じ扱い

**「答えを返さない」を実装すること。** proj007 で踏んだ穴の大半は「動いているように見える」形
だった。較正が失効したまま尤もらしい時刻を返す層は、同じ形の失敗になる。

## 決めたこと

- **決定**: proj008 ① では **RTL を変更しない**
  **理由**: proj007 rev2 の 4ch 構成と `epoch` / `mmcm_locked` で必要なものは揃っている。
  RTL を触ると「ソフト層の問題か RTL の問題か」の切り分けが増える。
  **`MAGIC` の番号だけは進める** — 実機に載っている版を 1 読みで言えなくなるため
  **見送った案**: PPS 欠落の sticky 記録（最大 `pps_interval`、欠落回数）を RTL に足す案。
  長時間監視のポーリング間隔を緩められるが、**持続性検証で実際に欠落が出てから入れる**

- **決定**: 較正専用の構成 A と運用形の構成 B を**分ける**
  **理由**: 4ch 全部に PPS を入れる構成では科学信号が取れない。これは**特性把握のための
  構成**であって運用形ではない。混同すると「較正のために科学 ch を 4 本潰す」設計に見える
  **狙い**: 構成 A の測定が、そのまま構成 B の割り当て（PPS 何本か）の根拠になる

- **決定**: 分配は**段を分ける**（`PPS Clk` へ −3 dB、ADC 側へ −3 −6 dB）
  **理由**: `PPS Clk` 側を proj007 で受かった実績と同じレベルに保つ。コンパレータの閾値が
  未文書なので、**分配を増やした結果として判定 1 が落ちると、原因がレベルなのか別の要因なのか
  切り分けに戻る**
  **見送った案**: 5 分配を 1 段で作る案。配線は簡単だが `PPS Clk` が −7 dB になる

- **決定**: 4ch のエッジ位置は **ch ごとに `beat_summary()` を掛ける**。まとめて平均しない
  **理由**: proj006 の「位相の巻き戻る量に算術平均を使って誤判定を出しかけた」、
  proj007 の「±1 ビートのディザを素朴な平均が潰した」と同じ形。**壊れた統計は
  壊れたこと自体を隠す**

- **決定**: 解析側の判定の分岐を **`make sim` で通す**（`sim/test_analysis.py`）
  **理由**: proj008 の結論を出すのは `epoch_verdict` の分岐だが、これは実機でしか通らない。
  放っておくと**一度も走ったことのないコードが結論を印字する**。
  proj007 で踏んだ 8 件はすべて「動いているように見える」形だった
  **効いた**: 書いた直後のテストで、`epoch_verdict` が numpy の `bool_` を返していて
  `is True` に一致しない件が出た。**値は正しいので実機では気づけない種類の誤り**である

## 成功の判定

| | 判定 | 通す条件 |
|---|---|---|
| 1 | **5 分配しても `PPS Clk` が受かる** | `pps_count` が毎秒 1 増え、glitch 0。TRIG / COMP の両経路 |
| 2 | **4ch 同時に PPS のエッジが読める** | 1 キャプチャで 4ch とも SNR が十分。**極性の符号を含めて**エッジ位置が出る |
| 3 | **同一タイル内の 2ch が 0.02 サンプル以内で揃う** | proj006 を**別の方法で再現**する。外れたら測定系を疑う |
| 4 | **タイル間のずれが 1 キャプチャで測れる** | proj006 の 1〜1.5 サンプル RMS と同じ桁に出るか、出ないかをはっきりさせる |
| 5 | **`epoch` を変えて自動再較正が働く** | `--epoch-test` で原点を作り直し、**人手なしで**較正が追随する |
| 6 | **数時間の持続性** | `epoch` が変わらない／PPS 残差がフラット／`mmcm_locked` = 1 のまま／開始と終了の較正が一致 |

**3 と 4 が本題である。** ここで構成 B の割り当てが決まる。1 と 2 はそのための道具。

**判定 3 は予言である。** proj006 は CW トーンの位相で測り、proj008 は PPS のエッジで測る。
**まったく違う方法で同じ量を測るので、一致すれば両方信用できる。** 外れた場合、
どちらが間違っているかはこの判定だけでは決まらない — それも結果として記録する。

## 着手条件

- **2 分配器 ×1、4 分配器 ×1**（または 2 分配器 ×3 で代用）
- **同じ長さ・同じ種類の SMA ケーブル 4 本**（揃えられない場合は長さを記録する）
- 減衰器（ADC 入力換算で 0 dBFS を超えないこと。**減衰量を記録する** — proj005 の規約）
- 45m の 1PPS（配線済み）と外部 10 MHz

## 再現手順

### ビルド（Vivado サーバ）

```bash
make sim        # tb 2 本 + 解析側のテスト。**Vivado もライセンスも要らない**
make sim-analysis   # 解析側だけ。**Mac 上でも走る**（numpy だけ）
make            # 合成〜ビットストリーム（build/proj008.bit と .hwh）
make timing-check   # 速度グレード -1 で閉じるか（build-1-e/ に出る）
```

**RTL は proj007 rev2 と同一なので、ビルドの結果も同じになるはず。**
WNS が proj007 の +0.235 ns から動いたら、それ自体が異常の印である。

### 実機（PYNQ v3.1.1）

```bash
scp build/proj008.bit build/proj008.hwh pynq/*.py xilinx@<board>:~/proj008/
ssh xilinx@<board>
cd ~/proj008

# 判定 1 — 5 分配しても受かるか。ここが通らなければ先へ進まない
sudo -E $(which python3) pps.py --probe --clkin 0

# 判定 2〜4 — 4ch 同時の較正
sudo -E $(which python3) pps_delay.py --ch all --trials 10 --clkin 0 --atten-db <実測値>

# 判定 5 — epoch を変えて自動再較正が働くか
sudo -E $(which python3) pps_delay.py --ch all --epochs 5 --trials 5 --clkin 0

# 判定 6 — 持続性
sudo -E $(which python3) pps.py --watch 21600 --clkin 0
```
