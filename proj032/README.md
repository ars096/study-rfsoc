# proj032 — SpW8 の性能仕様: 窓の数をできるだけ増やす（RTL の前に、見積もりと模型で）

日付: 2026-10-27
状態: 進行中（仕様を詰める段）

着手の前に [`../LESSONS.md`](../LESSONS.md) を全部読む（知見の全部は [`../docs/lessons_all.md`](../docs/lessons_all.md)）。

## 目的

YATSUGATAKE の SpW8（今の表は 4 ADC × 8 窓、幅 128〜8 MHz、4096 点、dt 10.24 ms。YATSUGATAKE `docs/spec/bits.md`）の性能仕様を、
**窓の数をできるだけ増やす**方向で決め直す。proj028（2 段の分光・PL DDR4）、proj030（DSP の節約・VCCINT）、proj031（係数の共有）の知見を使う。
RTL には入らず、**何が窓の数の壁になるか**を数で示してから仕様を決める。仕様の変更は YATSUGATAKE の bits.md に PR で入れる（ADR 0021）。

## 出発点（分かっていること）

### 今の窓の作り方（SAM45-Fine、proj015〜017・021）

ADC ごとに粗い PFB（`pfb_core`、共有）→ 窓ごとに DDC（`ddc_core`: NCO ＋ 半帯域 7 段 ＋ final）→ 窓の PFB T = 4 ＋ FFT 4096 点 ＋ 積分（`wspec_core`）。
**窓の部品は窓ごとに 1 組あり、時分割しない**（ddc の中の light 2〜7 段目だけ時分割、proj015 手順 2）。

### 窓 1 つの値段（YATSUGATAKE `docs/knowledge/resources.md`、SAM45-Fine の配置後の内訳）

| | DSP | BRAM | URAM |
|---|---|---|---|
| 粗い PFB（ADC ごとに 1 つ、窓に依らない） | 272 / ADC（4 ADC で 1,088） | 0 | 0 |
| 窓 1 つ | **≒ 118**（DDC 72・FFT 30・窓の PFB ほか 12・実数化 4） | **23**（FFT 15・NCO 4・窓の PFB の係数 4） | **7**（窓の PFB の履歴 5 面・積分器） |

- **今の形のまま窓を増やすと、壁は URAM**: 7 / 窓で 80 なら 11 窓ほど。SpW8 の 32 窓は URAM 224 で**入らない**。DSP も 32 × 118 ＋ 1,088 ≒ 4,860（114 %）で入らない
- つまり今の表の SpW8 は、**作り方を変えないと作れない**

| proj031 | 係数を 1 組にして共有（PS が起動時に書き、PL が CRC で照らす） | 窓の PFB の係数・NCO の ROM（BRAM 8 / 窓）を窓の間で共有。**ただし SpW では URAM が壁なので、係数は BRAM に置く** |
| proj028 | 狭い帯域のデータは全速の部品を時分割で回せる（細かい側は 1 組の部品で 32 本の荒い ch を順に）。PL DDR4 は 4 GiB・同時 17.66 GB/s | 窓の DDC の後段・窓の PFB・FFT を、**窓の数ではなく窓の帯域の和**で数える形に（下の A）。DDR は窓の積分には帯域が足りない見込み（下の C） |

## 見積もりの枠組み（まだ予言。数は下の E で確かめる）

窓の資源を 2 つに分けて数える。

1. **速さに比例する部分**（DSP・LUT）: NCO・半帯域・final・窓の PFB の積和・FFT。256 MHz のクロックで 1 拍に 1 複素標本を処理する「窓の機関」1 組で、**帯域の和 256 MHz ぶんの窓**を順に回せる（8 MHz の窓なら 32 本、128 MHz の窓なら 2 本）
2. **窓の数 × 点数に比例する部分**（記憶）: 窓の PFB の履歴（T − 1 = 3 フレーム以上）・機関に渡す溜め（1 フレーム）・積分器（1 面、読み出しと次の積みを同時に: proj028 F-3 の形）

| 窓 1 つ（4096 点）の記憶 | bit | RAMB36 換算 | URAM 換算 |
|---|---|---|---|
| 履歴 3 フレーム × 36 bit | 442 k | 12 | 1.5（72 bit 幅に 2 フレーム詰め） |
| 溜め 1 フレーム × 36 bit | 147 k | 4 | 0.5 |
| 積分器 1 面 × 48 bit | 197 k | 6 | 1 |
| 計 | **≒ 786 k** | **≒ 22** | **≒ 3** |

チップの記憶は URAM 80（23.6 Mbit）＋ BRAM 1,080（39.8 Mbit）。FFT の IP・TP・RAW・リング・共有 ROM に BRAM ≒ 300 を引くと、窓に回せるのは ≒ 52 Mbit で、
**4096 点の窓は 4 ADC の合計で 48〜64 本（ADC ごとに 12〜16）が記憶の天井**（詰め方の損を 0〜25 % と置いた幅）。点数を 2048 にすれば ≒ 2 倍。

速さの側は、**ADC ごとの窓の帯域の和の上限 B_tot**（仕様の新しい項目）で決まる:

| B_tot / ADC | 窓の機関 / ADC | DSP の見当（4 ADC、粗い PFB 1,088 を含む） |
|---|---|---|
| 256 MHz | 1 | ≒ 1,560（37 %） |
| 512 MHz | 2 | ≒ 2,030（48 %） |
| 1,024 MHz | 4 | ≒ 2,980（70 %、VCCINT の目安を越える恐れ） |

（機関 1 組を今の窓 1 つの DSP ≒ 118 と置いた粗い数。時分割の切り替えの LUT は未見積もり）

出口の量: 窓の ch の総数を N_ch とすると、PL → PS は u64 で 8·N_ch / dt、ネットワークは float32 で 4·N_ch / dt。
N_ch = 262,144（64 窓 × 4096）だと 10.24 ms で PS 205 MB/s・ネットワーク 102 MB/s で、**PL の dt 10.24 ms は PS の取得（proj029 で 131,072 ch が 61 %）に入らない見込み** → dt 20.48 ms か取得を 2 プロセスに。

| P-2・P-3 | 窓の数・点数 | **4096 点に固定**。窓の数は記憶と DSP の天井まで |

| P-5 | ADC の数 | **4** |

### 幅の違う窓の同居（P-1 の補足）

できる。条件は 3 つ。

- **機関への詰め込み**: 幅は 2 のべき乗（128・64・32・16・8）で、機関 1 組は 256 MHz。2 のべき乗の大きさのものを大きい順に詰めると隙間なく詰まるので、**ADC ごとの和 ≦ B_tot なら、どの組み合わせでも機関の数 B_tot / 256 に収まる**（窓をどの機関に割り当てるかは PS が WRST のときに決める）
- **フレームの頭が重なる**: 時刻の格子（proj017 の F0）で全窓のフレームの頭は L の倍数にそろうので、8 MHz の窓 32 本が同じ瞬間に 1 フレームずつ出す。機関が順に片づける間（最長 L = 512 µs）、次のフレームが溜まり始める → **窓ごとに 1 フレーム余分の溜め**が要る（下の記憶の見積もりを直した。SAM45-Fine の履歴 5 面と同じ形）。格子をずらしてフレームの頭を散らす案は、ダンプの区切りの一致（bits.md）を崩すので採らない
- **realtime の FFT の IP は途切れなく流す**（LESSONS）: 片づけるフレームが無い拍は空のフレームで埋める（proj028 F-4 の形）。忙しさ 100 % ちょうども回るが、余裕を E で決める

### 見積もりの直し（同居を考えて分かったこと）

- **記憶**: 窓 1 つは履歴 4 フレーム（3 ＋ 待ちの 1）＋ 溜め 1 ＋ 積分器 1 面 ≒ **934 kbit**（RAMB36 換算 ≒ 26・URAM 換算 ≒ 3.5）。窓に回せる ≒ 52 Mbit から、**4 ADC の合計で 40〜56 窓（ADC ごとに 10〜14）**
- **DSP**: DDC の頭（NCO 8 ＋ 半帯域 1 段目 10 ＋ 実数化 4 ≒ 22）は粗い PFB の出口の全速（256 MS/s）で動くので、**窓の幅に依らず窓ごとに要り、時分割できない**。DSP ≒ 1,088（粗い PFB）＋ 22·N_win ＋ ≒ 96·(機関の数)。48 窓・機関 8 組で ≒ 2,900（68 %）で、VCCINT の目安を越える恐れ → **粗い PFB の ch を細かくして（proj028 の os 8/7・64 ch の形など）DDC の頭も遅い側に寄せるか**を E-2 で比べる
- **ネットワーク**: ボードの NIC の出口は今 ≒ 27 MB/s（proj021 C3、原因は未解決）で、予算は ≒ 18 MB/s。48 窓 × 4096 点の float32 は 1 ダンプ 786 KB で、**ネットワークの tint は 51.2 ms**（NIC の天井が外れて 1 GbE の 70 % ≒ 77 MB/s になれば 10.24 ms）
- **PS の取得**: 48 窓 × 4096 = 196,608 ch は 2G-1 の 1.5 倍。proj029 の 61 % から 1 プロセスで ≒ 92 % の見込み → **2 プロセスに分ける**（ADC 0・1 と 2・3 など）

### DSP の上限と DDR の併用（2026-10-27、開発者）

- **DSP は 80 % まで使ってよい**（proj027 は冷やし方を変えて VCCINT 43 A で 4 時間 41 分落ちなかった。今のファンの配置が運用の条件）
- 問い: 窓が狭いと DSP は余るはず。DSP を共用しつつ PL DDR4 を併用して、窓をもっと増やせないか

見積もり（予言）:

| | 案 A: 記憶は全部チップ内 | **案 D: 窓の PFB の履歴を DDR に** |
|---|---|---|
| チップ内の記憶 / 窓 | 934 kbit（履歴 4・溜め 1・積分器） | **≒ 200 kbit**（積分器だけ。DDR の書き・読みの溜めは機関ごとに共有） |
| DDR の量 | なし | 標本 1 個につき書き 1 ＋ 読み 4 フレーム。I/Q 8 bit で 10 B、16 bit で 20 B |
| 帯域の和の上限 | 512 MHz / ADC（機関 2 組） | **256 MHz / ADC**（8 bit で 10.2 GB/s = 実測 17.66 GB/s の 58 %）。16 bit だと 128 MHz / ADC |
| DSP（1,088 ＋ 22·N_win ＋ 96·機関） | 48 窓で ≒ 2,900（68 %） | 4 機関（384）で 80 % まで N_win ≦ **88** |
| 窓の数の壁 | 記憶: **40〜56** | DSP（DDC の頭 22 / 窓）: **≒ 88**（ADC ごとに 22） |

- 積分器を DDR に置く案は、スペクトルの値 1 個ごとに読み書き 16 B で、帯域に対して損（記憶は 2 割しか減らない）。採らない
- 案 D の壁は**窓ごとに全速で動く DDC の頭**。粗い PFB の ch を細かくして DDC の頭を時分割できれば、次の壁は帯域の和（8 MHz × 32 = 256 MHz / ADC で **128 窓**）
- 履歴を 8 bit にするのは proj028 M-2 の形（窓ごとの利得 → 8 bit、損失 0.03〜0.07 %、強い線の余裕 +58 dB）。窓の後の 8 bit で同じになるかは模型で確かめる
- DDR を足す値段: MIG で LUT ≒ 15,600・BRAM 25.5（proj028 S-1）。リセット中の ready と、止まりうる UI クロックの側に最初に読むものを置かない（LESSONS、proj028 S-2d）
- 128 窓 × 4096 = 524,288 ch は 2G-1 の 4 倍。PS は proj029 の 61 % から 10.24 ms で A53 ≒ 2.4 コアぶん（4 コアのうち。specd・送り出しも乗る）→ **3 プロセスで 10.24 ms を試し、足りなければ PL の dt 20.48 ms（2 プロセス）**。ネットワーク（今の ≒ 18 MB/s の予算）の tint は ≒ 123 ms

### LO の周波数を格子に限ると DDC は軽くなるか（2026-10-27、開発者の問い）

窓ごとに全速で動く DDC の頭 22 DSP の内訳（proj021 の `pfb_core`・`ddc_core`。粗い ch は間隔 128 MHz・4 倍オーバーサンプリングで 512 MS/s = 2 標本 / クロック）:
実数化 4（窓ごとに Z[k] と Z[16−k] を組む）・NCO 8（複素の積 × 2 標本）・light 1 段目 10（半帯域 15 タップ、512 → 256 MS/s）。

| 格子の取り方 | 消えるもの | 残るもの | 読み |
|---|---|---|---|
| (a) 窓の中心を fs_c/8 = 64 MHz の倍数に | NCO の積が ±1・±j・(±1 ± j)/√2 になり、定数倍は LUT で（DSP −8、NCO の ROM BRAM −4） | light 1 段目 10・実数化 4 | 64 MHz 刻みでは窓の置き場所として粗すぎる。細かい LO を後ろ（256 MS/s 以下）で掛け直すと、その積は時分割できる。**DSP 22 → ≒ 15** |
| (b) 窓の中心を窓の出力レートの倍数に（「間引いてから混ぜる」） | 間引いた後の LO が 1 になる（e^{−j2πk·D·m/D} = 1） | フィルタが複素の帯域通過になり、積が 2 倍 | 格子の点の全部を 1 つの FFT で同時に出せる = **これはポリフェーズのフィルタバンクそのもの**。窓ごとの頭が消える代わりに、共有の分光器（粗い PFB）を細かくすることになる |
| (c) 窓の中心を窓の ch の格子（W / 4096）の倍数に | 資源は減らない | — | 各窓の中心を**その窓の** ch 幅 df_w の倍数に置くと、幅の違う窓の ch の境が入れ子にそろう（df は 2 のべき乗倍）。利点: 偏波・ADC 間の平均を補間なしで・重ねた窓をつないで 1 本に・狭い窓の 2^k ch の和を広い窓の 1 ch と比べる。RTL は変えず PS が NCO の Δ を丸めるだけ（1.953 kHz = 512 MHz / 2^18 は 32 bit の Δ で正確に表せる）。P-7 で決める |

(b) の考え方を素直に使うと、**粗い PFB の ch 間隔を 128 → 64 MHz にし（4 倍オーバーサンプリングのまま、1 ch 256 MS/s = 1 標本 / クロック）**、窓の頭を半分の速さにするのが効く。

- 窓は幅 ≦ 128 MHz なので、64 MHz 間隔の ch の 1 本に必ず入る（ch の中心から ±32 MHz ＋ 窓の半幅 64 = ±96 MHz < ナイキスト ±128）。**窓の中心は今どおり任意**（細かい NCO は残すが 1 標本 / クロック）
- 窓の頭: NCO 4・light 1 段目 ≒ 5・実数化 ≒ 2 で **22 → ≒ 11 DSP / 窓**（予言、E-2 で数える）
- 粗い PFB: 分岐の和は 1 標本あたりのタップ数（T × オーバーサンプリング = 12）で決まり 192 のまま。DFT が 32 点 → 64 点（実）で、**272 → ≒ 360 / ADC**（予言、根拠が弱い。OOC で数える）
- 案 D（履歴を DDR）と合わせた DSP: 4 × 360 ＋ 384（機関 4 組）＋ 11·N_win ≦ 3,418 → **N_win ≦ 145**。**DSP の壁は帯域の和の壁（8 MHz × 32 × 4 ADC = 128 窓）の外に出る**
- 窓の数 22 / ADC での差し引き: 窓の頭 −242・粗い PFB ＋ 90 → **1 ADC で ≒ −150 DSP**

### 幅ごとの窓の数の見積もり（2026-10-27、予言）

1 本の bit の中で部品の数は固定なので、**ADC ごとの窓の頭の数 H・機関の数 E・履歴をチップ内に持つ枠の数 S** の組を選ぶことになる。
置いた数: 粗い PFB 360 / ADC・窓の頭 11・機関 96（どれも E-2 で数える前の予言）、DSP の上限 3,418（80 %）→ ADC ごとに 11·H ＋ 96·E ≦ 494。
DDR の道は ADC ごとに帯域の和 256 MHz（8 bit の履歴、DDR 10.2 GB/s）、チップ内の道は残りの機関ぶん。記憶はチップ内の窓 934 kbit・DDR の窓 200 kbit。

| ADC ごとの構成 | 128 MHz | 64 | 32 | 16 | 8 | DSP | チップ内の記憶（最悪） |
|---|---|---|---|---|---|---|---|
| α: H 32・E 1・S 0 | 2 | 4 | 8 | 16 | **32** | 3,232（76 %） | 25.6 Mbit |
| β: H 24・E 2・S 6 | 4 | 8 | 14 | **22** | 24 | 3,264（76 %） | 36.8 Mbit |
| γ: H 16・E 3・S 8 | 6 | **12** | **16** | 16 | 16 | 3,296（77 %） | 36.3 Mbit |
| 参考: 今の SpW8 の表 | 8 | 8 | 8 | 8 | 8 | （今の形では入らない） | |

- 4 ADC の合計は 4 倍。混ぜるときの条件（PS が SET で照らす）: 窓の数 ≦ H、帯域の和 ≦ 256·E MHz、DDR の道の 256 MHz を越えた分の窓の数 ≦ S
- 記憶の使える量は 39〜52 Mbit（詰め方の損 0〜25 %）なので、β・γ はその下の端に近い
- 窓の頭が 11 より重いと H が減る（15 なら α は H 26 前後）

### D-2: DDR の窓の道（書き手・読み手）と、選びの前倒し（2026-10-28）

**DDR の配置**: 窓（DDR の枠 k）ごとに 64 KiB = 区画 b（0..3、1024 標本）× フレーム f mod 8 × 2 KiB。番地 = base + k·64 KiB + b·16 KiB + f·2 KiB。
書きは区画ごとに 2 KiB を 1 本（D-1 で入ると分かった大きさ）、読みは区画ごとにタップ 4 本 × 2 KiB（区画 1 つで 8 KiB = D-1 の読みのバーストと同じ）。
8 フレームの輪なので、DDR の窓の締め切りは周期の 4 倍以上ある。

  履歴の書き込みの遅れを D = 1024（BRAM の輪）に。模型（`model/eng_sched.py` の run_lead、`runs/e4_sched.txt`）: 前倒し 960 でチップ内の窓の始まりの最悪は「着き ＋ 周期」の 179 クロック前、

### K-1: 閉じたダンプの流れの山と、受け手の溜め（模型、2026-10-28）

機関は、窓のダンプの区切りの最初のフレームの仕事で、前のダンプ 4096 ch を 1 語 / クロック（u64 で 2 GB/s）で流す。全窓の区切りが同じ格子にそろうので、
1 ADC の 3 機関が同じ枠に流しうる。受け手は ADC ごとに流れを溜め、PS の DDR（MIG の DDR とは別。履歴の道とは取り合わない）へ R で書き出す。
`model/dump_burst.py`（選びは eng と同じ・格子 B の前後 48 枠・窓の組は機関ごとに幅 ≦ 256 MHz・ADC で 14 本まで。乱数 3,000 組 ＋ 形を決めた 4 組）→ `runs/k1_burst.txt`:

| 1 ADC の溜めの最大 | R 2 GB/s | 3 GB/s | 4 GB/s |
|---|---|---|---|
| u64（8 B / ch） | 288 KiB | 208 KiB | 128 KiB |
| **f32（4 B / ch）** | **64 KiB** | 0 | 0 |

- 最悪は「同じ NS の窓 14 本を 3 機関に 5・5・4」（区切りの直後に 3 機関が 5 枠続けて流す）。理屈の上限 14·4096 語 × (1 − R / 3 語) と同じ形（u64 2 GB/s で 299 KiB）。
  同じ窓を 1 機関に寄せると山は 1 語 / クロックで、溜めは 0
- 4 ADC の区切りもそろうので、PS の DDR への書きの山は 4R（≒ 80 µs）。平均は 56 窓 × 16 KiB（f32）/ 10.24 ms ≒ 90 MB/s と小さい
- **u64 のままでは入らない**: 1 ADC 200〜300 KiB の溜めは、BRAM（81.6 %）にも残りの URAM（24 個 = 1 ADC 6 個 × 32 KiB = 192 KiB）にも入らない
- **f32 を PL で作る案**: 積分器の値（< 2^53）を f32 に最近接・偶数で丸めると、今の PS（proj029 の C: u64 → double → float）と bit 単位で同じ値になる（< 2^53 は double が厳密）。
  受け手の溜めは 1/4 以下、PS は u64 → f32 の変換が要らなくなる（proj029 の C の記録は、CRC を除く大半が変換と逆順の読み。逆順も PL で書く番地を逆にすれば消える）。ネットワークは今も f32
- 溜めの形の案: 機関ごとに URAM 1 つ（2 ch を 64 bit の語にした FIFO、32 KiB = ダンプ 2 つ）。書き出しはレコード（ダンプ 1 つ = 頭 ＋ 16 KiB ＋ 尾、s45_ring の形）単位で機関を順番に。
  機関 1 つは 1 GB/s で最大 5 ダンプ続けて流すので、R 2 GB/s（機関あたり 0.67 GB/s）で溜めの山は ≒ 27 KiB < 32 KiB。URAM は 56 → 68（85 %）
- 要る実測（D-3）: **PL から PS の DDR へ、HP の口 4 本（ADC ごと）で同時に 2 GB/s ずつ書けるか**。足りなければ機関ごとの URAM を 2 つに（URAM 80 = 100 %）

### D-3: PL から PS の DDR へ HP の口 4 本で同時に書く（実機、2026-10-28 着手）

決めた（2026-10-28）: **PL → PS は f32**（K-1 の案。INTERFACE の u64 を変える）。受け手の溜めの大きさを決めるため、口の速さを実機で測る。

`d3/`（D-1 の形の自己完結のビルド。RFDC・MIG なし）: PS（HP0..3_FPD を 128 bit）＋ clk_wiz（pl_clk0 → clk_dsp 256 MHz = 本番の DSP のクロック）＋ `hp_tg` × 4 ＋ clk_mon。
- `hp_tg`（ID 0x0320_0D31）: 受け手の溜めを真似る。溜めに RATE で拍が入り（ON・PERIOD でダンプの山の形に）、BL ＋ 1 拍揃ったら AW を出して W を続けて出す。
  **溜めの最大（BACKLOG_MAX）= その速さの流れを受けるのに要る溜め**。数えは DUR の中だけ、B の待ちの最大も
- sim（`make -C d3 sim-hptg`）: T1 速い口で番地・データ・速さ 0.500 拍 / クロック・溜め 17 拍、T2 山の形（0.75 拍 × 4096 クロックを 0.5 拍の口で）の溜め 1,051 拍（予言 1,024）、
  T3 天井 0.500。全拍の番地とデータが式どおり。陽性対照（模型がデータを化けさせる）は落ちた
- 道具 `d3/pynq/hp_bw.py`: T0 中身（PS で全拍を照らす）・T1 1 本の天井・T2 4 本の天井・**T3 本番 2 GB/s × 4（合否）**・**T4 ダンプの山（3.07 GB/s × 74.7 µs を 10.24 ms ごと、合否 溜め ≦ 96 KiB）**・T5 余裕
- 予言: PS の DDR4 は **DDR4-1600・64 bit で天井 12.8 GB/s**（build.tcl の読み返し。PL の DDR より遅い）。T3 の合計 8.2 GB/s は天井の 64 % で通過、T2 の 4 本の天井は 9〜11 GB/s、T4 の溜めは 64 KiB 前後

**D-3 の結果（2026-10-28、実機。.bit `d3/build/proj032d3.bit` sha256 68bb841c…、WNS +0.407 ns・CRITICAL WARNING 0・結線の照合 0）**:
clk_mon で clk_dsp 256.000 MHz・locked を確かめてから hp_tg に触った。T0 の中身は 4 本とも全拍が式どおり、BRESP は全部の運転で 0。
`runs/d3_hp_bw_1.txt`（PS は静か）・`d3_hp_bw_hog1.txt`（CPU 1 コアが 64 MiB の memcpy を回し続ける、3.9 GB/s）・`d3_hp_bw_hog.txt`（3 コア、合計 7.6 GB/s）:

| 運転（4 本同時、口ごと GB/s: HP0・HP1・HP2・HP3） | PS は静か | CPU memcpy 1 コア | 3 コア |
|---|---|---|---|
| T2 上限なし（BL 64） | 4.10・2.82・2.82・4.10 = **13.8** | 2.96・1.48・1.48・2.96 = 8.9 | 1.85・0.92・0.92・1.85 = 5.5 |
| T3 本番 2 GB/s × 4 | ○（溜め 4.7 KiB） | ○（52 KiB） | × |
| **T4 ダンプの山 3.07 GB/s × 74.7 µs、要る溜め** | **3.3 KiB** | **77 KiB** | 165 KiB |
| T5 2.5・3.0・3.5 GB/s × 4 | ○・○・×（HP1・2 が 3.07） | ○・×・× | × |

- **PS が静かなら、口は山（3.07 GB/s）より速く、溜めはほぼ要らない**。1 本の天井は 4.096 GB/s（= 128 bit × 256 MHz、口の上限）
- **予言の外れ: 4 本の天井 13.8 GB/s は、読み返した DDR4-1600 の天井 12.8 GB/s を越えた**。PS の DDR の設定は .bit ではなくブートの側（FSBL）で決まり、
  build.tcl の読み返しの値は実機の DDR を表していない（速さは未確認。少なくとも 1600 より速い）
- **HP1 と HP2 は半分**（混むと HP0・HP3 の半分ずつ）: DDR の口を 2 本で分け合う形（HP0・HP3 はそれぞれ自分の口）。ADC と口の割り当てでは、HP1・2 の 2 本が先に詰まる
- **CPU がメモリを使うと、PL の書きは押し負ける**: memcpy 1 コア（3.9 GB/s）で山の溜めは 77 KiB、3 コアで 165 KiB（HP1・2 が 0.9 GB/s）
- 受け手の溜め: **機関ごとに URAM 1 つ（ADC ごとに 96 KiB）なら、CPU 1 コアの全力の memcpy まで受ける**（77 KiB）。取得のプロセス（proj029: リングを読んで f32 を送る、数百 MB/s）はこれより軽い。
  溜めが溢れるときはダンプを丸ごと捨てて数える（s45_ring と同じ）。それ以上の守りは、DDR の口の QoS（HP の口を優先）を後で試す余地
- **K-1 の f32 は要る**: u64 の山は 6.1 GB/s / ADC で、口 1 本の上限 4.1 GB/s を PS が静かでも越える

### K-2: ダンプの受け手（dsink）とリング（ring128）の RTL（2026-10-28）

**溜めの模型**（`model/dump_burst.py k2` → `runs/k2_sink.txt`）: 機関ごとの溜め（FIFO）から、ダンプを 1 つずつレコードにして機関の順番で書き出す。機関ごとの溜めの最大:

| 書き出し | ダンプが揃ってから選ぶ | 流れ始めたら選ぶ |
|---|---|---|
| 4.1 GB/s | 23.8 KiB | 19.8 KiB |
| 3.07 GB/s | 26.8 KiB | 21.5 KiB |
| 2.05 GB/s | 40.2 KiB | 32.2 KiB |
| 1.02 GB/s | 64.0 KiB | 48.6 KiB |

- 流れ始めたら選ぶ形にした（溜めが小さい）。書き出しが 2 GB/s を割ると、URAM 1 つ（32 KiB）/ 機関では足りない。
  **s45_ring の入口は 64 bit（2.05 GB/s）なので、入口を 128 bit にした ring128 を作った**
- PS のメモリの側で HP の口を優先させる手（DDR の口の QoS）は、Linux から AFI・DDRC のレジスタを読もうとしてバスエラー（ボードは無事）。今は追わない

**RTL**:
- `src/spw/f32cv.v`: u64 → f32（最近接・偶数）を 3 段で。`sim/check_f32cv.py`: 端の値と乱数 20,000 個（2^53 以上 4,443）で不一致 0。
  陽性対照（入力 1 個を 3 → 2）は落ちた（1 回目は大きな値の最下位を変えて、丸めで消えて落ちなかった）
- `src/spw/dsink.v`（ADC ごと）: 機関ごとに f32cv → f32 を 2·NU 個ずつ語に束ねて溜め（URAM NU 個、4096 語）へ。ダンプの頭で 1 ダンプぶんの空きが無ければ丸ごと捨てて数える（書き始めたダンプは欠けない）。
  頭が溜めに入ったダンプを機関の順番に選び、頭 4 拍 ＋ 本体 1,024 拍（128 bit）のレコードを出す（本体がまだ書かれていなければ待つ）
- `src/spw/ring128.v`: s45_ring を写して入口を 128 bit の 1 本に。CRC-32 は 128 bit / クロック（`tools/crc128_masks.py` が zlib.crc32 と照らして係数を作る）、
  尾の拍 0 に CRC が入るので最後の拍から 2 クロック待つ、バーストは ≦ 64 拍（1 KiB の境）、受け手で捨てた数を DROP_CNT と EXT_CNT（0x30）に
- レコードの頭（INTERFACE 4.4 の形）: type 5（SpW の窓）・s = 窓・core = ADC・SEQ（受け手ごと）・DUMP_K・log2 NFFT 12・NS・SHIFT・G・**fmt 1（f32）**・DUMP_N・本体 16,384 バイト。
  **DUMP_F0・DUMP_T はまだ 0**（時刻の道は PS のレジスタの設計で）。中身は FFT の ch の順（今と同じ。PS が並べ替える）

**sim**（tb_wsb に dsink → ring128 → PS の DDR の模型をつなぎ、PS の役が 20,000 クロックごとに [R, W) を写して R を進める。`sim/check_ring.py` がレコードの並び・頭の欄・尾・SEQ・CRC（zlib）・本体（流れの u64 を float32(float64(u)) にしたもの）を照らす）:

| 構成 | 既存の照合（check_wsb） | リング |
|---|---|---|
| CFG 2・TB_S 1 | 通過 | レコード 4・全部一致 |
| CFG 0・TB_S 14 | 通過 | レコード 28（PAD 1 = リングの端の折り返し）・全部一致 |
| CFG 0・TB_S 6（DDR の窓 8） | 通過 | 28・全部一致 |
| CFG 1・TB_S 6 | 通過 | 28・全部一致 |
| CFG 0・TB_S 14・NU 1 | 通過 | 28・全部一致 |

- 1 回目の照合は 2 つの tb の不具合で落ちた: 流れの記録だけ先に閉じた（入口の記録と長さが合わない）・PS のメモリの模型が AW より先の W を番地なしで捨てた（AXI では W が先に来てよい）
- 陽性対照（+HP_SLOW、PS のメモリの wready 3 % = 0.03 拍 / クロック < ダンプの平均）: **受け手が 20 ダンプを捨て（EXT_CNT = DROP_CNT = 20、sflags[2]）、届いた 18 レコードは全部一致**（欠けたダンプは丸ごと、レコードは壊れない）。
  12 % では平均が追いつき、捨てなかった
- 照合の陽性対照: リングの記録の本体の 1 バイトを化けさせると、CRC と本体の不一致の 2 件で落ちた

**OOC**（`src/spw/ksink_ooc.v` = dsink ＋ ring128、配置後）: NU 2 は DSP 0・LUT 3,137・FF 3,922・BRAM 2・**URAM 6**・WNS +0.576 ns、NU 1 は LUT 3,109・**URAM 3**・WNS +0.686 ns。
LUT の内訳は f32cv 300 × 3・ring128 1,458（CRC の XOR の木を含む）。
**見積もり（`tools/estimate.py --H 14 --S 6 --nco-p 12`）: LUT 80.5 → 83.5 %・BRAM 81.6 → 82.3 %・URAM 100 %（NU 2）/ 85 %（NU 1）**

**決めた（2026-10-28）: 受け手の溜めはまず NU 2（URAM 2 / 機関、URAM 100 %）**。書き出しが 1 GB/s まで落ちても捨てない。全体で入らなければ NU 1（85 %）に下げる

**変更案（INTERFACE、YATSUGATAKE に入れるとき）**: 4.4 のレコードに type 5（SpW の窓、s = 窓の番号）と fmt 1（f32、PL が丸めた値。u64 → double → float と同じ）を足す。リングは ADC ごとに 1 つ（HP の口 1 本ずつ）。
**4.5 の決定「リングの中は常に u64 の生の積分値。PL は切らない・丸めない」を SpW では改めることになる**（理由: u64 の山は口 1 本の上限 4.1 GB/s を越える、K-1・D-3）。4.5 の「照合は試験の命令で（u64 と f32 の両方）」は、SpW では PL の丸めと PS の丸めが同じ値になることの照合（sim の check_ring）に置き換わる

### R-1: PS のレジスタとレコードの時刻（案、2026-10-28）

正典（YATSUGATAKE の docs/spec/interface.md・timing.md、origin/main 2026-10-28）の形に SpW の窓を載せる。

- **コアと流れ**: ADC ごとにコア `s45_core_i`（64 KiB、BIT_KIND 7 = SpW8）。窓 w = 流れ s（KIND 3 DDC、s = 0..13）のブロック（0x4000 + 0x400·s）。
  DDC に固有の設定（0x100〜）は今と同じ WK・WDPHI・WNS に、**SpW に固有の FL（lane = 機関）・SL（履歴の枠: < S はチップ内、≧ S は DDR）・G（DDR の 8 bit の利得）** を足す
- **RUN・WRST はコアで 1 つ（案）**: 機関の選びの約束（lane ごとに幅の和 ≦ 256 MHz・DDR の窓の和 ≦ 256 MHz）は窓の組で決まるので、窓を 1 本ずつ入れ替えると途中で約束が崩れうる。
  流れのブロックの CTRL の RUN・WRST・ARM は受けるが、**どの流れに打ってもコアの全部の窓に効く**（specd は今も全部の流れに同じ START_AT で ARM するので、PS の手順は変わらない）。
  設定は WRST で取り込み、WRST の前に PS が上の約束を確かめる（PL も lane の和を数えて、破れていれば WRST を断り FLAGS に）
- **N_ACC・N_DUMP もコアで 1 つ**: 区切りは全窓で同じ格子（ng 格子 = 5 で BASE 10.24 ms。どの NS のフレーム長も G = 2.048 ms を割り切る）
- **DUMP_T（PS が束ねに使う: m = round(DUMP_T / BASE)）**: SAM45-Fine と同じ意味 = **ダンプの最初のフレームの最初の z が機関に入ったビートの T**。
  eng の書きの側で、ダンプの頭のフレームの z 0 のときに time_core の T を窓ごとに取っておき（LUTRAM、窓 14 × 64 bit × 2 面）、ダンプを流す仕事の札で d_* に添える。
  DUMP_F0 = F0 ＋ k·N（窓のフレーム）、DUMP_N = N。時刻の補正は DDC と同じ式（D_eff = D(NS) ＋ 1.5·L(NS)。D(NS) は SpW の鎖の sim で測る）
- **格子は time_core の T に揃える**: wsb の gidx（今は rst から数える）を T[63:19] に替える（RUN の g0 = START_AT の格子 ＋ 2）
- **帳簿の seqlock**（流れのブロックの SEQ・DUMP_* を AXI4-Lite で読む）: レコードに全部入るので、SpW では最後のダンプの写しだけ（試験と移行用）
- まだ決めないもの: 診断（0x200〜）の中身、DDR の窓の利得 G の決め方（PS が M-2 の式で）

**決めた（2026-10-28）: RUN・WRST はコアで 1 つ。**

**時刻の道の RTL（R-1a）**:
- `wsb`: 入口に time_core の T（`t_now`）。rst（= WRST）の後に窓 w の最初の標本が入口に来たビートを `t0[w]` に取る（機関は rst の後の標本を全部フレーム 0 から数え、書きの側は go を待たない）
- `dsink`: レコードの頭に **DUMP_F0 = (g0 ＋ k·ng)·2^(G_L2 − 12 − NS)**・**DUMP_T = t0[w] ＋ (g0 ＋ k·ng)·2^G_L2**（k·ng は DSP 2、ng は下 16 bit）。頭の値の段を 2 → 4 段にした
- sim（tb が窓ごとにフレームの頭の標本が入口に入ったビートを `wsb_t.log` に、`check_ring.py` が DUMP_F0 と DUMP_T を照らす。揺れの許し ≦ 16 ビート）:
  CFG 2・TB_S 1 / CFG 0・TB_S 14 / CFG 0・TB_S 6 / CFG 1・TB_S 6 で **DUMP_F0 一致・DUMP_T の差の最大 0 ビート**、ほかの照合も全部通過。
  照合の陽性対照（窓 0 のフレームの頭の時刻を 20 ビートずらす）は落ちた。tb の入口は窓のフレームの頭を待たせないので揺れが 0。実際の ddcb の lane の揺れは数ビートの見込み（時刻の補正の D(NS) と一緒に測る）
- OOC（ksink_ooc、配置後）: DSP 2・LUT 3,675（+538: t0 の選び・足し算）・URAM 6・WNS +0.577 ns
- 残り（R-1b）: コアのレジスタ（共通部・流れのブロック・WRST / RUN の ARM と START_AT・T の格子に揃えた rst）。今は wsb の rst が WRST、cmd_run が RUN

**コアのレジスタ（R-1b、`src/spw/spw_regs.v`）**:
- 共通部（IF_ID {2, 7, 1, 1}・PROJ・NSTREAM 14・CAPS・BASE_BEATS・BUILD・CORE_PORT）、SpW に固有の 0x80 CORE_FLAGS・0x84 NG・0x88 NDUMP・0x8C WRST_BAD・0x90 WRST_CNT、
  流れのブロック（SID・PARAM {fmt 1}・CTRL・N_ACC = NG·M の読み・SHIFT・FLAGS = その窓の機関の FLAGS・NCH・FRAME_BEATS・SRC・CFG_ID・RUN_CFG・WRST_CFG・RUN_SHIFT・RUN_T・RUN_F0、
  0x100〜 WK・WDPHI・WNS・WCUR・WCUR_DPHI・WSTART（= t0）・WRST_T・**WFL・WSL・WG・WCUR2**）。帳簿（SEQ・DUMP_*）は 0（レコードに入る）
- CTRL の RUN・STOP・ARM_RUN・取り消し・FLAGS を消す・WRST・ARM_WRST は**どの流れに打ってもコアに効く**。発火（time_core の go_out）で WRST → 明けて RUN
- **WRST の前に約束を H クロックで数え、破れていれば断る**（効いている設定もデータの道もそのまま、WRST_BAD に印）: [1] lane ごとの幅の和 ≦ 256 MHz・[2] DDR の窓の和 ≦ 256 MHz・
  [3] チップ内の枠の重なり・[4] DDR の枠 ≧ NK か重なり・[5] WNS が 1..5 の外。WFL ≧ E の窓は止める窓として数えない（**データの道はまだ止める窓を扱えない**）

### P-2: コア 1 ADC ぶんをつなぐ（spw_core、2026-10-29）

### P-3: 止める窓・PSPLIT の偶奇・ddcb の選びの 2 クロック化（2026-10-29）

  sim CORE_STOP（tb_core の窓 2 を WFL 3・WSL 0）: **窓 2 の出口 0 個、他の 5 窓は不一致 0・FFT の入口 40 枠 / 出口 37 枠とダンプ 10 個が bit 一致・レコード 10・CORE_FLAGS 0**（最新の RTL で再実行）
- **WRST の約束 [6]**: WK > 32、または PSPLIT（頭 0..H/2−1 は偶数の k、残りは奇数の k）と k の偶奇が合わない窓を断る。WRST_BAD は [6:1]。

### P-4: 格子を time_core の T に揃える・RUN の約束（2026-10-29）

- **決めたこと（開発者）**: SEQ は WRST で 0 に戻るままでよい。RUN の打ち直しは、レジスタで機械的に止める
- **WRST の明けを T の格子に揃える**（spw_regs）: WRST_T クロック後、T ≡ 2^AL_L2 − 1（AL_L2 = G_L2）を待ってから wrst を下ろす（データの道は T ≡ 0 のクロックから動く）。
  待ちは最長 2^G_L2 クロック（2.048 ms）。水抜きで明けの時刻がずれても、格子には揃う
- **wsb の格子を T から取る**: 数えていた gidx をやめ、RUN で g0a = T[G_L2 +: 32] ＋ 2（T の原点からの格子）、機関の F0 用に g0 = g0a − gbase（gbase = 明けの格子、近いほうに丸める）。
  DUMP_F0 = (g0a ＋ k·ng)·M（T の原点から数えたフレーム番号）、RUN_F0 = g0a·M。DUMP_T は今までどおり t0 ＋ (g0 ＋ k·ng)·G。
  これで **DUMP_T = K_F ＋ L·DUMP_F0、0 ≦ K_F < L**（proj023 の形。K_F は鎖の遅れ）
- **RUN の約束**（spw_regs）: RUN の中の RUN は断る（CORE_FLAGS[6]）。STOP の後 QUIET（12,288 クロック = 枠 3 つ）経ち、受け手が空く（dp_idle）までは RUN を待たせる。
  理由: レコードの頭の NG・g0 は今の値を読むので、送りかけのダンプの頭に新しい RUN の値が入り、DUMP_F0・DUMP_T・DUMP_N が黙って狂う。
  NDUMP で止まった後も RUN の中のまま（STOP してから打つ）。PS（proj031 の s45acq.py）は始める前に STOP を打っているので、手順は変わらない
- sim（`sim/tb_spw_regs.v`、AL_L2 5）: 照らし 8（WRST の明けが T ≡ 0 mod 32）・T7 RUN の約束（照らし 35〜41: RUN の中の RUN を断る・CORE_FLAGS[6]・STOP の直後は待つ・静まったら出る・受け手が空くまで待つ）を足して**全部通過**。
  **照らし 8 と 19 は前の行のコメントの中に入っていて、今まで実行されていなかった**（行をまとめたときの誤り）。分けて実行するようにした。
  陽性対照: AL_L2 4 で照らし 8 が、QUIET 0 で照らし 38 が、RUN の約束を外した版で照らし 36〜41 が落ちた。REGS_POSCTL も落ちる
- 通しの sim（tb_core、T の初期値の下位 14 bit は 0x3000 で格子からずらしてある）: **前段 6 窓とも不一致 0・FFT の入口 45 枠 / 出口 42 枠とダンプ 12 個が bit 一致・レコード 12・CORE_FLAGS 0、
  K_F = 89（NS 1）・178〜180（NS 2）で窓ごとに一定**（`check_ring.py` に K_F の照らしを足した: 窓ごとに一定、明けを揃える tb では 0 ≦ K_F < L）。
  明けを揃えない tb_wsb（CFG 0・TB_S 6 / CFG 2・TB_S 1）は K_F が 28,693〜28,734 で [0, L) の外に出る（照らしが効く証拠。この tb では範囲は求めない）。ほかの照合は全部通過。
  記録の G0A を 1 ずらすと DUMP_F0 の不一致で落ちる
- OOC（H 14・E 3・S 6・NU 2、配置後）: **DSP 814・LUT 79,724・FF 81,676・BRAM 222.5・URAM 20・WNS +0.502 ns**
- 残り: 粗い PFB の整数の模型との照合、TP・ギアボックスの共通部、BD に載せて実機

### P-5: 粗い PFB（pfb64_core）を整数の模型と bit 単位で照らす（2026-10-29）
