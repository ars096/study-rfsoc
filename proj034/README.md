# proj034 — 2G-2 にレーン FFT の 2-for-1 を入れる（proj030 の形を 2 ADC × 65536 ch に）

## 目的

2G-2（proj025、2 コア × 16 レーン × 8192 点の IP 32 個）に proj030 の 2-for-1 を入れ、**精度・機能を変えずに** DSP・LUT・BRAM・VCCINT がどれだけ減るか、タイミングの余裕（今は既定で WNS +0.046 ns）が広がるかを確かめる。
点数は増やさない（壁は前段 PFB の履歴と積分器の URAM、どちらも 2 ADC の ch の合計に比例。ADR 0022）。コアの形を 2G-4（proj031）とそろえることも狙い。

PFB の係数の URAM 共有（proj031）は入れない（入れるかは 2-for-1 の結果を見てから別に決める）: 係数は 2 コアで 1 組 ≒ URAM 16、得は DSP 128 で、2G-2 では DSP は壁でない。proj031 の WNS の改善（+0.010 → +0.047）は最悪経路が係数と無関係な所（RAW・gb_up → gb_fifo・sat_cnt）で、配置の揺れの幅と読む（WNS は構造の指紋にならない）。

## 手順（案）

proj033 と同じ型（M-1 → E-1 → P-1〜P-4 → B-1（2-for-1 だけ）→ B-2（記憶のカスケードに段）→ R）。違うのは N 8192・コア 2 個（2e-2 の「2 コアに同じ ADC でダンプが bit 単位で同じ」の陽性対照を引き継ぐ）・D_eff（今 12,289 ビート）の出し直し。
**proj033 の P 段が通ってから写す方が安い**（16384 点で直した部品の N を 8192 にするだけ）。

## M-1・M-2 模型（`model/s2_model.py`）— 予言（走らせる前に書く、2026-10-29）

写したもの（`git show`、そのまま）: タグ proj025-m0 の `model/g2_model.py`・`model/g22_fixed.py`（2G-2 の鎖の定義）。
`model/s2_model.py` は proj033（proj033-m0）のものを N 131072・M 8192 に直した（組は p と p + 8、IP 8 個 / コア）。2 本の ADC は同じ鎖を 1 本ずつ通るので、模型は ADC 1 本ぶんで確かめる。

2G-2 の今の g22_chain は Y（28 bit、|Y| ≦ 2^14 × 8192 = 2^27）を **1 bit 丸めて 27 bit → cmul SH 18**（proj025 の D1 = 1）。IP の出口 Z は複素の入力で |Z_re| ≦ √2 × 2^14 × 8192 < 2^28 なので **29 bit**（今の `fft_out_w` 29 のまま入る）。2-for-1 の 2Y は 30 bit。候補（proj033 と同じ 2 つを 1 bit ずらしたもの）:

- **(i) 2Y を 2 bit 丸める → 27 bit → SH 18**: 目盛りは今と同じ。|2Y| < 2^28 なので 27 bit に必ず入り、**飽和は起きない**
- **(ii) 2Y を 1 bit 丸める → 27 bit に飽和 → SH 19**: proj030（2G-4）と同じ形。刻みが今の半分、全振幅に近い入力で飽和しうる

予言:
- **M-1a 式**（浮動小数点、16 レーン × 8192 点の乱数）: 相対差 < 1e-12。陽性対照（共役なし）は > 1e-2
- **M-1b 鎖の全体**（proj025 M-c と同じ入力: CW 1000 LSB @ ch 20000 ＋ 雑音 σ 100、乱数の種 8、フレーム 3・4）:
  - 今（16 レーン）の ε は proj025 M-c の **8.5e-6 を再現**する（同じ入力・同じ鎖の定義）
  - (i)・(ii) とも ε は**今の 0.95〜1.00 倍**、(i) と (ii) の差は 2 % 未満（proj033 は 1.0000・0.9978。ε は y の整数への丸めで決まり、N にも Y の丸めにも依らない: proj025 M-c）
  - CW の差 < 0.01 dB、Z の最大は今と ±1 % 以内、2Y の飽和 0。IP の出口 Z の最大 ≦ 8.3M（今の Y の最大 4.1M の 2 倍以下。2^28 = 268M に余裕）
  - 陽性対照（相手を −k − 1 に取り違える）: ε > 1e-2
  - **決め方（測る前に決める、proj033 と同じ）**: (i) と (ii) の ε の差が 2 % 未満なら、**飽和の起きない (i)** を選ぶ
- **M-1c bit 反転順の出口で相手を待つ値**: 最大 **M/4 = 2,048 値 / IP**（proj030・033 の式。手で出した値なので当たりに数えない）。溜めは 2,048 × 464 bit（Z 29 bit × 2 × 8）= 0.95 Mbit。2K × 18 の構成なら 464 / 18 → **RAMB36 25.5〜26 / コア**（2 コアで 51〜52）
- **M-2a (B) の鎖の全体**（選んだ形で）: 65,536 ch がフレームごとに 1 回ずつ、ε は M-1b と同じ（0.9〜1.1 倍）、CW < 0.01 dB、飽和 0、`power_s2` の並びが ch ごとの Z の電力と一致。陽性対照（k2 8..15 を銀行 k2 − 8 に）は ε > 1e-2
- **M-2b 均しの待ち行列**: M に比例（proj033 は 2G-4 の 4 倍ちょうど）なので **行 2,049 本・組 1,025 項目（取り出しの後）・遅れの最大 2,048 拍・同じ行の間隔の最小 8,192 拍**（1 フレーム）。
  RTL の組の記憶の山は模型 ＋ 2 − 先読み 6 = **1,021 ≦ 1,024（余裕 3、2G-4・2G-1 と同じ）**。記憶 1,024 × 576 bit ≒ **RAMB36 16 / コア**
- これで E-0 の BRAM を見直すと（1 コア）: IP −104（8 個 × 13、proj025 の 1 個の数は E-1 で実測から）、s2_sep ＋26、s2_q ＋16 → 2 コアで 759.5 − 208 + 52 + 32 ≒ **636**（E-0 の 620〜650 の内）

**結果（`python3 model/s2_model.py`、2026-10-29、2 秒）: M-1・M-2 とも全部通過、予言は全部当たり。鎖の入口は (i)**
