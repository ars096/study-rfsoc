## 2G の仕様（BITS.md から）

| ADC | 1 本の FFT | 出す ch / ADC | df | フレーム L | 10.24 ms のフレーム数 | 格子 2.048 ms のフレーム数 | PFB の重心のずれ 1.5·L |
|---|---|---|---|---|---|---|---|
| 1 | 262144 点 | 131072 | 15.625 kHz | 16384 ビート = 64 µs | 160 | 32 | 96 µs |
| 2 | 131072 点 | 65536 | 31.25 kHz | 8192 ビート = 32 µs | 320 | 64 | 48 µs |
| 4 | 65536 点 | 32768 | 62.5 kHz | 4096 ビート = 16 µs | 640 | 128 | 24 µs |

- 窓（DDC）は無い。帯域は全部（2048 MHz、ゾーン 2）。dt = 10.24 ms（= BASE。PL のダンプそのもの）
- **どの構成でも 1 回に出す ch の総数は 131072**（4 × 32768 = 2 × 65536 = 1 × 131072）。計算の量（サンプル / 秒 × log₂N）と記憶の量もほぼ同じ
- PL → リング: 131072 ch × 8 B / 10.24 ms = **102.4 MB/s**。ネットワーク（float32）: **51.2 MB/s**（INTERFACE 1. の表・4.5）

## 作りの案（D-1 の候補）

| 案 | 中身 | 良いところ | 悪いところ |
|---|---|---|---|
| **R** 1 本の bit でレジスタで切り替える（BITS.md の「行はレジスタで」、proj014 の決定どおり） | 65536 点のコア（16 レーン × 4096 点）を 4 個持つ。2 / 1 ADC のときは r = 2 / 4 個のコアで 1 本の FFT を作る（**周波数間引きの最初の段 = 前段**を足す。M-1b で式を確かめた）。コア q の PFB は入力のフレームの q 番目の 1/r を受け持ち、前段の後、コア m が全帯域の ch r·k + m を出す | Overlay を替えずに ADC の本数を変えられる。コアは 4 個とも同じ | **入らない**（E-1: PFB ありで DSP 83 %・LUT 77 %、PFB なしでも LUT 72 %）。前段・入力の振り分け・モードごとの PFB の係数が全部のせになる。係数は表では 56.6 Mbit（モードごと・コアごと）で、補間が必須 |
| **O** Overlay で 3 本に分ける（2G-4・2G-2・2G-1） | 2G-4 = 4 コア × 16 レーン × 4096 点（SAM45-Wide から束ね・切り出しを外し、レーン FFT を 2 倍に）。2G-2 = 2 コア × 8192 点、2G-1 = 1 コア × 16384 点 | 1 本ずつは単純。**2G-2・2G-1 は余裕がある**（DSP 21〜39 %・LUT 22〜38 %）。2G-4 は Wide の RTL をほぼそのまま使える | bit が 3 本（ビルド・判定・リリースが 3 倍）。BIT_KIND の表（9 本）と BITS.md の「行はレジスタで」を変える。ADC の本数を変えるのに LOAD（10〜20 s） |
| **O を段階で** | まず 2G-4 だけを作る。2G-2・2G-1 は 2G-4 が動いてから | 最初の 1 本が Wide に最も近い（実績のある形） | 1 / 2 ADC の観測は後回し |

**決定（2026-10-17、西村さん）: O（Overlay で 2G-1・2G-2・2G-4 の 3 本に分ける）。** 理由: 1 つの観測で 3 つのモードが同居することはないので、1 本の bit に入れる必要がない。加えて R は資源の目安に入る組み合わせが 1 つも無い。作る順は **2G-4 から**（2026-10-17 に決めた）

### M-7 2G-1 の語長（D-7）— 予言（走らせる前に書く、2026-10-17）

dft16（proj023 の `dft16.v`）は U = V の 4 個の和（27 bit）を DSP の A ポート（27 bit）に入れるので、**V は 25 bit のまま**にしたい（dft16 を変えない）。
2G-1 のレーン FFT の出口は |Y| ≦ 11507 · 16384（29 bit）なので、Y → V で合わせて 4 bit 落とす（Wide は cmul の SH 17 で 1 bit）:
Y 29 bit → 2 bit 丸める → 27 bit（cmul の A ポート）→ cmul の SH 18（2 bit）→ V 25 bit → dft16 は今のまま（U 27・Z 29）。2G-2 は 3 bit（1 ＋ SH 18）。

判定: 16 レーンの整数の y（ガウス雑音 σ_y）→ レーン FFT → 上の丸め → cmul → dft16（段 2 の丸めも）の Z を、浮動小数点の鎖と比べ、加わった雑音の電力比 ε（= 誤差の電力 / 信号の電力）を出す。

予言:
- 丸めの雑音は Y の単位で、Y の 2 bit で ≒ 2·4²/12 × 16、V の 4 bit で ≒ 2·16²/12 × 16、dft16 の段 2 で ≒ 2·16²/12 × 4 × 4 → 計 ≒ 1,100。信号は E|Z|² = 16·M·σ_y²。**ε·σ_y² ≒ 4e-3（2e-3〜8e-3）**、2G-2（3 bit）は 2G-1 と同じ程度（M が半分、刻みも半分）、Wide（1 bit、M 2048）は 2G-1 より小さい
- σ_y 2 で劣化 ≦ 0.005 dB、σ_y 8 で ≦ 0.0005 dB → **σ_y ≧ 2 で劣化 < 0.01 dB を合格の線**にする（ADC の雑音は運転で σ_x ≫ 2 LSB。y ≒ x の単位）
- 陽性対照: Y でさらに 10 bit 落とす（計 14 bit）と、σ_y 2 で ε ≒ 2^20·4e-3 / 4 ≫ 1 → 劣化 > 1 dB で落ちる
- 飽和は起きない（上限の式から。模型でも |V| ≦ 2^24 を数える）

**結果（`make model` の M-7、2026-10-17）: 通過**

| | Y → 丸め → cmul | 最悪の同相 | σ_y 2 | σ_y 8 | σ_y 64 | ε·σ_y² |
|---|---|---|---|---|---|---|
| **2G-1**（M 16384） | 29 → 2 bit → 27 → SH 18 | V 25・Z 29 bit（入る） | 0.0034 dB | 0.0002 dB | 0.0000 dB | 3.1e-3 |
| 2G-2（M 8192） | 28 → 1 bit → 27 → SH 18 | V 25・Z 29 bit | 0.0017 dB | 0.0001 dB | 0.0000 dB | 1.6e-3 |
| Wide（参考、M 2048） | 26 → 0 → 26 → SH 17 | V 25・Z 29 bit | 0.0005 dB | 0.0000 dB | 0.0000 dB | 4.5e-4 |
| 陽性対照（2G-1 ＋10 bit） | 29 → 12 bit → 17 → SH 18 | | 3.01 dB | 3.01 dB | 2.31 dB | |

予言の当たり・外れ:
- 2G-1 の ε·σ_y² 3.1e-3: **当たり**（予言 2e-3〜8e-3）。σ_y 2 で 0.0034 dB < 0.01 dB
- 2G-2 は「2G-1 と同じ程度」: **外れ**（半分）。M が半分で信号が 1/2、刻みが半分で丸めの雑音が 1/4 → 比は 1/2。予言の理屈の誤り
- Wide は 2G-1 より小さい: 当たり
- 陽性対照: 落ちたのは当たり。ただし「ε ≫ 1」は**外れ**で、ε は 1 で頭打ち（雑音が足されるのではなく、信号ごと 0 に丸められる。誤差の電力 = 信号の電力）。σ_y 64 で 2.31 dB なのは、信号が刻みに近づいて一部が残るため
- **D-7 は (a) 丸めで足りる**: Y の下 2 bit を丸めて cmul の A ポート 27 bit に入れ、cmul の SH を 17 → 18 にする。dft16・Z 29 bit・SHIFT は Wide のまま

### M-8 2G-1 の新しい部品を bit 単位で決める（`model/g21_fixed.py`）— 予言（走らせる前に書く、2026-10-17）

RTL の proj の sim の正解の元にする（Wide の `wide_model.py` の `fixed_chain` と同じ役）。丸めは Wide と同じ `(v + 2^(s−1)) >> s`。

- **8-a 係数の補間**: 番地 i = t·N + n（0 ≦ i < L = 4N）を左右で折り返し（i ≧ L/2 なら i' = L − 1 − i）、s = i' >> 6・f = i' & 63。
  表は節 V[s] = round(h[64s]·2^(16+G))（s = 0..8191）と傾き S[s] = V[s+1] − V[s]。c = (V[s]·64 + S[s]·f + 2^(G+5)) >> (G+6)。
  1 ビート（m）の 16 レーンは同じ s で、t < 2 は s = t·N/64 + (m >> 2)・f = 16·(m & 3) + p、t ≧ 2 は s = (L − t·N)/64 − (m >> 2) − 1・f = 63 − 16·(m & 3) − p。
  予言: 浮動小数点の節（M-3）と同じ結果（差 ≦ 1 LSB・違う係数 ≒ 0.07 %）になる最小の G は 4〜6。S は 8 ＋ G bit（符号つき）に入る（傾きの最大 ≒ 1.1 LSB / タップ × 64）。
  表は 8192 × (V 18+G ＋ S 8+G) bit ≒ 0.28 Mbit、1 ビート 4 読み（2 ポート × 2 組）で BRAM ≦ 16。ビートの式は折り返しの式と全部の i で一致。
  陽性対照: 折り返しを i' = L − i にすると一致しない
- **8-b ひねり係数の積**: k1 = hi·128 + lo、A[p][hi] = round(2^16·W_N^(p·128·hi))・B[p][lo] = round(2^16·W_N^(p·lo))、w = cmul(A, B, SH 16)。
  予言: 直の表（round(2^16·W_N^(p·k1))）との差は最大 2 LSB、rms は直の表の量子化の 1.7 倍（M-4）。成分は 18 bit に入る（|w| ≦ 2^16 ＋ 数 LSB）。陽性対照: k1 = hi·127 + lo で差が 1 LSB を大きく越える
- **8-c 鎖の全体**: x（14 bit、CW ＋ 雑音 σ_x 100）→ PFB（補間の係数、y 15 bit で飽和）→ レーン FFT（rint）→ Y の 2 bit の丸め → cmul（積の w、SH 18）→ dft16 → Z を、浮動小数点の鎖（係数は原型の h）と比べる。
  予言: 4 フレーム目（履歴が埋まった後）で ε（誤差の電力 / 信号の電力）≒ 1e-5 程度（≦ 1e-4）、CW の ch の電力の差 < 0.01 dB。陽性対照: ひねり係数の k1 を 1 ずらすと ε > 1e-2
- **8-d 積分器の番地**: IP の出口の k1 は bit 反転順。1 フレームで 16384 の番地を 1 回ずつ通り（並べ替え）、同じ番地に戻るのは 16384 ビート後。予言: どちらも成り立つ

1 回目の不合格と、線の引き直し（**結果を見た後に変えた**ので、ここに残す）:
- 8-a: 「c = round(h·2^16) と違う係数の割合が G 8 と同じ」を線にしていたが、割合は G を上げるほど減り続け（G 4: 1.28 %、G 8: 0.12 %）、予言の 0.07 % は外れた。**c と違うこと自体は害でない**（h が丸めの境目にあれば 1 LSB 違うのが正しい）。物差しを**真の h に対する rms**に替え、「全部の表の 1.01 倍以内」を線にした（G 3 で 1.006 倍、G 4 で 1.0015 倍）。G は**表が 36 bit に入る最大の 5**（RAMB36 の数は G 2〜5 で同じ 8 個）
- 8-c の陽性対照: N 262144 では W_N^(p·(k1+1)) と W_N^(p·k1) の違いが 2π·p / N ≦ 3.6e-4 rad しかなく、**番地の 1 ずれが浮動小数点との比べでほとんど見えない**。陽性対照はそのままにし、鎖の線を ε ≦ 1e-4 から ≦ 2e-5 に締めた（陽性対照 1.2e-4 は落ちる）。
  **RTL の proj への申し送り: 番地の誤りは B 層（振幅の比べ）では捕まらないので、A2（bit 単位）と tw_k1 の見張り（Wide の tw_mis）を必ず置く**（LESSONS に足した）

生成の道具 `tools/gen_g21_tables.py`（`make gen`）: `build-gen/` に `g21_coef_lo.hex`・`g21_coef_hi.hex`（各 4096 行 × 35 bit）・`g21_tw_a.hex`・`g21_tw_b.hex`（各 128 行 × 576 bit、Wide の `wide_tw.hex` と同じ並び）を書き、読み返して模型と照らす（係数 1,048,576 タップ・ひねり係数 16 × 16384 とも一致）。生成物はコミットしない（RTL の proj で道具を写し、そこでコミットする）

## S-2 IP の配置配線（Vivado サーバ、`make s2`、2026-10-17）

`tools/ip_impl.tcl`: S-1 と同じ設定の FFT IP を 1 個ずつ OOC で配置配線し、**`-1`（実機の .bit と同じ part）・256 MHz（3.906 ns）**で閉じるかを見る。
内部のレジスタ間だけ（OOC なので口の経路は数えない。本番で落ちたのはリセットの配り・共有の ROM など IP の外の経路だった）。
物差し: lane_fft_w（2048 点・自然順、Wide のビルド 11 で本番の中で閉じた）。2G-2 の 8192 点・bit 反転順も並べる。戦略は Default と Explore。
陽性対照: 16384 点を 2.5 ns（400 MHz）で → 負になるはず（ならなければクロックか解析が効いていない。Tcl が exit 1）。

予言（走らせる前に書く、2026-10-17）:
- 物差し（2048 点）: Default で閉じる、WNS ≧ +0.3 ns
- **16384 点・bit 反転順（2G-1）: Default で閉じる**。WNS は物差しより小さく、差は 0.3 ns 以内。最悪経路は記憶（RAMB36 の縦続。BRAM を使う段が 4 → 7 に増える）に絡む
- 8192 点（2G-2）は物差しと 16384 点の間
- Explore は Default より悪くならない。WHS はどれも正
- 陽性対照（400 MHz）: WNS −0.3〜−1.0 ns
- 外れるとしたら 16384 点の記憶の経路。Default で落ちて Explore で閉じるなら、Wide と同じく PE を前提にする。両方で落ちるなら、IP の記憶の置き場（hybrid・段の数）を S-3 で振る

予言の当たり・外れ:
- 物差しが Default で閉じ WNS ≧ +0.3: 当たり（+1.834）

- 陽性対照 −0.3〜−1.0: **外れ**（+0.72）。上のとおり

読み: **2G-1 の 16384 点の IP そのものはタイミングの心配が無い**。`-1`・256 MHz で内部の余裕は 1.7 ns 以上あり、長さ 2048 → 16384 で減らない。
Wide で `-1` を詰めたのは IP の外の経路（リセットの配り・共有の ROM の配線・DSP の出口の段）だった（proj023 のビルド 7〜11）。
2G-1 はコアが 1 個（Wide の 4 分の 1 の論理）なので、本番の配置配線の混み具合も Wide より軽いはず。最初のビルドは既定の戦略で回し、落ちたら PE にする

### 2a. レーン FFT 16384 点の行動模型 — 予言（走らせる前に書く、2026-10-17）

`sim/lane_fft_g21_model.v`: lane_fft_w_model.v（567fda2）を写し、M 16384・bit 反転順の出力（XK_INDEX = 本当の k1）・出力待ち QF 4 にした。
tb（`sim/tb_lane_g21.v`）: 1 レーンに 3 フレーム（CW ＋ 雑音 / ±11507 の満杯 / 雑音 σ 30）を AXI の手渡しで。判定は `sim/check_g21.py lane`（numpy の DFT と比べる）。
- 出口 49,152 行、XK_INDEX は bit 反転順（0, 8192, 4096, …）・TLAST はフレームの最後、TLAST の事象 0
- 値は floor(DFT + 0.5)。倍精度の基数 2 と numpy の差で丸めの境目だけ 1 違いうる → |RTL − DFT| < 1 は全部、floor と違う行は 0〜数行
- 満杯のフレームの |Y| は 29 bit に入る（|Y| ≦ 11507·16384 = 188,530,688 < 2^28）
- `-DFFT_STALL_AT=3`: tready が 1 回下がり（待った 1 クロック）、手渡しで吸えてデータは欠けない（同じ判定が通る）

**結果（2026-10-17、`make sim-lane`、作業用のクラウドの環境）: 通過**（1 回目は判定の誤りで plain が不合格。下に）

| | 行 | 並び（XK_INDEX・TLAST） | floor(DFT + 0.5) と | \|RTL − DFT\| の最大 | 流し始めた後の tready の待ち | TLAST の事象 | 結果 |
|---|---|---|---|---|---|---|---|
| lane（下げなし） | 49,152 | OK | 全部一致 | 0.500 | 0 | 0 / 0 | 全部通過 |
| lane（`-DFFT_STALL_AT=3`） | 49,152 | OK | 全部一致 | 0.500 | **1** | 0 / 0 | 全部通過 |

- 予言は当たり（floor と違う行は 0）。ただし「満杯のフレーム」は符号がでたらめの ±11507 で、|Y| は 12.4M（√M で育つ）にしかならず、29 bit の上限は試していない（同相の最悪は 1d で試した）
- 1 回目: tb が「tready で待ったクロック」にリセットの後の tready の遅れ（READY_DELAY の 6 クロック）を混ぜていて、下げを入れない plain が「待った」と判定されて落ちた。
  **模型ではなく判定の誤り**。最初に受ける前と後を分けて数えるように tb を直した（後: plain 0・stall 1）
- この行動模型の陽性対照（たとえば自然順で出す変種）は置いていない。bit 反転順の並びは 2c 以降の sim（g21_chain の k1・積分器の番地）でもう一度見る

### 2b. g21_acc — 予言（走らせる前に書く、2026-10-17）

`src/g21/g21_acc.v`: 面ごとに 16384 行（番地 = k1）× 384 bit（8 銀行 × 48 bit）の記憶 1 つ（URAM 24 / 面、計 48 = 見積もりと同じ）。1 クロックに 1 行を RMW。wide_acc の段（W0〜W4）と面の口の使い分けを写した。
tb（`sim/tb_g21_acc.v`）: 決まった式の擬似乱数の電力（37 bit の上の 2 bit は 0、≦ 2^35）を bit 反転順の k1 で 27 フレーム。ダンプ A（フレーム 0〜8、面 0）・B（9〜17、面 1）・C（18〜26、面 0 の 2 回目）。
B を積んでいる間に A を、C を積んでいる間に B を、終わってから C を、全 131,072 ch 読み出す（積んでいる面の RMW と凍った面の読み出しが同じクロックに並ぶ）。判定は `sim/check_g21.py acc`。
- ふつう: A・B・C とも 131,072 ch 読めて、**模型と違う ch 0**。和の最大 ≒ 9 × 2^35 ≒ 3.1e11（48 bit に入る）
- 陽性対照 `-DACC_FIRST_ERR`（最初のフレームで消さない）: A（面 0 の 1 回目、記憶の初期値は x）と C（面 0 の 2 回目、A が足される）が違う。B（面 1 の 1 回目）も初期値 x に足すので違う → **A・B・C とも全 ch 違う**

| g21a（ふつう） | 131,072 ch・違う 0 | 131,072 ch・違う 0 | 131,072 ch・違う 0 | 全部通過 |
| g21a-err（`-DACC_FIRST_ERR`） | 全 ch 違う（x） | 全 ch 違う（x） | 全 ch 違う（x） | 不合格（落ちた） |

### 2c. g21_spec — 予言（走らせる前に書く、2026-10-17）

`src/g21/g21_spec.v`: wide_spec を写し、g21_pfb・lane_fft_g21 × 16（待ち行列つき）・g21_tw ＋ g21_chain・g21_acc をつないだ。流れ 1 本、フレーム 16384 ビート、F0 の格子 2^GF_L2 フレーム、

  （M-8 のひねり係数の番地と同じ型）。bit 単位の照合は 1 ビートでも違えば落ちるので捕まるが、振幅の比べ（B 層）なら見落としうる。**coef_mis の見張りは本番でも残す**
- nomask: 違うビート 49,152 は当たり。並びの NG（PFB_NOMASK は y_fr を 3 に固定する）は予言に書いていなかった

### 1d. g21_chain — 予言（走らせる前に書く、2026-10-17）

`src/g21/g21_chain.v`: wide_chain を写して、Y 29 bit の S1 の丸め（(Y + 2) >>> 2）・cmul SH 18・k1 14 bit・ひねり係数を g21_tw（LAT 6）から（段を S_T = 6 起点に）・束ねを外す、の 4 点を直した。
tb（`sim/tb_g21_chain.v`）: g21_tw ＋ g21_chain。入力はレーン FFT の出口 Y（模型の lane_fft）を bit 反転順の k1 で 3 フレーム:
0 = CW 1000 ＋ 雑音（PFB の 4 フレーム目）、1 = 雑音だけ σ 30、2 = 最悪の同相（y がすべて +11507 → k1 = 0 で Y が 29 bit いっぱい）。判定は `sim/check_g21.py chain`（chain_Y ＋ 電力・銀行ごとの飽和）。
- ふつう（SHIFT 7）: 49,152 ビート・k1 の並びが入れたとおり・**模型と違うビート 0**・tw_mis 0。飽和を含むビートはフレーム 2 の k1 = 0 だけ（1 ビート、銀行 0）
- 飽和（SHIFT 4）: 通過（模型と同じ飽和の数）。CW の ch（k1 7232・k2 2）とその両隣が飽和する
- 陽性対照 `-DCHAIN_TW_LAT_ERR`（TW_LAT 5）: tw_mis 1。bit 反転順の隣の k1 は大きく離れる（例: 0 の次は 8192）のでひねり係数はまるで違い、**違うビート ≒ 100 %**（レーン 0 だけの寄与の銀行は残りうるが、ビート単位ではほぼ全部）
- 陽性対照 `-DCHAIN_NORND`（切り捨て）: Yd が半分のビートで 1 LSB 小さい → V では 1/4 LSB で丸めに消えやすく、さらに SHIFT 7 で消える。**違うビートは 5〜50 %**（弱い対照になる見込み。bit 単位なので 1 つでも違えば落ちる）

**結果（2026-10-17、`make sim-g21ch`、作業用のクラウドの環境、1 分 30 秒）: 通過**

| | SHIFT | ビート | k1 の並び | 模型と違うビート | 飽和を含むビート（模型） | tw_mis | 結果 |
|---|---|---|---|---|---|---|---|
| g21ch（ふつう） | 7 | 49,152 | OK | **0** | 1 | 0 | 全部通過 |
| g21ch-sat | 4 | 49,152 | OK | **0** | 2 | 0 | 全部通過 |
| g21ch-twlat（`-DCHAIN_TW_LAT_ERR`） | 7 | 49,152 | OK | **32,768（66.7 %）** | 1 | **1** | 不合格（落ちた） |
| g21ch-nornd（`-DCHAIN_NORND`） | 7 | 49,152 | OK | **4,338（8.8 %）** | 1 | 0 | 不合格（落ちた） |

予言の当たり・外れ:
- ふつう: 全部当たり（飽和はフレーム 2 の k1 = 0 の 1 ビート）
- 飽和: 通過は当たり。「CW の ch の両隣も飽和」は**外れ**（飽和は CW の k1 7232 と最悪の同相の k1 0 の 2 ビートだけ）。CW は ch のちょうど中心にあり、隣の ch は −53.7 dB（M-2）で飽和しない。両隣が飽和するのは ch の間の CW の場合
- twlat: tw_mis 1 は当たり。「≒ 100 %」は**外れ（66.7 %）**: フレーム 2（最悪の同相）は k1 = 0 以外の Y が 0 なので、ひねり係数がずれても電力は 0 のまま。違ったのはフレーム 0・1 の全部（32,768）
- nornd: 8.8 % で予言の 5〜50 % に入った（当たり）

**手順 1 のまとめ**: 2G-1 の新しい部品 4 つ（係数の補間・ひねり係数の積・PFB・鎖）は、どれも模型（model/g21_fixed.py）と bit 単位で一致し、陽性対照は全部落ちた。
番地のずれ（係数・ひねり係数）は値の比べでは一部しか見えない（1c で 25 %、1d で 67 %）が、見張り（coef_mis・tw_mis）はどれも立った。**本番でも見張りを残す**

## INTERFACE.md・BITS.md の変更案（proj023 の会話か西村さんが入れる。ここでは書き換えない）

1. **BITS.md の 2G の行を 3 本に**（2G-1・2G-2・2G-4、D-1）。「各 bit の中の行はレジスタで切り替え」（proj014）の例外として、2G は ADC の本数ごとに Overlay を替える、と書く
2. **BIT_KIND**（INTERFACE 2.4 の表）: 3 本に番号を 1 つずつ（例: 2G-4 = 3 のまま、2G-2・2G-1 = 10・11）か、BIT_KIND 3 のまま自己記述で見分けるか（D-9）
3. **NCH が 4096 を越える流れ**: 2G は KIND 1 FULL（切り出しなし）で NCH 32768 / 65536 / 131072、FRAME_BEATS 4096 / 8192 / 16384（D-10）。SLICE の約束（S0 ≦ N/2 − 4096）は触らない。
   PS 側は `NCH = 4096`・`s45proto.IF_ORDER`・`s45client` の `P.NCH` を NCH から作る形に（s45proto v2 の nch は u32 で足りる）
4. **リングの大きさ**: 2G-4 は 10.24 ms ごとに 256 KiB のレコード × 4、2G-1 は 1 MiB × 1（どれも 102.4 MB/s）。32 MiB のリングでは ≒ 0.3 s しか持たない。PYNQ の allocate は 64 MiB まで（LESSONS）なので、64 MiB でも ≒ 0.6 s。4.1 の目安（1 s 以上）に届かない → リングを 2 本の allocate に分けるか、目安を 2G で読み替えるか
5. **ネットワークの予算**（8. の 10）: float32 で 51.2 MB/s は今の予算 17.7 MB/s を越える。ネットワークの tint ≧ 30.72 ms に読み替えるか、送り出しの頭打ちを直すか（D-11）

## 結論・次にやること

**今の結論（S-1 の前）**: 2G は**記憶が律速**。PFB の履歴・積分器・レーン FFT の中の記憶が取り合い、何も工夫しないとどの案も入らない。
入れる手は 4 つ（bit 反転順・積分器 48 bit・ひねり係数の積・係数の補間）で、どれも模型で害が無いことを確かめた（M-3・M-4・M-5）。
**1 本の bit で 1 / 2 / 4 を切り替える案 R は入らない見込み**。Overlay で分けた 3 本のうち、2G-2・2G-1 は PFB 込みで余裕があり、**2G-4 は Wide と同じく LUT が重い**。
