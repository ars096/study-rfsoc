## 最終仕様（2026-09-18 に決定）

| | 値 |
|---|---|
| IF 入力 | **2〜4 GHz**（45m から来る IF のまま。アナログで下げない）|
| IF 入力数 | **4**（ADC_A/B/C/D 同時）|
| 窓 | **1 IF あたり最低 2、目標 4、最高 8**。窓の位置と幅は任意（例: 2.1〜2.2 / 3.0〜3.2 / 3.5〜3.55 GHz）|
| 構成 | ADC → **PL 内で分配** → 窓ごとのフィルタ → FFT → 積分 |
| fs | **4096.0 MSPS** |

### なぜハード DDC ではないか

RFDC のハード DDC は **ADC 1 本につき 1 系統**しかない。1 本の IF から複数の窓を取るには、
**間引きなしで全レートを PL に入れ、PL 内で分配する**しかない。

### なぜ 4096 MSPS か

2〜4 GHz（幅 2 GHz）を実数サンプリングで 1 つのナイキストゾーンに収めるには **fs = 4.0 GSPS ちょうど**しかなく、
それでもガードバンドはゼロになる。**どの fs を選んでも帯域の端は 100 MHz 前後削れる**ので、
「4.0 に近くて作れるもの」から選んだ。

RFDC タイル内 PLL の範囲（PG269: R 1〜4 / N 13〜160 / M 2, 3, 4, 6, 8…偶数 ≤64 / VCO 8.5〜13.2 GHz）と
LMX の 491.52 MHz から、4 GSPS 付近で作れるのは次の 4 つ。**M = 2 では VCO 下限から fs ≥ 4.25 GSPS になるので M = 3 を使う。**

| fs (MSPS) | R | N | M | VCO (MHz) | AXIS（16 サンプル/ビート）| 無事に使える帯域 |
|---|---|---|---|---|---|---|
| 3932.16 | 1 | 24 | 3 | 11796.48 | 245.76 MHz | 2.00〜3.86 GHz |
| 4014.08 | 2 | 49 | 3 | 12042.24 | 250.88 MHz | 両端とも余裕が無い |
| 4055.04 | 4 | 99 | 3 | 12165.12 | 253.44 MHz | R = 4 で位相雑音に不利 |
| **4096.0** | **1** | **25** | **3** | **12288.0** | **256.0 MHz** | **2.10〜4.00 GHz** |

**決定: 4096.0 MSPS（R = 1 / N = 25 / M = 3）。**
理由: R = 1 で LMX の 491.52 MHz をそのまま使える（proj004 の 10 MHz 系統は無変更）。上側に 96 MHz の余裕がある。
1 秒 = 256,000,000 ビートちょうど。AXIS 256 MHz は 4915.2 MSPS（307.2 MHz）より 2 割軽い。
見送った案: 3932.16（下端 2.0 GHz から使えるが 3.86 GHz より上を失う）／ 4.000 ちょうど（491.52 からは作れず、
LMX を分数分周にするとスプリアスを抱える。作れてもガードバンドはゼロ）／ 4915.2（2〜4 GHz がゾーン 1 と 2 にまたがり、
2.0〜2.46 と 2.46〜2.92 GHz が重なる）。
**代償**: 2.0〜2.05 GHz の成分が 2.05〜2.10 GHz に折り返す。**ADC 前の BPF は下端を急峻に切る必要がある。**

### 周波数計画（fs = 4096 MSPS）

```
ゾーン 1: 0      〜 2048 MHz   (f_obs = f)
ゾーン 2: 2048   〜 4096 MHz   (f_obs = 4096 − f)   ← IF 2〜4 GHz はここ。スペクトルは反転する
ゾーン 3: 4096   〜 6144 MHz   (f_obs = f − 4096)
```

- **ゾーン 2 はスペクトルが反転する。** 周波数軸の向きを取り違えると、線の位置は合っていても左右が逆になる
- RFDC は `NyquistZone = 2` に設定する（較正をゾーン 2 に合わせる）

## 成功の判定

**まず 1ch（ADC_B = Tile 226 / slice 0）で通す。** 4ch（1024 bit / 256 MHz）はその後。

キャプチャ長 65536 サンプル（16 µs）で **FFT 分解能 = 4096 MHz / 65536 = 62.5 kHz ちょうど**。
試験トーンは 62.5 kHz の倍数に置いてビン中心に立てる。

| | 判定 |
|---|---|
| 1 | IP から読み返した fs・R/N/M が設計値どおり。実機で `PLLLockStatus = 2`、`SamplingFreq = 4.096` |
| 2 | **予言**: ゾーン 2 のトーン（例: 2.2 / 3.0 / 3.9 GHz）が **4096 − f**（1896 / 1096 / 196 MHz）に、期待する電力で立つ |
| 3 | **予言**: SG の 2 次高調波が計算どおりの位置に出る（例: 3.0 GHz の 2 倍 6.0 GHz → ゾーン 3 で 1904 MHz）。**置き場所を先に書いてから測る** |
| 4 | **16 並列の並び順が正しい**: 並びを誤ると k·fs/16 ± f にスプリアスが立つ。**それらしいスペクトルは出てしまうので、トーンの純度で判定する** |
| 5 | 外部 10 MHz ロックが維持されている（トーン周波数のずれで proj004 と同様に確認）|
| 6 | 341.33 MHz（入口）と 256 MHz の両方で WNS ≥ 0、CRITICAL WARNING なし |

**判定 4 を外さないこと。** 並び順の誤りも「動いているように見える失敗」になる。

### 2026-09-18: `make probe` の結果 → ギアボックスを入れる

**fs 4096 MSPS で RFDC の Data_Width（1 語のサンプル数）の有効値は 7〜12。16 は通らなかった。**
Outclk の有効値は 32 / 64 / 128 / 256 MHz。範囲外の 16 を指定した結果、IP は黙って 8 に戻し
`Fabric_Freq = 512 MHz` を返していた（通常の `make` なら読み返しで止まる）。

| 1 語のサンプル数 | AXIS | |
|---|---|---|
| 8 | 512 MHz | PL では閉じない |
| 12（上限） | 341.33 MHz | 重い。12 並列は 2 のべき乗でなく、1 秒が整数ビートにならない |

**決定: RFDC は 12 サンプル / 341.33 MHz で受け、入口のギアボックスで 16 サンプル / 256 MHz に詰め替える。**

```
RFDC ─192 bit @341.33─▶ gb_up（×4）─768 bit─▶ gb_fifo（非同期）─▶ gb_dn（÷3）─256 bit @256─▶ capture_gate ─▶ …
      12 サンプル                48 サンプル                               16 サンプル
      └──── ADC ドメイン（clk_out1）────┘                     └──── DSP ドメイン（clk_out2）────
```

- 341.33 MHz で動くのは RFDC の AXIS と gb_up・gb_fifo の書き込み側だけ。以降はすべて 256 MHz・16 並列
- 2 つのクロックは 1 個の MMCM（入力 256 MHz、VCO 1024 MHz、÷3 と ÷4）から出す。流入と流出の速度は厳密に等しい
- 時刻は 256 MHz 側で数えれば 1 秒 = 256,000,000 ビートの前提が残る
- 見送った案: fs を 3932.16 MSPS に下げる（12 サンプルで 327.68 MHz。12 並列が残り、上端 3.86〜4.0 GHz を失う）／
  12 並列のまま DSP を組む（フィルタ・FFT が 341 MHz・12 並列になる）

**新しい未知数**: 341.33 MHz の入口が閉じるか。`clk_out2` のクロック名（`timing.xdc` は類推で書いてある）。
`validate_bd_design` が RFDC の `m2_axis_aclk` の FREQ_HZ（341333333…）と MMCM 出力の差を咎めないか。

### 実機 1 回目（2026-09-18、ADC_B、E8257D 3000.0625 MHz / −10 dBm）

| 判定 | 結果 | |
|---|---|---|
| 1 | **通過** | Tile 226 `PLLLockStatus = 2`、`SamplingFreq = 4.096`。**タイル PLL の M = 3 は実機で動いた**。`NyquistZone = 2` を読み返しで確認 |
| 2 | **通過（周波数）** | **1095.9375 MHz（= 4096 − 3000.0625）に立った**。ずれ +288.6 Hz = **+0.096 ppm**。proj004 の外部基準での残差（15 ppb）より 6 倍大きい。**SG が同じ 10 MHz に同期していたか未確認** |
| 3 | **通過** | H2 が **1904.125 MHz** に −55.6 dBc（予言どおり）|
| 4 | **通過（並び順）** | 奇数 m の最悪 **−67.5 dBc**。ギアボックスを含めて 16 並列の並びは正しい |
| — | FIFO | 取得前後とも `IsFIFOFlagsAsserted = 0`、ゲート done |

**予想していなかったもの: 偶数 m のイメージが −38.8 dBc。**

```
f ± fs/8   (m=2)   1607.94 / 583.94 MHz   −38.8 / −39.0 dBc
f ± fs/4   (m=4)   1976.06 MHz            −40.1 dBc
3fs/8 − f  (m=6)   440.06 MHz             約 −42 dBc
fs/2 − f   (m=8)   952.06 MHz             約 −43 dBc
5fs/8 − f  (m=10)  1464.06 MHz            約 −41 dBc
```

**fs/8 の倍数だけに立ち、奇数 m（fs/16 の奇数倍）には立たない。**周期 8 の構造 = RF-ADC 内部の
**8 並列インタリーブ（副 ADC）の不整合**と読むのが自然。ギアボックス（周期 12 / 16 / 48）の誤りなら奇数 m にも立つ。
**`lane_check` が奇数と偶数を分けて出していたので切り分けられた。**

ただし −39 dBc は分光計として大きい（強い線のイメージが別の周波数に偽の線として立つ）。
**予言（測る前に記録）**: 時間スキューの不整合ならイメージは入力周波数に比例して強くなる。
**同じ観測周波数 1095.9375 MHz を、ゾーン 1（入力 1095.9375 MHz）で入れた対照**では
20 log(3000/1096) ≒ **8.7 dB 弱くなる**はず。利得の不整合なら変わらない。ギアボックス起因なら較正モードにも入力周波数にも反応しない。

**レベル**: `--atten-db -10`（負）で入力したため帳簿が 20 dB ずれていた（ADC 入力は −20 dBm が正しい見込み）。
その場合 0 dBFS ≒ +12.4 dBm で、100 MHz の +5.8 dBm より 6.6 dB 感度が低い（ケーブル・バラン・入力帯域の周波数特性。未分離）。
**以後 `--atten-db` は負値を拒否する。**

### 実機 2 回目（2026-09-18、イメージの切り分け）

条件: E8257D を同じ 10 MHz に同期（確認済み）、SG −10 dBm、経路の減衰 16 dB（ADC 入力 −26 dBm）。
各条件とも Overlay を読み直し、5 s 間隔で連続取得。

| 条件 | 入力 | 較正モード | 偶数 m（fs/8 の倍数）[dBc] | 奇数 m [dBc] |
|---|---|---|---|---|
| ゾーン 2 × 12 回 | 3000.0625 MHz | 2（既定） | **−54.8〜−61.1** | −63.0〜−67.1 |
| ゾーン 2 × 6 回 | 3000.0625 MHz | 2（明示） | −55.1〜−64.8 | −63.8〜−66.2 |
| ゾーン 2 × 6 回 | 3000.0625 MHz | 1 | −51.9〜−64.4 | −63.0〜−68.8 |
| **ゾーン 1 × 6 回（対照）** | **1095.9375 MHz** | 2 | **−54.9〜−61.0** | −62.6〜−64.3 |

**読み**

- **1 回目の −38.8 dBc は再現しなかった。**同じ SG 設定・同じピーク（−32.42 dBFS）で、今回は Overlay 直後の 1 回目から −55 dBc 前後。
  1 回目だけ何が違ったかは未特定（電源投入直後・この fs での最初の較正、が候補）
- **予言は外れた。**時間スキュー支配なら、ゾーン 1 の対照（入力 1.1 GHz）は 3 GHz より約 8.7 dB 弱くなるはずだったが、
  **両者は同じ範囲（−55〜−61 dBc）**。入力周波数に比例しない = 利得の不整合か、背景較正の残差が支配的
- **較正モード 1 / 2 の差は、取得ごとのばらつき（5〜10 dB）に埋もれて見えない**
- **イメージの強さは取得ごとに 5〜10 dB 揺れる**（5 s 間隔）。背景較正が動き続けているため。
  平均して沈むかどうかは、積分器を作ってから確かめる（イメージは信号と同期しているので、較正が止まっていれば積分しても沈まない）
- **分光計の仕様としては、強い線の f ± k·fs/8 に −55 dBc 級の偽の線が立ちうる**、と記録しておく

**判定 5（外部 10 MHz）: 通過。**ゾーン 2 の 12 回の ppm は平均 **−0.009 ppm**（σ 0.036、平均の誤差 ±0.010）。
内部基準なら +14.9 ppm（proj003）なので、外部基準は効いている。1 回目の +0.096 ppm はこのばらつきの 2.7σ。
16 µs の取得 1 回では 0.03 ppm 程度しか決まらない（proj004 の 15 ppb は長時間の方法）。

**レベル（0 dBFS 換算、経路 16 dB 込み、ケーブルの周波数特性は未分離）**:
100 MHz **+5.8 dBm**（proj005）／ 1095.9375 MHz（ゾーン 1）**+8.6 dBm** ／ 3000.0625 MHz（ゾーン 2）**+6.4 dBm**。
単調でないので、SG の出力平坦度とケーブル損を分けて測らないと入力帯域は論じられない。

**ゾーン 1 の対照で H2 が −44 dBc**（3 GHz 入力では −57 dBc）。SG 自身の高調波の可能性が高い。
ADC の SFDR を決めるには LPF / BPF が要る（業務ログの宿題どおり）。
