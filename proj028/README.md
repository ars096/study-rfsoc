## 目的

全帯域（2048 MHz、1 ADC）の分光で、**チップ内の記憶で決まっている点数の上限**（2G-1 の 131072 ch。proj024）を、
PL の DDR4 を時刻 ↔ 周波数の並べ替え（corner turn）に使うことで外せるかを、RTL を書く前に模型と資源・帯域の見積もりで判定する。
入るなら、点数（と dt）の現実的な上限と、作りの形（M・P・語長）を決める。

## なぜ 1 段のままでは点数が増えないか（2026-10-23 の会話の要点）

- 2G-1（build-PE）は DSP 22 %・LUT 22 %・**BRAM 62 %・URAM 60 %**。律速は記憶で、PFB の履歴（11.0 Mbit）・レーン FFT の中身（BRAM ≒ 344）・積分器（12.6 Mbit = URAM 48 全部）がどれも N に比例する。1 ch あたり ≒ 280 bit → 262144 ch は ≒ 73 Mbit でデバイス（62.5 Mbit）を超える
- 計算は 1 サンプルあたり log N でしか増えない（S-1: レーン FFT の DSP は 4 倍ごとに +6）。荒く分けても N log M + N log(N/M) = N log N で減らない
- 荒い PFB（オーバーサンプリング os）で分けてチップ内で処理するだけでは、履歴・FFT の中身が os 倍に増えるだけ。時計を遅くしても記憶は減らない（並列の数が増える）
- **DDR に記憶をそのまま移すのは帯域で入らない**: 積分器 ≒ 25 GB/s、PFB の履歴 ≒ 30 GB/s
- **corner turn なら入りうる**: 荒いチャンネルの時系列を 1 dt ぶん DDR に溜め、チャンネルごとにまとめて読み出して細かい PFB・FFT・積分をする。チップ内の記憶は同時に処理する P 本ぶん（N/M × P）になる

## 作りの案（仮）

```
ADC（4096 MSPS、ゾーン 2）
 → 荒い PFB（M ch、os = M_os/M、複素）→ ch ごとの利得と再量子化（b bit）
 → PL DDR4 に書く（時刻順、2 面 × dt）
 → 1 ch の dt ぶんを読む（P 本を並べて）
 → 細かい PFB（T 4、N_f 点）→ FFT → 重なりを捨てる → 電力 → 積分（チップ内、N/M × P）
 → リング（PS の DDR）→ specd
```

### M-1 荒い PFB — 予言（走らせる前に書く、2026-10-23）

組み方（ここで決める仮の形）:
- 実数の入力 fs = 4096 MSPS → M 点の PFB（間引き D = M / os）→ 複素の ch が M/2 本、各 os·Δ（Δ = fs/M）の速さ
- **ch の格子を半 ch ずらす**（ch k の中心 = (k + 1/2)·Δ、k = 0..M/2−1）。M/2 本でちょうど 0〜fs/2 を敷き詰め、DC・fs/2 の半端な ch が出ない（ゾーン 2 の帯域の端は捨てる所なので、どちらでも差は小さいが、全部の ch を同じ形にできる）
- 残すのは各 ch の |f − f_k| ≦ Δ/2。折り返しで残す範囲に落ちるのは |f − f_k| ≧ (os − 1/2)·Δ の入力 → **遷移帯は (os − 1)·Δ**
- 原型は Kaiser 窓の sinc（切れ目 = os·Δ/2、遷移帯の真ん中）。最適化した設計（Parks–McClellan）ではないので、タップは上限側の見積もり

判定: 残す範囲に落ちる折り返し ≦ **−60 dB**（2G-1 の ch の応答 ≧ 1.5 ch −58 dB と同じ大きさ）。残す範囲の端（±Δ/2）の落ち込みと、範囲の中の波打ちも数える（較正で消えるが、継ぎ目の ch の雑音の重みが変わる）。

予言（1 枝あたりのタップ T_c、Kaiser の式 L ≒ (A − 8)/(2.285·2π·(os−1)/M) から T_c ≒ 3.6/(os − 1)）:

| 4/3 | 0.333 Δ | 11〜13 | 180〜210（4〜5 %） |
| 5/4 | 0.25 Δ | 15〜17 | 240〜270（6 %） |

- 端の落ち込み: 切れ目を遷移帯の真ん中に置くので、±Δ/2 での落ち込みは窓の波打ち（≒ 0.001 dB）程度

### M-1 で分かった格子の制約（算術。模型ではない）

荒い段を足すと、**フレームの長さ D·N_f（ADC のサンプル）と、ch の格子（Δ が df の整数倍か）の両方**が os に縛られる。
FFT の IP は 2 のべき乗の長さしか取らないので、荒い FFT の M も細かい FFT の N_f も 2 のべき乗にすると、os = M/D から D に奇数の因子 q が入る。

| os（M 64） | D | 時刻: ダンプを 2.048 ms の格子に載せられる dt の単位 | df（N_f 16384） | 1 本の荒い ch から残す細かい ch（N_f/os） | 全部の ch |
|---|---|---|---|---|---|
| 4/3 | 48 | 3 × 2.048 = **6.144 ms** の倍数（30.72 ms・61.44 ms…） | 5.208 kHz | 12288 | 393216 |
| 8/7 | 56 | 7 × 2.048 = **14.336 ms** の倍数（71.68 ms = 7 × 10.24 …） | 4.464 kHz | 14336 | 458752 |
| 5/4・9/8・21/20 | — | M 64 では D が整数にならない（M を 80・72・84 にすると FFT が 2 のべき乗でない） | | | |

- **ch の格子はつながる**: Δ / df = N_f / os が整数（N_f が p の倍数）なので、どの荒い ch の細かい ch も同じ格子 f = j·df に乗り、重なりを捨てるとちょうど敷き詰まる
- **df は fs / 2^k ではなくなる**（因子 q が入る）。10.24 ms の dt はフレームの整数倍にならない（2^23·5 サンプルに 7・3 の因子が無い）。ダンプの区切りを格子に載せるには dt を q·2.048 ms の倍数にする
- 別の道: D を 2 のべき乗にして（時刻は今の格子のまま・df = fs / 2^k）、M を 80（os 5/4）などにする。荒い FFT が 2 のべき乗でなくなり（16 × 5）、Δ / df = 0.8·N_f が整数でないので、荒い ch ごとに細かい周波数の回転（NCO）で格子を合わせる手間が増える
- E-3（出口）で dt は 40 ms 級以上になる見込みなので、**実験では「M・N_f は 2 のべき乗、dt は q·2.048 ms の倍数」を勧める**（決めること）

目安（ピーク 19.2 GB/s の 70 % = 13.4 GB/s）: **b = 8 はどの os でも入る。b = 16 はどれも入らない**。b = 10 は 8/7 以下なら入る。継ぎ目の読み直し（(T−1)/フレーム数、数 %）は含めていない。
os を小さくすると DDR・細かい側の記憶が減る代わりに、荒い PFB の DSP が増える（M-1 A）。**8/7 は DSP 10 %・DDR 9.4 GB/s で、どちらにも余裕がある**。

### M-1d 荒い FFT を 32 点の複素 FFT 1 回に・出口の回転を省く — 予言（走らせる前に書く、2026-10-23）

RTL の形を決めるための式の確かめ。z_r（r = 0..63）は実数（h も x も実数）なので:
- w_n = (z_n + j·z_{n+32})·e^{jπn/64}（n = 0..31）、F = 32 点の DFT（e^{+j2πmn/32}）として、**Y_{2m} = F_m（m < 16）、Y_{2m+1} = conj(F_{31−m})**
  （半 ch ずらしの 64 点を n と n + 32 に分け、Y_{63−k} = conj(Y_k) を使う）。64 点の複素 FFT の代わりに 32 点 1 回
- **出口の回転 e^{−j2π(k+½)mD/M} を省ける**: D/M = 7/8 なので、回転は荒い ch の中の周波数のずれ (k + ½)·7/8 = 7k/8 + 7/16（1/16 の倍数）。
  N_f が 16 の倍数なら、細かい FFT の出口で ch k ごとに整数 bin（−(7k/8 + 7/16)·N_f mod N_f）巡回してずれるだけ → 掛け算は要らず、細かい ch の番地の足し算で済む

予言: どちらも浮動小数点の丸めの大きさ（≦ 1e-12）で一致。陽性対照: 共役の取り方を conj(F_{31−m}) → F_{31−m} にすると落ちる。ずれの bin を 1 違えると落ちる

### M-2 再量子化（荒い段の後に b = 8 bit）— 予言（走らせる前に書く、2026-10-23）

組み方: 荒い ch ごとの利得 g_k を PS が観測の前に 1 回決めて固定し（観測中は動かさない。較正が効くように）、
各成分の雑音の σ が S LSB になるように合わせてから、丸め・±127 で飽和。S を 16 と 8 で比べる。
細かい ch の物差し: 1 本の荒い ch の雑音は細かい ch 1 本の 14336 倍（+41.6 dB。N_f 16384 のうち残す 14336 本）。

判定:
- **(a) 量子化の損失** var(q(x) − x) / var(x)（雑音の床の持ち上がり）。目標 ≦ 0.1 %
- **(b) 強い線の余裕**: CW の強さを上げ、細かい FFT（N_f 16384、Hann）の 64 本平均で、CW の ±3 bin の外の最大が床 + 3 dB を超える（飽和の歪みが見える）ときの CW の強さ（細かい ch の雑音に対する dB）
- 陽性対照: b = 4（±7）・S = 2 では (a) が ≒ 2 %（1/12/4）で落ち、(b) は低い強さで歪みが見える

予言:

| S | (a) 損失 | (b) 歪みが見え始める CW（荒い ch の雑音に対して / 細かい ch の雑音に対して） |
|---|---|---|
| 16 | 3.3e-4（1/12/S²） | +9〜+12 dB / **+51〜+54 dB** |
| 8 | 1.3e-3 | +15〜+18 dB / **+57〜+60 dB** |
| 陽性対照 b 4・S 2 | 2.1e-2 | +3〜+6 dB |

- 比べる物差し: 2G-1 は ADC の飽和で決まり、運転のレベル（−16〜−21 dBFS）なら、ADC の全帯域の雑音に対して +16 dB 前後 = 細かい ch（131072 本）の雑音に対して ≒ +67 dB まで歪まない。**8 bit にすると線の余裕は 10〜15 dB 減る**見込み
- (a) は S = 16 で 0.03 % なので、損失より余裕のほうで S を決めることになる（S を下げると余裕が増え、損失が増える）

  模型の判定を「損失が 1/12/S² と 5 % 以内」に改め、0.1 % は S を選ぶ物差しとして表に並べた。S を選ぶ材料に S 11・12 を足した

### M-3 荒い段の語長（固定小数点、bit 単位ではなく語長を決める模型）— 予言（走らせる前に書く）

形: x（ADC 14 bit、運転 −16〜−21 dBFS）→ 荒い PFB（係数 18 bit、最大を 2^17 − 1 に。z = Σ (−1)^t·h·x を SH bit 落として 18 bit に丸め・飽和）
→ cfft32（出口 24 bit、S-1 の RTL の語長）→ Y への詰め替え（共役）→ ch ごとの利得 g_k（18 bit、Y × g_k を 16 bit 落とす）で各成分の σ を S = 12 LSB に → 8 bit に丸め・飽和。
判定: 量子化の損失（荒い段の出口の雑音の床の持ち上がり）・CW の余裕（z の 18 bit が飽和し始める強さ）・IF の帯域の傾き（ch の間 ±10 dB）を利得で吸収できるか

予言:
- SH は z の雑音の σ が 2^12 前後（18 bit の飽和まで ≒ 30 dB）になる値。z の丸めの損失は ≦ 1e-6（無視できる）
- 損失の合計は再量子化（S 12、5.8e-4）でほぼ決まる: 合計 ≦ 6e-4
- z の飽和が始まる CW: 荒い ch の雑音に対して +40 dB 以上（8 bit の再量子化の +16.5 dB より十分大きく、律速は M-2 の 8 bit のまま）
- 利得 18 bit（最大 2^17）で、ch の間 ±10 dB の傾きを吸収できる（Y の σ の幅 20 dB に対して利得の幅は 2^17 / S·… で 60 dB 以上）

**結果（`make model-m3`、`model/m3_coarse_fixed.py`、2026-10-23）: 全部通過（1 回目は (b) の判定の組み方で不合格。下）**

| | 予言 | 結果 |
|---|---|---|
| SH | σ_z ≒ 2^12 | **SH 18**（‖h‖ = 9.7e5、σ_x 1031 LSB（−18 dBFS）→ σ_z ≒ 3807 LSB、18 bit の最大まで 30.7 dB）○ |
| z と FFT の丸めの損失 | ≦ 1e-6 | 中央値 8.0e-7・最大 7.5e-6（最大は IF の傾きで弱い端の ch）△ |
| 8 bit までの損失の合計 | ≦ 6e-4 | **5.80e-4〜5.91e-4**（1/12/S² = 5.79e-4）○ |
| ch の間 ±10 dB の傾き | 利得で吸収 | Y の σ の幅 19.3 dB → 8 bit の σ 11.98〜12.03 LSB。利得 141〜1294（18 bit の中、余裕は大きい）○ |
| z が飽和し始める CW | +40 dB 以上 | **z より先に ADC が飽和する（荒い ch の雑音に対して +26 dB）** |

- **1 回目は (b) で不合格**: 判定を「z の飽和が +40 dB 以上」と置いたが、運転のレベル（−18 dBFS）では ADC が +26 dB で先に飽和し、z まで届かなかった。予言が ADC の飽和を数えていなかった。
  確かめたいのは「z の語長が律速にならないこと」なので、判定を「z が ADC より先に飽和しない」に改めた
- 強い線の律速は M-2 の 8 bit（S 12 で +16.5 dB）で、ADC（+26 dB）より 9.5 dB 低い（M-2 の「8 bit にすると余裕は 8〜12 dB 減る」と合う）
- **RTL に渡す値: 係数 18 bit（最大 2^17 − 1、(−1)^t を含めて表に）・SH 18・z 18 bit・Y 24 bit・利得 18 bit（Y·g >> 16、PS が ch ごとに書く）・出口 8 bit（丸め・飽和）**。
  利得を PS が決めるために、荒い ch ごとの電力の数え（Σ|Y|²）を RTL に持たせる

### C-1 荒い PFB の RTL（`coarse_pfb`）— 作りと予言（走らせる前に書く、2026-10-23）

作り（`tools/gen_coarse_pfb.py` が `src/coarse_pfb.v` を作る。係数は (−1)^t を含めた 1728 個 × 18 bit の定数）:

- ブロックの間は 3 拍か 4 拍なので、3 拍の計算は重ならない。出口 z（64 × 18 bit）は 1 ブロックに 1 回の valid で cfft32 の入口にそのまま

- sim（`make sim-cstage`、600 ブロック、ch 5 に +24 dB の CW を入れて ch 5 の利得は雑音の ch のまま）: **出口の y がブロック m ≧ 30 で模型と全部一致**（36,480 値で違い 0）。
  POW（最後に閉じた区切り、SEQ 5）が RTL の出口から数え直した和と一致する区切りの頭がちょうど 1 つ（ブロック 40 = NACC を書いた後）。CLIP は ch 5 で 138・ほかは 0、模型（飽和の前の値で数える）と一致。
  陽性対照（奇数の ch の共役を抜く）は 8841 値が違って落ちる
- 書いている途中で見つけた誤り（sim の前に直した）: 電力の 2 乗を符号なしの式に混ぜていた（`pacc + qr*qr` は式全体が符号なしになり、−127 の 2 乗を誤る）→ 2 乗を符号付きで別に

### C-3 corner turn の書き手（`ct_wr`）— 作りと予言（走らせる前に書く、2026-10-23）

作り:
- **DSP のクロック（256 MHz）で動かし、MIG（300 MHz）とは SmartConnect で乗り換える**（自作の CDC は持たない、LESSONS）。512 bit・256 MHz の口は 16.4 GB/s で、書きの 4.68 GB/s に足りる
- 並べ替え: 32 個の銀行（各 16 bit × 4096 = 2 面 × 32 ch × QB 拍、QB = 64）。ブロック b の ch k の 16 bit を銀行 (k + b) mod 32 の番地 {面, k, ⌊b/32⌋} に書く（入口を b mod 32 だけ回す）。
  読みは 32 個の銀行を同じ番地 {面, k, q} で読み、k だけ回すと ch k のブロック 32q..32q + 31 = 1 拍（512 bit）
- 1 群 = 32·QB = 2048 ブロック。群が満ちたら ch ごとに QB 拍（4 KiB）のバーストを 32 本。DDR の番地 = BASE ＋ (チャンク mod NPLANE)·PLANE_STRIDE ＋ k·CHSTRIDE ＋ 群·QB·64
- チャンク = GPD 群（本番 10,240 群 = 20,971,520 ブロック = 286.72 ms）。ch k の領域はチャンクの中で連続（CHSTRIDE = 40 MiB）。
  **面は 3**（3.75 GiB、4 GiB に入る）: 細かい PFB はチャンクの頭で前のチャンクの末尾 (T − 1)·N_f を読み直すので、2 面だと書き手の上書きと競る。3 面で競りを無くす
- 最後の B を受けてチャンクを閉じたら、読み手へ「チャンク c が揃った」（同じクロック）。チップ内の 2 面が空く前に次の群が満ちたら溢れを数える（粘着の FLAGS）

判定（`tools/sim_ct_wr.py`、AXI4 のメモリの模型、QB 4・GPD 3 に縮めて 7 チャンク流す）: 模型の DDR の中身（最後の 3 チャンク）が、ch ごとに連続に並べ替えた入力と全部一致・チャンクが閉じた数と順・溢れ 0。
陽性対照: 入口の回しを 1 ずらした RTL で落ちる。-DSTALL（wready を長く落とす）で溢れを数える

予言:
- sim: 全部一致（違い 0）・閉じたチャンク 7・溢れ 0。陽性対照は落ちる。STALL で溢れ ≧ 1
- OOC（256 MHz、QB 64）: BRAM 64（32 銀行 × 4096 × 16 bit、RAMB36 は 2K × 18 なので 1 銀行 2 個）・DSP 0・LUT 3,000〜6,000（入口と出口の 32 × 16 bit の回し 2 個）・WNS > 0

**sim の結果（`make sim-ctwr`、2026-10-23）: 予言どおり**
- ふつう（QB 4）: 最後の 3 チャンクの中身が全部一致（36,864 値）・chunk_done 0..6 の順・CHUNKS 7・OVF 0・GROUPS 21・FLAGS 0
- **QB 64（本番の大きさ）: 589,824 値で全部一致**・同じく 7 チャンク
- 陽性対照（入口の回しを 1 ずらす）: 36,863 値が違って落ちる。STALL（wready を 3 群ぶん落とす）: OVF 2・FLAGS 1 を数えた（溢れた群のバーストは失われ、閉じたチャンクは 6）
- **1 回目の QB 64 で模型が「AW より先の W」を見つけた**（中身は一致していた）。書き手は W を AW と独立に出していた。AXI4 では許されるが受け手に頼らず、
  AW を受けてもらったバーストの分だけ W を出す（aw_ahead の数え）に直した。QB 4 では AW が先に出ることがたまたま多く、表に出なかった
- 書いている途中で見つけた誤り（sim の前に直した）: SystemVerilog のキャスト `5'(…)`（Vivado は .v を Verilog 2001 で読む）、FLAGS の bit を 2 つの always から書く、読み途中の数え（2 bit で 4 まで数えられない）

OOC（256 MHz、QB 64）: **DSP 0・LUT 3,586・FF 1,811・BRAM 64・合成の WNS +1.712 ns** ○（予言 BRAM 64・LUT 3,000〜6,000）

### C-4 corner turn の読み手（`ct_rd`）— 作りと予言（走らせる前に書く、2026-10-23）

作り（DSP のクロック。MIG とは SmartConnect）:
- chunk_done（ct_wr から、チャンク c）を受けて、ch k = 0..31 の順に「前のチャンクの末尾 HB バイト（c ≧ 1 のときだけ）→ チャンク c の本体 CHS バイト」を 64 拍のバーストで読む。
  番地は ct_wr と同じ式（面の頭 ＋ k·CHS）。末尾は面 (c − 1) mod NPLANE の k·CHS ＋ CHS − HB から。HB = (T − 1)·N_f·2 = 768 KiB（本番）
- 出口: AXI4-Stream 512 bit（32 サンプル、i 番を [16i +: 16]）、tuser = {チャンク c, ch k, 末尾か本体か}、tlast = ch の最後の拍。下流の tready で止まる（R の口を止める）
- 先に出す AR は 8 本まで（溜め 16 拍 ＋ 出した AR の分を超えない）。読みのチャンクが溜まる（読み終わる前に次の chunk_done）と数えて捨てる（粘着の FLAGS）
- レジスタ: BASE・CHSTRIDE・PLANE_STRIDE・NPLANE・HB（末尾のバイト）・RUN、STATUS（読み途中・読み終えたチャンクの数・溜まって捨てた数）

判定（`tools/sim_ct_rd.py`）: 模型のメモリに ct_wr と同じ配置の中身を置き、chunk_done を 3 回与えて、出口の拍の並び（末尾 → 本体、ch 0..31）と中身と tuser・tlast が期待と全部一致。
下流の tready をランダムに落とす。陽性対照: 末尾の番地の式を 1 拍ずらす RTL で落ちる

予言: 全部一致・陽性対照は落ちる。OOC（256 MHz）: LUT 1,500〜3,000・FF 3,000〜5,000（溜め 16 × 512 bit を LUT RAM か FF で）・BRAM 0〜8・DSP 0・WNS > 0

**結果（`make sim-ctrd`、2026-10-23）**
- sim: **16,384 拍の並び・中身・tuser・tlast が全部一致**、DONE 3・DROP 0・FLAGS 0、チャンク 1 の直後の STATUS 3（読み途中 ＋ 待ち）。陽性対照（末尾の番地を 1 拍ずらす）は 4,096 拍が違って落ちる
- **1 回目は不合格**: 区間の終わりの判定が、どこからも値の入らない `seg_len` と比べていた（不定との比べは偽 → ch 0 を読み続け、範囲外の AR 65 本）。
  `iverilog -Wall` は値の入らないレジスタを警告しない（すり抜けた）→ 区間（本体 CHS・末尾 HB）で比べるように直した
- 書いている途中で見つけた誤り（sim の前に直した）: 読み途中に閉じて待たせたチャンクの「前の面」に、待たせたチャンク自身の面を使っていた
- **OOC の 1 回目は WNS −0.873 ns（256 MHz に入らない）**: 最悪経路は番地の `ck × CHS` の掛け算（DSP 2 個）から AR の番地へ。
  ch ごとに CHS を足す積算（本体の頭・末尾の頭）に替えて **WNS +1.549 ns・DSP 0・LUT 855・FF 556・BRAM 0**（溜めは LUT RAM）。予言の LUT 1,500〜3,000・FF 3,000〜5,000 は外れ（少ない）

見積もり（`make estimate`）の DDR 系を ct_wr・ct_rd の実測に置き換え、**DDR の量を 3 面で数え直した**: N_f 131072 は DDR 3.75 GB（4 GB に入る）・DSP 45.9 %・BRAM 46.9 %・URAM 47.5 %・LUT 41.6 %・FF 33.3 %
