# proj004 — 外部 10 MHz 基準クロック

日付: 2026-09-17
状態: **成功**

## 目的

**ボードのサンプリングクロックを観測所の 10 MHz 基準に同期させ、それが効いていることを
数値で示す。**

proj003 で測ったクロックのずれ **+14.92 ppm** は、ボードのクロック源の確度そのもの
だった。分光計としては、これが周波数軸の目盛りの誤差になる。45m 鏡の観測で
「どの周波数を見ていたのか」を言うには、目盛りを観測所の基準に繋ぐしかない。

proj004 の成果物はビットストリームではない。**「外部基準が効いている」と言い切れる
状態**である。

## なぜこれが自明でないか

**外部基準を挿していなくても、ボードは何事もなく動く。**

LMK04828 は外付けの 160 MHz VCXO を PLL2 の種にしており、PLL1 の基準が無くても
（ホールドオーバに入っても）出力は出続ける。ADC も回るし DMA も完走する。
**「動いているように見える」ことは、外部基準が効いている証拠にならない。**

だから判定には外側の証拠が要る。proj003 が作った測定器（ppm を測る道具）が
そのために要る。**proj003 → proj004 の順序はここで固定されている。**

## クロックの系統

```
 48 MHz XO（±15 ppm）─▶ Si5395 ─(10 MHz)─┐
                                          ├─▶ LMK04828 ─ PLL1 ─▶ 160 MHz VCXO
 CLK_IN（SMA）── 外部 10 MHz ─────────────┘        │
                                                   └─ PLL2 ─▶ 2457.6 MHz
                                                        ├─ 245.76 MHz ─▶ LMX2594
                                                        └─ 122.88 MHz ─▶ PL
                                          LMX2594 ─(491.52 MHz)─▶ RFDC ─▶ fs = 1228.8 MSPS
```

**先頭の 48 MHz 水晶が ±15 ppm 品である。** proj003 の実測 +14.92 ppm はこれで
説明がつく。PLL1 の基準を CLK_IN 側に切り替えれば、fs の確度は外部基準のものになる。

| | 値 | 出典 |
|---|---|---|
| 基板の基準 | Si5395 が出す **10 MHz**（48 MHz XO から生成） | RefMan A6 / TICS プロジェクト |
| LMK の VCXO | 160 MHz | RefMan A6 |
| PLL1 の位相比較周波数 | **80 kHz**（10 MHz / 125） | 出荷時のレジスタ値 |
| PLL1_N | 2000（80 kHz × 2000 = 160 MHz） | 同上 |
| 出荷時に選ばれている入力 | **CLKin1**（0x0147 = 0x1A） | 同上 |

## 設計

**PL の設計は proj003 と同じ。** ビットストリームは作り直すが中身は変えない
（リポジトリの方針どおり proj004 を自己完結にするため）。変えたのは PYNQ 側だけ。

| ファイル | 役割 |
|---|---|
| `pynq/extref.py` | **新規。** LMK04828 の PLL1 基準入力を選び直す |
| `pynq/extref_test.py` | **新規。** 条件を切り替えて ppm を並べる。proj004 の判定そのもの |
| `pynq/adc_capture.py` | proj003 から。`--clkin` を足し、`analyse()` が数値を返すようにした |
| `clocks/` | 出荷時のレジスタファイルの控えと、読み方 |

### 触るレジスタは 3 バイトだけ

```
0x0147        どの CLKin を PLL1 に入れるか   0x1A（CLKin1）→ 0x0A（CLKin0）
0x0153/0x0154 CLKin0_R = 125（10 MHz → 80 kHz）
```

`0x0147` の中身は

```
bit [6:4] CLKin_SEL_MODE   0 = CLKin0 manual / 1 = CLKin1 manual / 2 = CLKin2 manual / 4 = auto
bit [3:2] CLKin1_DEMUX     2 = PLL1 へ
bit [1:0] CLKin0_DEMUX     2 = PLL1 へ
```

**PLL1_N も VCXO も PLL2 以降も一切触らない。** 位相比較周波数を出荷時と同じ 80 kHz に
保つので、基板上のループフィルタの定数がそのまま成立する。ここを変えると PLL1 の帯域が
変わり、「ロックしない」「ロックが遅い」という別の症状に化ける。

## 決めたこと

- **決定**: CLK_IN の SMA がどの CLKin かは、配線図ではなく **実測で決める**
  **理由**: 出荷時のレジスタでは **CLKin0 と CLKin1 の両方が 10 MHz 前提**
  （R = 125）になっている。ケーブル無しで PLL1 がロックする以上、選ばれている
  CLKin1 が基板の Si5395 であり、**CLK_IN は CLKin0 の可能性が高い** — が、これは推定。
  proj003 で「SMA のラベルとスライス番号の並びが逆」を踏んでいる。
  `extref_test.py` は `stock / 0 / 1` を順に測るので、**どれが SMA かは表を見れば決まる**
  **見送った案**: RefMan と回路図を読んで確定させてから測る案。RefMan A6 の本文は
  「CLK IN が LMK に入る」としか書いておらず、CLKin の番号は書かれていない

- **決定**: CASPER の検証済みレジスタファイルをそのまま置く方式は採らない
  **理由**: `xrfclk._read_tics_output()` はパッケージのディレクトリの `*.txt` を
  **ファイル名を `_` で 2 分割して** `チップ名_周波数.txt` と解釈する
  （`chip, freq = name.split('_')`）。`rfsoc4x2_lmk_CLKin0_extref_10M_...txt` を
  置くと **`set_ref_clks()` が `ValueError: too many values to unpack` で落ちる**。
  VERSIONS.md に書いた「CASPER のファイルを当たる」は、この版では成立しない
  **採った方式**: 出荷時のファイルをその場で読み、**必要なレジスタだけ差し替えて**
  `xrfclk._write_LMK_regs()` に渡す。差分がコードに残るので、何を変えたのか後から分かる
  **付随**: RFSoC 4x2 の PYNQ イメージは `xrfclk` にパッチが当たっており、
  `_read_tics_output()` が `set_ref_clks()` のたびに走る（素の Xilinx 版は初回のみ）

- **決定**: 書き込んだレジスタは読み返さない。**効果（ppm）で検証する**
  **理由**: このリポジトリは「設定したら読み返す」を原則にしているが、LMK04828 では
  それができない。`xrfclk` は SPI を書くだけで読み出しの口を持たず、LMK04828 の
  読み返しは 4 線モードで別ピンに出す方式で、そのピンが RFSoC 4x2 のどこへ行って
  いるかが未確認。無理に有効化すると `Status_LD1`（PLL1 ロック LED）の出力を潰しかねない
  **代わりに置いた 2 系統**: (1) ボードの **PLL1 ロック LED**、(2) **取得波形の ppm**。
  (2) が本命で、(1) は「ケーブルが刺さっているか」を切り分けるための早い信号

- **決定**: 条件を変えるたびに **ビットストリームを読み直す**
  **理由**: RFDC のタイルはビットストリームをロードした時点で起動し、そのとき LMX の
  491.52 MHz を掴む（proj003 で確認）。クロック源を変えた後にタイルをそのままにすると、
  **古い基準で起動したタイルの上で測る**ことになり、何を測ったのか言えなくなる。
  クロックを書く → Overlay → 確認 → 取得、の順を条件ごとに繰り返す
  **見送った案**: タイルを `ShutDown` / `StartUp` で作り直す案。proj003 の
  「動いているタイルには触らない」に反するうえ、Overlay の読み直しで同じことができる

- **決定**: 信号発生器（APSYN420）も同じ 10 MHz に同期させる
  **理由**: ppm は **SG とボードの周波数差**である。ボードだけを外部基準にしても、
  ずれは「SG 自身の確度」に置き換わるだけで、**減るとは限らない**。両方を同じ基準に
  繋いで初めて 0 に潰れ、それが「外部基準が効いた」ことの最も強い証拠になる
  **言えること・言えないこと**: 0 に潰れたことは「両者が同じ基準を見ている」ことしか
  言わない。**基準そのものの確度はこの測定では分からない**（共通のずれは打ち消える）。
  観測所の基準を使う以上それで十分だが、混ぜないこと

- **決定**: 内部基準に戻すときは **出荷時のレジスタを書き直す**（ケーブルを抜くのではない）
  **理由**: LMK04828 にはホールドオーバがある。外部基準を抜いても直前の DAC 値を保持して
  VCXO を走らせ続けるので、**抜いた瞬間に ppm が +14.9 に戻るとは限らない**。
  比較対照は必ず設定を書き直して取り直す

- **決定**: SG を観測所の 10 MHz にロックさせ、その REF OUT をボードの CLK_IN に配る
  **理由**: 観測所の基準を引ける口が 1 つしかない。SG を `ROSC:SOUR EXT` で観測所に
  ロックさせれば、その REF OUT は観測所の基準そのものになる。SG とボードが共通基準に
  なるので ppm は 0 に潰れ、proj004 の判定条件が成立する
  **付随**: **APSYN420 の REF OUT は既定で出ない**（`ROSC:OUTP:STAT ON` が要る）。
  スペアナで無出力を確認するまで、ボード側の PLL1 と LMK の入力バッファ型を疑っていた。
  **「信号が来ているか」を測るのが先**で、レジスタを疑うのは後

- **決定**: PL の設計は proj003 から変えない
  **理由**: proj004 で疑うのはクロック源だけ。同時に PL を変えると、結果が変わったときに
  どちらのせいか言えない。**ビルドは作り直すが中身は同じ**なので、WNS が proj003 と
  近い値になることが、ビルド環境が変わっていないことの確認にもなる


```bash
# Vivado サーバ — 試験トーンの供給
# 観測所の 10 MHz を **SG とボードの両方** に分配してから（分配器か T 分岐）。
python3 tools/apsyn.py --probe                      # source が INT か EXT か見る
python3 tools/apsyn.py --ref ext --ref-freq 10MHz   # **外部基準に切り替える**
python3 tools/apsyn.py --ref-out on                 # **REF OUT を出す**（下記）
python3 tools/apsyn.py --preset bin                 # 100.0125 MHz / -10 dBm
```

**SG の REF OUT は既定で出ていないことがある。** ボードの CLK_IN に SG の REF OUT を
配る構成では、`--ref-out on` を打たないと何も出ない（2026-09-17 にスペアナで無出力を
確認して判明。それまで「PLL1 がロックしない」側を疑っていた）。
**書けたことと出ていることは別なので、スペアナか周波数カウンタで必ず確かめる。**

**APSYN420 は `--ref ext` を明示しないと内部基準のまま。** しかも `ROSC:EXT:FREQ`
の出荷時の値は 100 MHz で、10 MHz を入れても掴まない。`--ref ext` は
**先に周波数を教えてから** `ROSC:SOUR EXT` にし、`ROSC:LOCK?` を読んで確かめる。
ロックしなければ終了コードを非ゼロにして止まる。

**SG が内部基準のままだと ppm は 0 に潰れない。** proj004 の判定条件そのものが
崩れるので、測定の前に必ず `--probe` で `source : EXT` と `locked : 1` を確認する。

```bash
# ボード（PYNQ v3.1.1）
scp build/proj004.bit build/proj004.hwh pynq/*.py xilinx@<board>:~/proj004/
ssh xilinx@<board>
cd ~/proj004

# 0. 何が設定されているか見るだけ（書き込まない）
sudo -E $(which python3) extref.py --show

# 1. 内部基準のまま proj003 を再現する（**外部ケーブルを挿す前に**）
sudo -E $(which python3) adc_capture.py --clkin stock --tone 100.0125

# 2. CLK_IN に観測所の 10 MHz を挿す。PLL1 ロック LED を見る

# 3. 3 条件を続けて測る。**これが判定**
sudo -E $(which python3) extref_test.py --tone 100.0125 --save-prefix run1

# 4. 内部基準に戻して +14.9 ppm が戻ることを確認する
sudo -E $(which python3) adc_capture.py --clkin stock --tone 100.0125
```

**`sudo python3` ではなく `sudo -E $(which python3)`。** PYNQ v3.x は Python が
venv（`/usr/local/share/pynq-venv`）に入っており、素の `sudo` は `secure_path` で
PATH が置き換わって `ModuleNotFoundError: No module named 'pynq'` になる。

環境の固定値は [`../VERSIONS.md`](../VERSIONS.md)、詰まったときは
[`../proj001/docs/runbook.md`](../proj001/docs/runbook.md)。

## 着手前に裏取りが要ること

- **CLK_IN の SMA がどの CLKin か。** 推定は CLKin0。`extref_test.py` の表で決まる
- **外部基準の波形とレベル。** 観測所の基準は正弦波。TI は
  「**10 MHz は方形波でないと PLL1 がロックしないことがある。入力タイプは MOS に**」
  と回答している（E2E フォーラム）。出荷時の `0x0146` は CLKin の入力タイプを持つが、
  **ビット割り当てが未確定なので触っていない**。正弦波でロックしなければ、
  レベルを上げるか方形波に変換して切り分ける
- **基準の分配とレベル。** CLK_IN の入力インピーダンスと許容レベルは RefMan 未確認。
  過大入力を避けるため、まず控えめなレベルから

## 想定される詰まりどころ

| 症状 | 見るところ |
|---|---|
| どの条件でも ppm が減らない | **SG を同じ 10 MHz に同期させたか。** していなければ 0 にはならない |
| CLK_IN に信号が来ていない | SG の REF OUT を配っているなら `--ref-out on`。**既定では出ない**。スペアナで確かめる |
| `--clkin 0` で ppm が変わらない | CLK_IN は CLKin0 ではない。`--order stock,0,1,2` で全部試す |
| PLL1 ロック LED が消える | その CLKin に基準が来ていない。ケーブル・レベル・波形 |
| LED は点くが ppm が減らない | **CLKin の取り違え。** 別の（基板内の）入力にロックしている |
| タイル PLL がロックしない | LMK を書いた直後に LMX を書いていないか。`extref.py --settle` を伸ばす |
| ケーブルを抜いても ppm が 0 のまま | **ホールドオーバ。** 比較対照は設定を書き直して取り直すこと |
| `ValueError: too many values to unpack` | xrfclk のディレクトリに `_` を 2 つ以上含む `.txt` を置いた |
| `ModuleNotFoundError: No module named 'pynq'` | `sudo -E $(which python3)` で実行する |
| `extref.py` が LMK のファイルを見つけられない | `xrfclk` のパッケージの場所。`--show` が探した先を表示する |
| `AttributeError: module 'xrfclk' has no attribute ...` | **私有関数の名前は版で変わる。** `extref.py --api` で実機に何があるか出して、推測で書き換えずに合わせる |
| SPI を 2 度書いてしまう | `_find_devices()` は append するだけなので 2 回呼ぶとデバイスが重複する。`extref.py` は自分で呼ばず、`set_ref_clks()` の副作用に任せている |
| ppm は 0 になったがノイズフロアが上がった | 外部基準の位相雑音。**分光計としてはここから先が本題**。proj005 以降 |

## 結論・次にやること

- **周波数軸が観測所の基準に繋がった。** fs = 1228.8 MSPS の確度は、これ以降
  ボードの水晶ではなく観測所の基準のもの。分光計の周波数目盛りが外部に対して
  説明可能になった
- **CLK_IN = CLKin0。** 切り替えは `0x0147` を `0x1A` → `0x0A` の 1 バイトだけ。
  以降の proj はこれをそのまま使える
- **状態レジスタでは基準の正しさを判定できない**ことを実測で示した。
  `PLLLockStatus` = 2 のまま 90 ppm ずれる。判定は ppm でしか行えない
- 次: **proj005 で 4ch 同時取得とタイル間同期（MTS）。** 外部基準が入ったので、
  複数ボードへ広げる下地もできた
- その先: PFB / FFT と積分（Phase 4）
- ~~宿題: ノイズフロアが 1.3 dB 上がった件~~ → **[proj005](../proj005/) で決着**。
  正弦波源（E8257D）に替えて信号源と装置を分離した。SFDR の確定はフィルタ待ちで持ち越し

### どの CLKin が SMA かは、表の 1 列で決まった

| clkin | 推定周波数 [MHz] | ずれ [Hz] | ppm |
|---|---|---|---|
| `stock` | 100.013991 | +1491.4 | **+14.912** |
| **`0`** | **100.012498** | **−1.5** | **−0.015** |
| `1` | 100.013991 | +1490.9 | +14.908 |

**`clkin 1` が `stock` と一致したことが効いている。** CLKin1 は出荷時の選択なので
レジスタの差し替えが起きず、**書き込み経路が `xrfclk` と等価**であることの対照になる。
これが無いと「`clkin 0` で値が動いたのは、基準を変えたからか、自前で LMK を書いたからか」
が言えない。

CLKin0 が SMA だという事前の推定（出荷時ファイルで CLKin0_R が 10 MHz 用の 125 に
設定されていた）は当たっていたが、**当てにいったのではなく表で決めた**。

### 残差 −0.015 ppm の意味

−1.5 Hz @ 100 MHz。**これは「ずれが無い」ではなく「この方法で測れる下限に張り付いた」**
と読む。53.3 µs のキャプチャに Hann 窓のサブビン補間をかけて言えるのはここまでで、
補間の系統誤差がこの程度ある。さらに追い込むならキャプチャ長を伸ばす。

**0 に潰れたことは「SG とボードが同じ基準を見ている」ことしか言わない。**
基準そのものの確度は共通なので打ち消えており、この測定では分からない。

### 「動いているように見える」を実際に踏んだ

最初の測定で `clkin 0` が **+90.68 ppm** になった。原因は **SG の REF OUT が
出ていなかったこと**（APSYN420 は既定で出ない）。CLK_IN には何も来ていなかった。

このときの症状を記録しておく価値がある。

| 見たもの | 値 | 判断 |
|---|---|---|
| `tile.PLLLockStatus` | **2（locked）** | 正常に見える |
| DMA | 完走。`done` = 1 | 正常に見える |
| `IsFIFOFlagsAsserted` | 0 | 正常に見える |
| 波形・高調波 | proj003 と同じ | 正常に見える |
| **ppm** | **+90.68** | **クロックが 90 ppm ずれている** |

**`tile.PLLLockStatus` は RFDC タイルの PLL であって、LMK の PLL1 ではない。**
LMX が出す 491.52 MHz にタイルがロックしているというだけで、その 491.52 MHz が
正しい基準から来ているかは何も言わない。**ロック状態を見ても基準の正しさは分からない。**

+90.68 ppm は、PLL1 が有効な基準を失って DAC が振り切れ、160 MHz VCXO が
引っ張られた端の値と整合する。**外部基準が来ていなくても ADC は回り、データは取れ、
どの状態レジスタも正常を返す。** proj004 の前提がそのまま実証された形になった。

なお、このとき振幅が 1.3 dB 落ちたのは信号品質の劣化ではなく **スキャロップ損**。
ピークがビン中心から +0.484（ほぼ半ビン）に移ったためで、Hann 窓なら約 1.4 dB。

### SG の REF OUT

観測所の基準を 1 本しか引けないので、**SG を観測所の 10 MHz にロックさせ、その
REF OUT をボードの CLK_IN に配る**構成にした。SG とボードが共通基準になる。

```
観測所 10 MHz ─▶ APSYN420 REF IN（ROSC:SOUR EXT）
                     ├─▶ RF OUT 100.0125 MHz ─▶ ADC_B
                     └─▶ REF OUT 10 MHz ─▶ RFSoC4x2 CLK_IN（要 ROSC:OUTP:STAT ON）
```

**`ROSC:OUTP:STAT ON` を打つまで REF OUT は出ない。** 綴りは機種依存で、AnaPico の
プログラマーズマニュアルが公開経路で取れなかったため、`apsyn.py --ref-out on` は
候補を順に書いて `SYST:ERR?` と読み返しで採用されたものを特定する作りにしてある
（このボードは `ROSC:OUTP:STAT`）。
